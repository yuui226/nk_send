## 采集尺寸

Apple 当前规格要求每个设备尺寸至少 1 张、最多 10 张，接受 PNG/JPG/JPEG，不接受透明通道。必需尺寸章节列出灵动岛中等屏 iPhone，以及支持 iPad 时的 13 英寸 iPad；表格另列大屏 iPhone 的回退条件。本项目准备下列三组原生竖图，覆盖这些档位。[Apple 截图规格](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/)

| 本项目采集组 | 使用设备 | 竖图像素 | 对应设备登记 |
|---|---|---|---|
| `iphone-medium` | iPhone 17 | 1206 × 2622 | `B6B4E291-173A-4BFE-BB9C-2D1F62643C49` |
| `iphone-large` | iPhone 15 Plus | 1290 × 2796 | `FB86603E-3366-461E-A2A8-0F2CB15FE262` |
| `ipad-13` | iPad Pro 13 英寸 M5 | 2064 × 2752 | `303DAFA2-48C7-4470-90E9-5763EB1CB58B` |

以上尺寸均在 Apple 规格表内。使用表中设备直接采集，不把其他比例的图片拉伸过来。横图只有在实际页面与采集方向相符时采用相应宽高对调尺寸；App 内监看画面旋转不自动表示系统截图已变成横图。当前先以原生竖图交付。

Apple 允许在界面一致时由后台缩放适配较小尺寸；本项目仍保留独立 iPad 图，不把手机截图放大成平板图。正式上传当天再次核对官方规格和后台设备标签，不仅凭旧教程中的“6.5/6.7/6.9 英寸”称呼选择。检查不要求为此重测所有历史机型。

## 页面顺序与每张内容

六张是本项目建议的展示顺序，不是 Apple 规定必须拍六张。先采集不依赖相机和授权照片的页面；缺少内容的条目保留待办，不填假图。

| 顺序 / 建议文件名 | 真实页面和拍摄状态 | 所需内容及验收重点 | 当前由谁完成 |
|---|---|---|---|
| 01 / `01-connect` | 正常启动后的连接首页，USB/AP/STA 入口清晰，帮助与设置关闭 | 展示已实现的连接方式。未连接就保留未连接状态，不制作假的已连接设备或传输速度 | 助手已归档三尺寸简中候选图，待整套最终选用 |
| 02 / `02-library` | 真实连接后的照片列表，已有缩略图且加载完成 | 本人可公开使用的照片；不显示敏感文件名、人像、精确位置或设备序列号。拍到真实筛选和选择状态 | 本人提供素材并连接相机，助手采集整理 |
| 03 / `03-transfer` | 同一真实会话的传输队列 | 至少有实际任务及真实进度/完成结果；不通过注入测试队列制造速度或完成状态 | 本人连接相机，助手采集整理 |
| 04 / `04-monitor` | 实体相机出流后的监看页面 | 取景内容获准公开；展示实际可用工具。不能用黑色测试取景器、静态替代视频流或未提供的手机端录制入口 | 本人连接相机并布置取景，助手整理 |
| 05 / `05-effects` | 工作台实际导入照片后的滤镜、边框或水印效果 | 选定授权照片，等当前效果渲染完成并确认保存结果；先可制作免费滤镜/边框图。若展示高级版专属水印，标注“部分功能需高级版 / Some features require Pro.”，且使用真实可用权益 | 本人确认照片公开使用权；助手完成编辑、采集与文案 |
| 06 / `06-pro` | Apple 商品正常加载的购买页面 | 正确套餐名称、年度续订/永久区别，隐私和条款链接可用；不含模拟支付说明、测试价格错误或未完成权益确认。不同地区价格以实际商品为准 | 正式商品配置后由助手采集，本人配合账号 |
| 备选 / `settings-reference` | 正常设置页面，已滚到需要展示的分组 | 可先作为排版与文案参考图；不默认替代照片、监看等核心功能展示。等待权益初始化结束，不能把临时加载提示当最终界面 | 助手已归档三尺寸简中参考图，最终是否入选由整套内容决定 |

商店图应展示 App 的真实使用过程；宣传付费功能时说明需要额外购买，并确保摄影素材具备公开展示权。本项目不会将只有启动画面、未实现功能或 Debug 数据的图作为正式整套截图。[Apple 审核指南 2.3.2、2.3.3、2.3.9](https://developer.apple.com/app-store/review/guidelines/#accurate-metadata)

不能直接采用的现有图片包括：历史 `PrelaunchLayoutUITests` 中使用 Debug 场景的诊断附件、带 `Queue` 等 harness 控件的预览图、含 `debug_sample_01.jpg` / `debug_sample_fhd.jpg` 的相册图，以及带模拟 Pro/测试购买说明的截图。这些图片继续保留为内部验证证据。测试工具的附件格式本身不决定图片用途：本次另用独立临时 runner 操作已安装的候选 Release，正常无参数启动且无业务注入，其来源、二进制摘要及逐张核看记录均单独保存，不能与历史 Debug 图混用。

## 助手如何采集清洁 Release

1. 使用本轮修复收敛后的 Release 模拟器 `.app`。先完成[发布包检查](../发布包静态检查说明.md)，记录构建日志、源码时点、版本/构建号和主可执行文件 SHA256。无签名模拟器 Release 可用于准备其实际能运行的页面截图，但不是 App Store 可上传安装包，也不证明实体相机或真实购买已验收。
2. 只使用上表的本任务专用模拟器，逐台操作。确认它没有被另一轮 UI 测试使用；不清除或覆盖其他任务设备，不使用含糊的 `booted` 选择器。已有测试设备中的业务内容不自动当作可公开素材。
3. 将已检查的 Release 安装到所选专用设备，正常启动 `com.ztransfer.ios`，不带 `--...test`、模拟连接、模拟权益或诊断参数。遇到系统权限提示，按实际准备的功能选择；不为拍照改写 App 业务状态。
4. 通过正常设置入口选择当前采集语言。首批为简体中文；英文材料准备好后，用相同页面顺序单独采集英文界面。繁体中文只在计划启用该商店本地化时补相应图片。不能仅改宣传标题而把图内另一种语言当成已本地化。
5. 保持实际支持的布局、正常字体与选定主题，关闭键盘、帮助弹层和非必要系统通知；若截图目的就是展示某弹层，则保留该弹层。等待照片、预览和权益状态稳定后查看完整屏幕。发现真实遮挡先记录并修复，不裁掉问题区域。
6. 直接保存设备原生像素，不截取 macOS 桌面、模拟器边框或工具栏。下面是采集命令形式，只在设备已启动、页面准备完成后执行：

```sh
captureDevice="B6B4E291-173A-4BFE-BB9C-2D1F62643C49"
captureOutput="ios/docs/screenshots/raw/zh-Hans/iphone-medium"
mkdir -p "$captureOutput"
xcrun simctl io "$captureDevice" screenshot --type=png "$captureOutput/01-connect.png"
sips -g pixelWidth -g pixelHeight -g hasAlpha "$captureOutput/01-connect.png"
```

若原生 PNG 含 alpha 通道，保留原始文件供追溯，重新从相同已准备好的屏幕直接采集 JPEG：

```sh
xcrun simctl io "$captureDevice" screenshot --type=jpeg "$captureOutput/01-connect.jpg"
sips -g pixelWidth -g pixelHeight -g hasAlpha "$captureOutput/01-connect.jpg"
```

7. 实际打开每张图片检查，而不仅看文件存在或尺寸输出。记录原始文件 SHA256、页面、语言、设备、系统和权益状态。若添加标题或说明，保存独立成品并保留原图；不修改 App 本体画面、不伪造 UI，不将处理后的图片写回原图。
8. 最终版本若修改了截图可见界面、套餐/额度、提示或品牌信息，仅重新采集受影响图片；无可见变化时，记录与提交构建一致的核对结论，不因源码任意变化重复制作全部图片。

## 目录与采集记录

只有实际生成后才建立对应文件，不创建空 PNG 或占位照片。建议结构：

```text
screenshots/
  README.md
  raw/<语言>/<采集组>/          原生截图，不覆盖
  ready/<语言>/<采集组>/        已逐张验收、可上传的图片
  capture-record.json           实际采集记录
```

`capture-record.json` 在采集时按实际结果填写，每张至少包含：文件相对路径、SHA256、像素宽高、格式/alpha 检查、设备型号/UDID/系统、语言/主题、App 版本/构建号、二进制摘要、源码提交及未提交变更说明、页面状态、素材权利依据位置、观察结果、是否允许上传。状态可用 `candidate`、`ready`、`needs-owner-material`；不能仅因截图命令成功就标 `ready`。

如果仅完成首页与设置，交付说明写“已采集首页/设置参考图，核心功能素材仍待本人”，不写“商店截图齐全”。没有照片的页面仍可先完成技术规格检查，不必等购买会员。

## 逐张及整套验收

- [ ] 文件是正常运行的候选 Release 页面，原图及采集记录可定位；没有测试入口、模拟支付文案或诊断浮层。
- [ ] 尺寸符合所属采集组，格式正确且没有 alpha；没有拉伸、错误方向、模拟器外框。
- [ ] 已打开实际图片检查：文字可读，按钮和提示无遮挡；没有加载中、旧水印位置、系统通知、无关键盘或失败提示。
- [ ] 照片、品牌元素和姓名/位置等内容已确认可公开使用；权利不明确的图片不进入 `ready`。
- [ ] 图片展示的功能、付费边界与当前商店文案一致；不宣传手机端监看录制，不宣称所有相机功能相同，不写死全球统一价格。
- [ ] 各语言各设备组的页面顺序合理，包含核心使用场景；首页/设置准备图不冒充完整核心场景。
- [ ] 选定送审构建后，核对所有成品仍反映该构建；App Store Connect 预览中检查排序、语言、自动缩放及裁切。

开通后在 App Store Connect 的 App 版本页选择对应语言、截图页签和设备组上传，仅使用 `ready` 中验收通过的图片。上传成功不等于已通过审核。[Apple 管理商店素材说明](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-your-app-store-assets)

审核用实体相机演示是另外一份材料，复用[硬件演示拍摄脚本](../审核硬件演示拍摄脚本.md)；无需为准备商店截图先制作宣传视频。
