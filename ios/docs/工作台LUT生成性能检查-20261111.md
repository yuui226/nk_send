# 工作台与导出照片效果性能

2026-11-11。用户反馈工作台，以及导出后生成照片，在 LUT、NP3、边框、胶片颗粒上明显慢于安卓。两处共用 `PhotoEffectsRenderer`：预览可降到长边 1920 且滤镜最多 2 个 worker；生成和传输导出不传 `previewLongEdge`，按完整原图、滤镜 1 个 worker。2400ms sleep 只是结果提示结束后回到准备状态，不是处理前等待。

## 和安卓的差别

顺序都是颜色滤镜（CUBE 与 NP3 互斥）→ 照片上的颗粒 → 边框、信息和水印。慢的是 CPU 像素，不是静态图 GPU。监看 LUT 的 Metal 路径保持独立，没有拿来处理静帧。

- LUT：安卓 `PhotoCubeMapper` 预建每通道 256 项轴，默认 `NativePhotoLut.mapBatch`，16384 像素一批，关闭 FMA。颜色收尾只在非中性时再走一遍。文档记录约 20MP、33³：Kotlin 数秒，Native16K 约 418ms。iOS 原先整段插值、强度混合和收尾都在 Swift 里逐像素做。同日先加的 `CubeLUT.ByteSampler` 只省掉不透明像素的 domain 除法和 floor，插值仍在 Swift。
- NP3：安卓导出用 `ExactRgbMemo`（2^20 槽，键是归一化后的 RGB）。预览最多 2 个 worker，不用这张表。iOS 原先每个像素都在 Swift 里重算 HSL，没有命中缓存。worker 数量本来就和安卓一致：原图 1 个；预览仅在不小于 512×512 时最多 2 个。
- 颗粒：核 `photo_grain_kernel.h` 与安卓 `1f804ab8` 逐字节相同。iOS 桥每 16384 像素重建一次核，构造只是字段初始化。不透明像素仍做了结果不变的反预乘和再预乘。全分辨率 `samples_` 通常为 1。模拟器上 24MP 粗颗粒大约一秒，不是这次数秒级 LUT/NP3 的主因。
- 边框：安卓 `drawPhotoElevation` 在 0.25 代理上做两层较大阴影，再放大。iOS 先前改成整幅画布上的窄接触阴影（短边 0.0028、高度偏移 0.0012、cinema 不透明度 0.20 其余 0.16），因为四分之一代理用 `CGContext.draw` 会垂直翻转，大半径阴影放大后变成灰块。背景盒模糊已经是大约 192 像素的代理，这次没动。

## 修改

不改颜色公式、强度、收尾系数、取消发布规则、JPEG、原图并发，也不把边框改回安卓那两层大阴影。

- LUT：`ThirdParty/PhotoLUT/PhotoLutBridge.cpp`。每张图准备 6×256 的偏移和权重，与 `ByteSampler` 和安卓轴步长一致。不透明像素在 C++ 里做三线性插值、强度混合和收尾。混合前的原值是 `(byte/255)*255`，四舍五入是 `floor(double+0.5)`，与现有 Swift 非负 `rounded()` 一致，不是安卓 native 的整数原值。编译 `-O2 -ffp-contract=off -fno-fast-math -fwrapv`。alpha 0 跳过；0&lt;alpha&lt;255 整批交给原来的 Swift `lut.sample`。取消仍是进入、每 4096 像素一批开始、发布前。
- NP3：`ThirdParty/PhotoNP3/Np3ExactApply.cpp` 只负责扫描、反预乘、查表和预乘。未命中时回调现有 `filterPixel`。键使用 `normalizedIntensityPercent` 和 `adjustments.normalized`。原图借用进程内一张 8MB 表；预览每个 worker 自己一张。行首和每 4096 列检查取消，取消后不发布半成品。预乘写成 `(channel*alpha+127)/255` 再截断，避免 `static_cast` 先于除法。
- 颗粒：alpha 为 255 时直接把 RGB 送进同一核并写回，半透明仍走原来的反预乘。核的 ABI 和采样次数没改。
- 边框：窄阴影的半径和颜色不变，画进 0.25 的透明 `UIGraphicsImageRenderer`，再用 `UIImage.draw` 画回，避免 Y 翻转。毛玻璃面板阴影先裁到面板外扩 `blur*3+abs(offset)`，避免全画布模糊扫到上方照片。

- 第一次 64 项 Passed、0 Failed：`CubeLUTTests`、`PhotoCubeLUTMapperTests`、`PhotoNp3RenderingTests`（含 1648 组与安卓逐字节）、`PhotoGrainTests`（含 24MP 和边框外圈不被颗粒改写）、`Np3BitmapFilterTests`、`Np3FilterEngineTests`。
- 第二次 3 项 Passed：`LUTFinishingPerformanceTests`，其中包括冻结的 `testProductionMapperMatchesOriginalRGBAAtDifferentStrengthsAndAlpha`（不透明和预乘半透明、多种强度和收尾）。

`PhotoGrainTests` 覆盖了颗粒桥的 Swift 调用。本轮没有重新跑 `ios/NativeTests/run_photo_grain_tests.py`。macOS `swift test` 仍会在 `PhotoEffects.swift` 的 UIKit 导入处失败，这是该包在 Mac 上的既有限制，不能当成这次逻辑失败。
