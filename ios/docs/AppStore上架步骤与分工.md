## 操作路线与当前进度

- 阶段 A：步骤 1–4 中可独立完成的本地质量、草稿、网页与素材准备，不要求先买 Apple 会员。
- 阶段 B：步骤 5–9，开通会员、账号配置、签名、商品及真实支付测试；同时回填依赖正式后台的条款、网址和商品截图。
- 阶段 C：步骤 10–13，商店资料、演示视频、正式审核和发布。

当前中英文内容草稿、支持页、拍摄脚本及七页静态网页预览已准备，尚未定稿或上线。以下 13 个发布步骤均未在本手册核销为全部完成；其中一些已有代码、历史测试或用户资料，不代表要重做。完成后在对应步骤勾选并留下日期、版本或后台结果。本人尚需提供的事实已集中到[材料交接分工](上架所需信息与材料.md#本轮材料交接与剩余分工)，无需把各文档的重复标记分别填写一遍。

这些步骤是工作分组，不要求机械地把步骤 1–4 全部打勾才允许进入步骤 5。当前条款中的正式家庭共享开关要在步骤 8 创建商品后核对，整站发布保护会等该标记解决；正式商品截图、签名和真实沙盒也依赖会员。因此，先完成助手可独立的本地待办、明确本人资料及素材处理方案，再进入会员阶段，随后回到步骤 2–4 完成依赖项。最新 Release 和清洁首页/设置截图是否已完成，只看[执行记录](付费前准备执行记录.md)及实际采集记录，不因本手册已写好就算通过。

## 3 建 GitHub Pages 网站并绑定域名

**前置条件：**准备仓库和 DNS 配置只需能登录本人 GitHub/域名后台；实际公开正文前须完成步骤 2，包括步骤 8 后确认的家庭共享事实。网页生成器与七页预览已经准备，当前没有可发布的最终文件、未部署。操作和生成命令见[网站部署说明](site/README.md)。

**你操作：**

1. 登录自己的 GitHub。创建一个单独的网站仓库，例如 `ztransfer-site`（建议名称，不是已创建仓库）。
2. 若使用 GitHub Free，选择适用的公开仓库 Pages 方案；公开内容只放政策、条款、支持页，不上传本 App 源码或个人证件。
3. 告诉助手仓库地址。草稿尚有标记时先保留本地预览；正式生成成功后再由助手准备并上传正式文件，或在无法访问账号时给你可上传的文件夹。
4. 仓库进入 **Settings → Pages → Build and deployment**。采用简单静态文件时，选择 **Deploy from a branch**，分支选实际上传分支（通常 `main`），目录选 `/(root)`，保存。
5. 等正式内容部署成功，先打开 GitHub 提供的默认网址，检查隐私、条款、支持的中英文六个页面。
6. 在 **Pages → Custom domain** 填 `ztransfer.top`，保存。域名所有权验证可在个人 Settings 的 Pages 中按提示添加 TXT 记录。
7. 登录域名服务商 DNS 控制台。先让助手检查现有记录，再添加 GitHub 官方要求的根域名解析记录；具体记录值以操作当天官方文档为准，不照抄多年以前教程。
8. 等域名检测和证书就绪，启用 **Enforce HTTPS**。
9. 用未登录 GitHub 的浏览器打开六个完整 HTTPS 地址，再用手机网络打开一次。

**助手处理：**静态 HTML、目录结构、链接、部署源和 DNS 对照检查，最终把真实 URL 接入 App。

**特别注意：**DNS 只按域名或子域名路由，不能仅把 `/ios/` 路径交给 GitHub。如果根域名已有其他网站，需要保留现有业务并讨论子域名或路由方案，不能直接覆盖现有解析。三个路径都可在同一个 GitHub Pages 站点下共存。

**完成标志：**中英文六个页面均能公开访问，HTTPS 正常，无登录、404、草稿占位或失效邮箱；域名备案状态另记录。

**常见问题：**默认网址可以打开但自定义域名不行，先查 DNS 与证书；页面 404，检查仓库实际目录和发布源；不要删除邮箱 MX 等无关记录。

参考：[发布源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)、[自定义域名](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)。

## 9 上传 TestFlight 并验证真实支付

TestFlight 是 Apple 的测试版安装 App；你一人可作为内部测试员。它不是正式商店发布，也不是强制前置渠道，但本项目建议用它验收发布候选版本。

**助手处理在先：**

1. 使用符合 Apple 当前要求的 Xcode/SDK，明确版本号和递增构建号，制作 Release Archive。
2. 验证并上传至对应 App Store Connect 记录；保留上传结果。
3. 等 Apple 处理构建，按真实加密使用填写适用的出口合规信息。
4. App → TestFlight → Internal Testing，建立内部组，把有权限的本人账号加入并分配构建。

**你操作：**

1. 从 App Store 安装 Apple 的 TestFlight，接受内部测试邀请并安装指定构建。
2. 留意测试版可能覆盖同标识现有 App；按助手说明保留重要文件，不自行卸载来解决商品查询问题。
3. 打开高级版页面，配合购买、重启、恢复和年转永久等指定步骤。确认是 TestFlight/Sandbox 测试环境，不拿普通商店真金白银购买当作沙盒测试。
4. 如需专用沙盒账户：App Store Connect → **Users and Access → Sandbox → Testers → +**，按官方要求填写测试账户；登录路径随系统版本由助手当场指导。不为此退出整台手机 iCloud。
5. 配合真实相机网络下的离线行为测试；不要求你理解 StoreKit 日志。

**助手处理后续：**验证交易交付、恢复、退款、到期、续订、账户及网络变化；记录结果并修复。Debug 模拟 Pro 和 Xcode 本地交易不能代替本步骤。

**完成标志：**指定发布候选构建的购买与恢复路径有通过证据；不仅是安装成功。外部测试首个构建的 Beta 审核与正式审核不同，本人内部测试不需要找其他人组队。

常见问题：构建不出现先查处理状态和上传邮件；商品为空先查 Bundle ID、商品 ID、协议、地区、配置传播及网络；由助手诊断，不反复创建新商品。

参考：[沙盒账户](https://developer.apple.com/help/app-store-connect/test-in-app-purchases/create-a-sandbox-apple-account/)、[TestFlight 内购](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testing-subscriptions-and-in-app-purchases-in-testflight)、[TestFlight](https://developer.apple.com/testflight/)。
