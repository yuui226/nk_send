## 9 上传 TestFlight 并验证真实支付

TestFlight 是 Apple 的测试版安装 App；你一人可作为内部测试员。它不是正式商店发布，也不是强制前置渠道，但本项目建议用它验收发布候选版本。

**助手处理在先：**

1. 使用符合 Apple 当前要求的 Xcode/SDK，明确版本号和递增构建号，制作 Release Archive。
2. 验证并上传至对应 App Store Connect 记录；保留上传结果。
3. 等 Apple 处理构建，按真实加密使用填写适用的出口合规信息。
4. App → TestFlight → Internal Testing，建立内部组，把有权限的本人账号加入并分配构建。

**你操作：**

1. 从 App Store 安装 Apple 的 TestFlight，接受内部测试邀请并安装指定构建。
2. 留意测试版可能覆盖同标识现有 App；按助手说明保留重要文件，不自行卸载来解决商品查询问题。
3. 打开高级版页面，配合购买、重启、恢复和年转永久等指定步骤。确认是 TestFlight/Sandbox 测试环境，不拿普通商店真金白银购买当作沙盒测试。
4. 如需专用沙盒账户：App Store Connect → **Users and Access → Sandbox → Testers → +**，按官方要求填写测试账户；登录路径随系统版本由助手当场指导。不为此退出整台手机 iCloud。
5. 配合真实相机网络下的离线行为测试；不要求你理解 StoreKit 日志。

**助手处理后续：**验证交易交付、恢复、退款、到期、续订、账户及网络变化；记录结果并修复。Debug 模拟 Pro 和 Xcode 本地交易不能代替本步骤。

**完成标志：**指定发布候选构建的购买与恢复路径有通过证据；不仅是安装成功。外部测试首个构建的 Beta 审核与正式审核不同，本人内部测试不需要找其他人组队。

常见问题：构建不出现先查处理状态和上传邮件；商品为空先查 Bundle ID、商品 ID、协议、地区、配置传播及网络；由助手诊断，不反复创建新商品。

参考：[沙盒账户](https://developer.apple.com/help/app-store-connect/test-in-app-purchases/create-a-sandbox-apple-account/)、[TestFlight 内购](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testing-subscriptions-and-in-app-purchases-in-testflight)、[TestFlight](https://developer.apple.com/testflight/)。
