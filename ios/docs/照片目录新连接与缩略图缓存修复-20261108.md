## 根因与实现

1. **跨连接旧目录继承**：原 `STACatalogRecovery` 将旧 files/index/handles 拷给新 repository；`PhotoListViewModel.inheritCatalog` 又提前发布旧列表，Root 保持旧网格投影。现删除这整条恢复路径，新连接创建空模型，初次 `load` 明确 `preserveExisting=false`。Root 直接以本次 session 身份作为视图身份，在替换连接的同次渲染重置旧网格，而不是等异步回调补清。断线尚未重连时保留离线页面的既有规则不变。
2. **N 日提前停止**：旧实现用“已有行＋当前批次的日期数量 > N”判定越界。旧三日加最新日第一张便可提前停止。现仍按最新 N 个拍摄日求范围，但只有**本批次真正读到更早的有效拍摄日**才停止，保持同一最新日余下照片的读取；同连接新拍摄后的刷新也适用。保留原批次增长、双卡日期归并、范围扩大续读和前台抢占规则。
3. **断点归属**：原 `PhotoScanSnapshot` 只核对 `catalogRevision`，不同连接经常同为 0。新增连接 UUID，要求显式保留、连接一致、目录版本一致才复用；前台等待返回后再次核对。失配即重新读当前 handles。真实新连接不继承评分、负缓存或扫描进度。
4. **机身归属**：继续使用厂商/型号＋有效序列号，缺序列号使用传输设备 GUID/标识。同一明确身份支持磁盘复用；二者均缺失时使用当前连接身份，不能以相同型号证明同一相机。旧根目录平铺缓存不再自动归给新相机；同一机身目录内、元数据匹配的旧显示名称键仍可迁移。
5. **文件归属**：原 STA 缓存只含文件编号与大小，复用编号且大小相同可命中旧拍摄。新版本键增加当前文件的拍摄时间，并保留 JPG 增强质量标记与稳定编号（不依赖可后续校正的 STA 显示名称）。旧弱键不迁移，首次需重新填充，随后可复用新键；普通文件键仍为名称＋大小＋拍摄时间。没有新增网络探测、逐帧任务或轮询。
6. **清理时机**：保留 90 日未连接机身清理、切换连接的内存/失败/在途任务重置、完整且权威目录完成后的当前机身清理。N 日截断、元数据不完整、请求失败不删除尚未读取的历史缓存。新拍摄绕过历史加载范围的既有事件路径不变。

没有改可见文案、按钮、时长、动画参数；新连接重建列表视图及其临时展示状态，避免旧网格、预览等状态带入新连接。传输队列仍属于 workspace，连接替换后按既有逻辑重新绑定 provider，不清队列。

## 真机验收

1. 范围设 3 日，连接存在至少 4 个拍摄日的卡：首屏从最新日开始，完整加载最近 3 个实际拍摄日，同一天多张不能只出第一张。
2. 断线，在相机删一张已缓存照片并新拍几张，再连：不能先闪旧目录、不能出现已删照片，新照片应进入最新日。
3. 同机再次连：匹配的文件可使用本地缩略图；文件编号相同但拍摄时间变化不能使用旧缩略图。升级后首次 STA 旧弱键不复用属于预期。
4. 换另一台同型号机身，即使同名/同编号/同大小：列表和缩略图均来自新机身。再回原机，可复用原机对应的有效磁盘缩略图。
5. 范围改 1/5/10/全部，切队列/预览/监看后返回：范围续读、新拍摄补入和既有队列继续工作。
