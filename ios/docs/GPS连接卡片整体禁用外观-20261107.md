# GPS连接卡片整体禁用外观

用户要求：开启GPS后，USB和Wi-Fi两张连接卡片的图标、文字及按钮都应显示不可操作状态，不能只有正文变淡。

## 行为依据与修正

安卓基准为本地 `eafc461d36da712260ebb262f034d7da70450ae6` 的 `HomeScreen.kt`：`gpsBlocksConnection = gpsState.enabled`；两张卡片的共同父层最上方覆盖背景色圆角层（alpha 0.28、zIndex 5），320ms FastOutSlowIn（0.4, 0, 0.2, 1）进出。模式图标是独立飞行层，也在覆盖层下。连接、重置及模式切换禁用；连接按钮仅在已连接时保留disabledAlpha=1，其余禁用为0.45。对应Home连接/GPS展示与卡片材质测试已查阅，没有发现覆盖该整体置灰层级的安卓像素用例。

iOS原来的覆盖层挂在cardSurface上，漏掉同级celebrationLayer中的USB/Wi-Fi图标；`allowsHitTesting(false)`也没有给按钮传播isEnabled=false，导致灯泡/重置没有禁用材质。连接按钮还把安卓已连接时的透明度例外错误扩展到了所有禁用状态。

修正集中于公共`ConnectionMethodCard`：

- 覆盖层移到完整卡片ZStack最上方，仍处于共同NativeAttentionHost内，与卡片共享形变；保留原320ms曲线、圆角、阴影及飞起图标逻辑。
- 卡片正文传播disabled状态，保留触摸拦截；灯泡也按用户“全部不可操作”要求变淡。外侧卡片点击仍显示既有“请先关闭GPS”提示，GPS入口本身不受影响。
- STA连接按钮仅在已连接时保留原透明度例外，GPS禁用的普通连接动作采用0.45。
- 没有增加逐帧计算、截图、drawingGroup、整卡透明度或灰度滤镜；没有修改公共灯泡图标/材质/红点，没有恢复呼吸。
