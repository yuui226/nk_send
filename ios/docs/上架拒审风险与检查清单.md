# Z传上架拒审风险与检查清单

更新：2026-10-21。用于提交前核对，不是过审保证。Apple 按提交构建、实际功能及当时规则审核；遇到新反馈按原文补充，不将一次审核通过外推为所有机型已验收。

优先级说明：“提交阻塞”表示在本项目的发布检查中必须解决再提交；“重点检查”表示需要有检查记录，不代表一定会被拒。下表当前是待执行清单，没有把文档准备完成记为测试通过。

## 1 外部相机功能无法由审核人员验证

**优先级：提交阻塞。**

风险：审核人员没有相同相机，不知道该用什么线、设置什么模式；视频只有 App 录屏，无法证明真实设备交互。

你要做：拍摄手机和相机的真实连接、浏览、传输及监看；提供这一次演示的型号、固件、手机系统和线材。无需列全部固件，视频也无需穷举工具。无需口头解说，可加简短英文字幕。

助手要做：核对步骤与送审构建一致，说明无相机可用功能，提供可访问的视频及必要的硬件条件。

通过标准：未看过 App 的人能照步骤理解核心流程；视频无需登录或额外申请即可查看；需要专用设备的部分明确写出。后续 Apple 要求补充硬件或资源时如实配合。

- [ ] 视频真实硬件交互，不仅是录屏。
- [ ] 相机设置、连接步骤和视频地址可用。
- [ ] 不把 Debug 模拟连接作为真实硬件证据。

依据：[完整审核资料](https://developer.apple.com/help/app-review/before-submitting-for-review/complete-review)。

## 2 内购无法完成或权益错误

**优先级：提交阻塞。**

风险：商品未配置、商品 ID 不一致、价格加载失败；购买成功后仍显示免费；恢复购买失效；永久购买后误导用户以为年费已取消。

你要做：完成付费会员和商业协议，配合真实测试购买与恢复；确认目标价格。无需理解交易代码。

助手要做：检查年度与永久两商品、真实沙盒、冷启动/恢复、到期退款及离线场景；解决已有权益恢复待确认项。检查购买页明确显示周期、实际价格、自动续订、恢复/管理入口和法律链接。

通过标准：正式候选版本在真实 Apple 测试环境完成关键流程；首次内购关联 App 版本一起送审；不凭 Debug Pro 判断成功。

- [ ] 年度为一年自动续期，永久为非消耗型商品。
- [ ] 恢复购买可用，年转永久保留取消原年费的说明与入口。
- [ ] 真实商品显示正确，法律链接有效，后台无缺失资料。
- [ ] 沙盒完成后没有把测试交易视为正式生产购买。

依据：[配置内购](https://developer.apple.com/help/app-store-connect/configure-in-app-purchase-settings/overview-for-configuring-in-app-purchases/)、[审核指南订阅部分](https://developer.apple.com/app-store/review/guidelines/)。

## 3 后台定位解释不充分或行为超出用途

**优先级：提交阻塞。**

风险：项目声明后台定位，但用户看不懂为什么；关闭 GPS 后仍继续定位；用定位维持无关传输任务。

你要做：配合在真机上启用、关闭和撤回定位权限；如果审核需要，补 GPS 操作视频。

助手要做：检查触发条件、权限提示、前后台启停、相机断线与用户开关的真实行为；审核说明写清用于向兼容相机提供拍摄位置。地图地点名称查询使用 Apple 地理编码服务，政策中不能写“所有位置绝不联网”。

通过标准：用户主动控制，后台用途与功能一致，关闭或撤权后按规定停止；有拒绝权限时的合理处理。没有证据不能声明已验证后台省电。

- [ ] 权限用途文案明确，中文英文与实际一致。
- [ ] GPS 关闭、撤权、连接冲突等状态实测。
- [ ] 不把后台定位解释成普通传输或监看的保活手段。

参考：[审核指南 2.5 和 5.1](https://developer.apple.com/app-store/review/guidelines/)。

## 4 隐私政策与真实数据处理不一致

**优先级：提交阻塞。**

风险：政策仍是模板，URL 404；App 实际使用 Apple 地点查询、客服翻译或诊断服务，却声称“完全不联网、不接触任何数据”；App Privacy 回答缺乏依据。

你要做：确认运营者信息、客服使用的翻译服务和实际留存做法。服务商或法定事实由本人确认。

助手要做：检查 App 及依赖数据流，区分设备内处理、相机通信、Apple 服务、用户主动分享、云盘同步和客服邮件。按 Apple 定义逐项判断隐私标签；政策、标签、权限与工程清单各自填写，不能互相替代。

通过标准：政策适用 iOS、正文无待填标记，公开 URL 有效，第三方与保存删除规则真实；适用 Required Reason API 有正确声明并进入发布包。

- [ ] 隐私政策能从商店及 App 相关入口访问。
- [ ] 没有未经审计的“不收集任何数据”等绝对结论。
- [ ] `PrivacyInfo.xcprivacy` 与实际 API、依赖及发布包一致。
- [ ] 客服翻译和邮件保留没有写成未实际执行的承诺。

参考：[App 隐私详情](https://developer.apple.com/app-store/app-privacy-details/)、[隐私清单](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files)。

## 5 页面能显示但无法正常使用

**优先级：提交阻塞（核心操作受影响时）。**

风险：iPad 或小屏上按钮离屏，购买页被键盘挡住，弹窗内容无法滚动，监看转屏后控件错位；只测 iPhone 15 Plus 就宣称全设备通过。

你要做：按要求复测真实手机体验。没有 iPad 真机时不用虚构验收。

助手要做：执行[多尺寸专题](多尺寸逐页排版测试专题.md)，真实渲染并查看截图，点击、滚动、弹键盘和重复开关弹层；记录系统及尺寸缺口。测试辅助数据只用于 UI，不代替相机硬件验证。

通过标准：适用页面与关键状态可读、可点击、可返回；主要路径在代表性尺寸没有阻塞。系统最低支持为 16.0 仅说明配置，不免除旧系统 API 和运行检查。

- [ ] iPhone 与 iPad 分别检查，不只缩放一张截图。
- [ ] 中文、繁体、英文及长文案不覆盖操作按钮。
- [ ] 键盘、大字体、安全区、深浅色和实际允许的横竖屏已检查。
- [ ] 不把模拟器通过当作 USB/蓝牙/发热测试通过。

## 6 商店宣传超出实际功能或权利范围

**优先级：提交阻塞（明显失实时）。**

风险：写支持所有相机、所有固件、所有控制；承诺手机端录像；用 USB 3.2 线材暗示 iPhone 15 Plus 具有 USB 3.2 速率；让人误以为 Nikon 官方 App。

你要做：提供可公开照片的使用依据，补已有可靠记录中的部分 D 系列名单。品牌图形和内置 NP3 已决定从 iOS 移除，不再将这两组素材的授权联系列为此次首发待办。

助手要做：使用“支持 Nikon Z 系列及部分 D 系列，可用功能因型号、固件和模式而异”的真实口径，明确不提供手机端监看录像；不把用户确认的支持范围改写为本轮逐台验收。图片、字体及第三方库授权另检查。

通过标准：文案、截图、视频与实际版本一致；明确独立开发，付费功能没有被包装成全部免费。

- [ ] 不承诺固定最高速度、所有设备相同能力或无条件无限制。
- [ ] 截图是真实功能，不含测试状态或没有实现的界面。
- [ ] 普通品牌文字用于真实说明兼容性或照片 EXIF，不暗示不存在的官方授权。
- [ ] 此次 iOS 品牌图形拨轮档位及内置 NP3 已移除；新包实际检查无相应资源，旧截图/旧功能描述不进入送审材料。用户自定义图片水印和自行导入 NP3 仍按实际功能核对。

## 7 正式构建不完整或包含测试行为

**优先级：提交阻塞。**

风险：旧构建、崩溃、资源缺失、错签名、加载不到法律 URL，或者 Debug 模拟支付进入 Release。

你要做：安装指定候选版本，确认收到的构建号；不要混用早期 Debug 的反馈与新发布包结论。

助手要做：检查 Release 配置、资源、能力、签名、版本号、SDK 要求和第三方许可；验证无模拟入口、无占位地址、无将 Android 更新下载或激活文案误接入 iOS 真实流程的情况。导入的历史字符串存在本身不等于实际入口存在，需查调用与界面。

通过标准：提交的构建就是验收的构建；上传处理通过，核心路径可用。

- [ ] 无测试后门、假支付、假联网或审核专用隐藏行为。
- [ ] 实际隐私、条款、支持链接可点击。
- [ ] 无未解决崩溃和阻塞错误。

参考：[审核指南 App 完整性](https://developer.apple.com/app-store/review/guidelines/)、[上传要求](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds/)。

## 8 地区或商业资料不齐

**优先级：提交阻塞或地区不可用，按后台实际状态区分。**

风险：勾选全球却缺地区资料；会员协议、税务或银行仍待处理；商品可售地区与 App 不一致。

你要做：身份、协议、银行税务、适用备案与交易者声明。厦门是所在地，不是 App 销售范围。

助手要做：逐地区检查后台提示并列出具体缺口；不把网站备案当作 App 备案，也不把个人开发者身份直接当作非交易者。

通过标准：预定开放地区的必需条件满足；不具备条件的地区有明确处理决定。是否开放与是否审核通过分开记录。

- [ ] App 与内购地区均已配置。
- [ ] 中国大陆适用备案、欧盟适用交易者资料已核对。
- [ ] 付费协议与收款事项没有未解决阻塞。
- [ ] 出口合规按实际加密用途完成判断及适用材料；不能把“使用 Apple 系统加密原语”直接写成“完全没有加密”，也不能随意填写批准代码。当前 Nikon 配对、SHA256 等事实见[技术说明](隐私清单与数据流核查.md#出口合规技术事实)，该说明不等于已取得分类结论。

## 9 内容与辅助功能问卷填写不准确

**优先级：重点检查；错误声明应先修正。**

风险：年龄分级靠猜；没有实测就声明 VoiceOver 或大字体支持；无对应验证却打开额外平台可用性。

你要做：确认实际产品定位与内容。问卷出现不理解的字段时让助手解释，不能为追求更低分级随意选择。

助手要做：按功能和测试结果给出填表依据，核对 Mac/Apple Vision Pro 可用性及其他提交时出现的字段。新增必填字段按实际后台处理，不沿用旧截图强填。

通过标准：每个声明能对应实际功能或证据。

## 10 提交前逐项复查

提交当天由助手整理，用户确认最终内容：

- [ ] 已选择正确版本和构建；未把测试历史当作本轮通过。
- [ ] 隐私、条款、支持页及视频在未登录浏览器可打开。
- [ ] 名称、描述、截图、价格、地区和功能范围一致。
- [ ] 相机测试说明具体，演示资料充分。
- [ ] 真实购买、恢复和关键权限路径通过。
- [ ] 首批两项内购已关联送审。
- [ ] 审核姓名、邮箱、电话完整可联系。
- [ ] 不包含任何 `【待填写】`、`【待核实】`、`【待确认】` 或内部编辑备注。
- [ ] 地区、隐私、内容与辅助功能声明有依据。
- [ ] 构建出口合规已处理；需要的材料已提供，或已有适用的无需提供材料依据。
- [ ] 发布方式已决定，知道手动发布需通过后再操作。

## 被拒之后如何处理

1. 保存 Apple 原文，不只记录“被拒了”。记录规则编号、审核设备、系统及附件。
2. 由助手判断缺材料、配置问题还是实际代码缺陷，给出复现或补充方案。
3. 缺说明就补具体步骤和证据；代码问题就修复并验证新构建。不要机械地重复提交同一内容。
4. 回复逐条对应审核问题，说明修改内容、入口及证据。不要声称未做过的硬件或支付测试已完成。
5. 记录新提交版本和结果，不删除历史失败来制造首次通过的印象。

本清单初稿仅整理风险与动作；后续实际执行情况见下节及付费前执行记录，不能据此把整份清单标为通过。主要依据为[Apple 审核指南](https://developer.apple.com/app-store/review/guidelines/)及各节官方文档；最终以当前规则和具体审核反馈为准。

## 2026-10-20 实际发现：未公开系统设置路径

`CameraWirelessSettings` 使用 `App-Prefs:root=WIFI` 与个人热点路径。这些不是已核实的公开导航 API，存在审核与兼容风险，不能因为模拟器能打开就认定可正式使用。[Apple 公开设置入口](https://developer.apple.com/documentation/uikit/uiapplication/opensettingsurlstring)只定位本 App 的设置。

用户已明确选择移除按钮。已移除首页两个无线设置入口、离线 AP 空态入口，并将 AP 信号胶囊改为与 USB/STA 相同的纯状态展示；清除共同跳转实现。GPS 权限设置采用公开接口，不属于本次移除范围。STA 重连不是设置跳转，保留。

构建及既有连接状态/顶栏布局专项 6/6 通过，日志 `/tmp/ztransfer-prelaunch-remove-settings.log`，生产代码检索已无原路径。首页改动后的实际排版仍待覆盖；不能把移除一项风险外推为必然通过苹果审核。
