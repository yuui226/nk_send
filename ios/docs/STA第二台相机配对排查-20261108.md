### 11:35 探测连接交接修复及集中验证

进一步核对发现实际平台实现差异：Android `PtpIpDiscovery.isPtpPortOpen` 使用 `Socket.use`，返回可连接候选前关闭探测连接；iOS 先前使用 `NWConnection`，收到 ready 后返回，`defer cancel()` 的关闭异步发生，正式 BSD 握手可能与探测连接重叠。已改为同一 BSD 通道的轻量探测：450ms 超时、绑定原本地地址、不发送 PTP 数据、无命令通道参数优化；返回候选之前同步 shutdown/关闭，不改变扫描优先级、24 并发或 48 地址批次。

这是已确认的连接生命周期差异，尚不是这台相机报错的已证实根因。Apple SDK `Network/connection.h` 明确 cancel 异步完成；[公开 cancel 文档](https://developer.apple.com/documentation/network/nwconnection/cancel%28%29)及[TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)用于核对平台机制。BSD 同样受本地网络权限约束，没有绕过权限。

r3 增加三个真实 TCP 探测回归并运行 41 项（含既有流程）：探测不发送协议字节并退出、后续正式连接可读写；失效本地绑定不能静默换路；取消不发布候选。与 r1/r2 去重 **92 项通过，9 项新增**。

### 11:50 根因确认：两个 MAC 同时声明相机 IPv4 地址

USB 接线后用开发诊断服务捕获，不依赖管理员密码；仅在内存筛选当前相机 IP 的 ARP/TCP15740，落盘只有头字段，不保留照片或其他业务流量。两轮有限采集已结束，RVI 已停止，临时 listener/DNS 浏览进程均退出。

ARP 实证：相隔 83.6ms，两种 MAC 均回复同一 `<conflicting-ip>` 属于自己。TCP 实证：相机 MAC 回复 SYN-ACK，但后续 ACK/下一连接 SYN 被手机地址表导向另一 MAC；另一 MAC 用相同源 IP 回 RST-ACK。故直接确认是局域网 IPv4 地址冲突，足以解释“探测偶尔可达/正式连接被拒绝”，不是推测相机业务拒绝配对。设备数据脱敏保留在 `arp-conflict-redacted.jsonl`、`tcp-headers-conflict-redacted.jsonl`。

用户确认相机启用自动获取 IP。不能据此认定相机自己选错或路由器一定双重分配，另一设备静态地址/重复 DHCP 等分配来源尚未核实。IEEE OUI 官方表将另一 MAC 前缀 `2C-19-5C` 登记为 Beijing Xiaomi Mobile Software Co., Ltd；不能仅靠前缀断言具体设备型号。建议核对路由器 DHCP/静态保留，给相机保留一个确实空闲地址，并让相机重新获取。
