## 本轮发现与处理

原 `STAConnectionDiagnostics` 在 Release 已不输出文件，但 `STAConnectionTrace` 本身仍分配锁/记录数组、读时钟、拼接日志。调用方即使遇到空实现，也会先生成参数字符串和 `trace.report()`。这些只在握手发生，未发现它们逐帧/逐包运行，不能将其说成持续发热根因；但结果在 Release 无消费者，属于可去掉的工作。

- trace 的锁、时钟、数组和写入逻辑限制在 `#if DEBUG`；Release `report()` 为空。
- trace 和诊断入口的文本/标签/报告/结果参数采用不逃逸 `@autoclosure`，Release 空实现不求值，避免 String(format:)、错误描述和报告拼接。
- 协调器的诊断等待计时、WiFi 服务的诊断最终结果跟踪只编译进 Debug；真正的重连期限时钟不动。
- 未改变发现顺序、协议命令、重试限额、信任写入、监看帧补救、UI 或动画；不是减少功能性验证来换性能。
