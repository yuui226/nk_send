## 检查命令

在仓库根目录执行，最后一个参数替换为实际生成的 Release `.app` 路径：

```sh
python3 ios/scripts/verify-release-bundle.py "/实际构建目录/ZTransfer.app"
```

脚本只读取文件，以 JSON 输出结果；`packagingChecksPassed: false` 或非零退出值都必须先查原因。不要通过删除报告中的失败项来“通过检查”，应修改工程打包配置并重新生成产物。

正式提交前还必须使用新增严格配置模式：

```sh
python3 ios/scripts/verify-release-bundle.py --submission "/实际构建目录/ZTransfer.app"
```

默认模式只检查打包，可在网页尚未上线时使用；`--submission` 同时要求两个法律 URL 已填写为不含占位、账号密码或本地/示例主机的 HTTPS 地址。报告始终列出 `legalURLConfigurationPassed` 与原因，严格模式有配置错误即返回非零。`selectedChecksPassed` 只表示选中的静态检查通过；即使为 true，也不代表网址已上线或已经可以送审。脚本不访问网站，还必须用实际 App 和浏览器检查网页正文、入口、登录限制、重定向、HTTPS 与语言。

历史配置验证（早于网址回填）：保留设备 Release 的普通模式退出0，严格模式准确因两个 URL 缺失退出1；另9项合成配置验证（有效形状、HTTP、凭据、普通/编码占位、示例主机、私有IP、无效端口、缺条款）符合预期，共11项。随后修正字体通知的文件指向文字后，旧包又准确报告通知已过时；必须在下一候选包中更新。没有修改原产物、发布网页或新建构建。[严格配置验证证据](evidence/submission-configuration-audit-20261021.json)

### Apple 当前规则与本机检查证据

- Apple 的 [iOS/iPadOS 27 发布说明](https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-27-release-notes) 在已修复问题 `166422120` 中说明：SDK 27 构建的 iPad App，不应再因为没有声明全部四个方向而被当作不能连续缩放窗口。因此，不能直接用旧版多任务规则断言这个 SDK 27 包一定上传失败。此结论只涉及该运行时行为，不证明较旧系统或上传验证已经放宽。
- Apple 的 [TN3192](https://developer.apple.com/documentation/technotes/tn3192-migrating-your-app-from-the-deprecated-uirequiresfullscreen-key) 当前版本已覆盖 iOS/iPadOS 27：`UIRequiresFullScreen` 已弃用，SDK 27 App 在系统 27 上即使将其设为 `YES`，也不能据此禁止用户调整窗口；它会影响连续或离散缩放方式。不能把加上这个键当作长期适配方案。
- 本机 Xcode 的 `SWBTaskExecution` 二进制仍包含 `validateiPadMultiTaskingSplitViewSupport` 校验符号，以及警告文本 `All interface orientations must be supported unless the app requires full screen.`。对应的 [Swift Build 公开源码](https://github.com/swiftlang/swift-build/blob/main/Sources/SWBTaskExecution/TaskActions/ValidateProductTaskAction.swift) 对 `iphoneos` 平台、包含 iPad 的包执行四方向检查；未声明全屏且缺少方向会发出警告，调用方不因此使构建失败。该公开源码不能证明本机每个分支或 Apple 服务端采用完全相同规则。
- 模拟器Release检查不运行上述`iphoneos`专属分支，`verify-release-bundle.py`也没有替代这项验证。2026-10-20只读核查时尚未构建设备包；2026-10-21上文的无签名设备Release已实际运行该验证并产生方向警告，随后构建成功。仍未进行分发Archive、上传验证或取得App Store Connect报告，故不记录“上传通过”或“必然拒绝”。
