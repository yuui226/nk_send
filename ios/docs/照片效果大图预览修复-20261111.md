## 依据与定位

iOS 两入口原先用 fullScreenCover，另用可选 expandedSnapshot 提供内容。工作台的入口还处于按可见范围创建/移除的 TabView 子视图中。弹层布尔状态和内容不是同一个发布状态，存在内容为空却仍呈现全屏控制器的路径，默认系统背景与系统转场又叠加在自绘缩放外。以上是源码定位，未在本轮通过运行或采样证明用户当次卡死的具体调用栈，不将其宣称为已实机复现。

## 修改

- 稳定的工作台/设置弹窗外层各自持有 PhotoEffectsExpandedPresentation。两个入口向它交付当前实际显示的完整预览图与锚点，顶层 overlay 直接显示。移除两处 fullScreenCover，不创建空白系统模态页，不移走底层工作台/弹窗。工作台和相机效果配置仍完全独立。

- 保留原340/260ms缩放、0.74遮罩、220ms逆时针旋转、双击/捏合/长按比较。预览期间屏蔽底层点击与辅助访问，PopupDragBoundary 阻止主工作台分页手势，收起期间继续拦截且禁用旋转。

## 后续检查：双指缩放不灵敏

用户反馈打开大图后的放大缩小不灵敏。读取 Android ZoomablePreviewViewport 的 awaitEachGesture/awaitFirstDown(requireUnconsumed=false)/calculateZoom 与 PreviewGestureGeometryTest，以及 iOS PreviewPinchObserver、PhotoEffectsExpandedImageSurface 和现有触摸回归。发现效果大图的 SwiftUI DragGesture(minimumDistance:0) 与窗口级 TouchTransform 竞争；后者未定义防止被取消的策略。当第一根手指先移动时，拖动可以先识别并使尚在等待第二根手指的缩放识别器失败。该路径可解释慢落第二指时不响应，但本轮未采集设备触摸事件，未宣称是所有不灵敏的唯一原因。

为 PreviewPinchObserver 增加仅效果大图启用的 retainsTouchesForPinch，防止同一触摸序列中的拖动/长按提前取消该识别器。保持原有第一次双指移动即更新、按实际距离比值缩放、缩放边界、反向手势和剩余单指平移。普通照片列表使用默认策略，未改变翻页竞争；没有增加缩放倍率或人为加速。仍由既有取消/结束/detach 清理触点和 magnifying 状态。

新增 testEffectsPinchSurvivesAnEarlierDragAndAppliesSmallReversingMovements，用已有 GestureAuditTouch 驱动实际识别器与效果缩放模型，检查单指先移动后第二指加入、拒绝被拖动取消、2%放大和反向缩小、结束复位。该测试未执行，不等同系统手势调度实测。三份 Swift 文件 parse 与 git diff --check 通过，未类型检查/构建/运行回归/安装。此追加任务开发2/2，运行验收0/1；整体预览任务仍等待设备验证。
