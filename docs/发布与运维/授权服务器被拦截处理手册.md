# 授权服务器被拦截处理手册

> 适用场景：App 提示「无法连接激活服务器」，新用户无法激活或付款，但服务器本身运行正常。
> 首次发生：2026-10-13 约 12:40 起。

## 1. 这次发生了什么

| 项目 | 结论 |
|---|---|
| 服务器 `106.15.239.203`（阿里云轻量，上海） | 正常运行，本机访问 `/healthz` 返回 `{"ok":true}` |
| 阿里云平台 | 工单确认平台侧无拦截、无备案阻断 |
| 被拦截的流量 | 这个 IP 上的**所有 HTTPS**（8443、9443 都一样，与证书、端口无关） |
| 不受影响的流量 | 同 IP 的普通 HTTP、SSH、ping |
| 影响范围 | itdog 全国测速：8443 失败 169/314，9443 失败 199/314；海外节点大多正常 |
| 拦截方式 | 运营商网络中的设备在 TLS 握手时注入伪造 RST，断开连接 |

关键证据（服务器抓包）：

- 客户端真实包 TTL=52，伪造 RST 包 TTL=57、IP id=1、无 DF 标志。
- RST 负载固定为 `01 02 03 04 05 06 07 08 09 00`，与 GFW Report 记录的**省级区域防火墙**注入特征一致：[Emerging Regional Censorship in China](https://gfw.report/publications/sp25/data/poster/poster.pdf)。
- 按 TTL 推算，注入点在客户端所在运营商的网络内，不在阿里云。

拦截原因目前**未确认**。最可能的原因是这个 IP 被运营商的反诈或可疑名单收录。容易触发误判的特征有：用裸 IP 访问、自签证书、个人收款通道、同机还运行着 `wxtool` 服务。

## 2. 对用户的影响

- **新用户**：激活和付款实时依赖服务器，被拦截期间无法完成。
- **已付费用户**：本地通行证过期前不受影响。过期后会暂时降成免费版，连上服务器后自动恢复，不需要重新输入激活码。
  - 2026-10-13 之前签发的通行证有效期是 7 天。
  - 从 2026-10-13 16:37 起，服务端改成签发 20 天的通行证（`server/license-server.js` 里的 `HARD_GRACE_SEC`），用户下一次续签成功后生效。

## 3. 总体方案

| 阶段 | 做法 | 耗时 | 作用 |
|---|---|---|---|
| 应急 | 香港轻量服务器 + 域名 + 正规证书 | 半天 | 恢复新用户的激活和付款（需发 App 新版本） |
| 中期 | ICP 网站备案 + App 备案 | 1–3 周 | 国内服务器合规，降低被误判的概率 |
| 长期 | App 内置多个服务器地址，自动切换 | 随应急版本一起发布 | 一个入口被拦，不会整体瘫痪 |
| 并行 | 向运营商 / 12321 申诉误拦截 | 数天到数周 | 让旧 IP 恢复，旧版本 App 也能自愈 |

**决策规则**：先提交备案。如果备案预计超过 3 天，或者已付费用户的通行证快要过期，就立即启动香港应急方案，不等备案结果。

## 4. 应急：香港服务器

### 4.1 购买

- 轻量应用服务器产品页：<https://www.aliyun.com/product/swas>
- 免费试用入口（新用户可领，地域和配置以页面为准，通常不含香港）：<https://free.aliyun.com/>
- 控制台：<https://swas.console.aliyun.com/>

购买时：

1. 地域选 **中国香港**。香港不需要备案。
2. 镜像选 **Alibaba Cloud Linux** 或 **CentOS / Rocky**，与上海服务器保持一致，方便迁移。
3. 最低配置就够用（授权服务内存占用约 80MB）。
4. 买好后在服务器「安全 → 防火墙」放行 TCP `8443`、`443`，来源 `0.0.0.0/0`。

### 4.2 先验证，再迁移

迁移前必须先确认香港 IP 在国内能正常走 HTTPS：

1. 在香港服务器上临时开一个测试服务：

   ```bash
   cd /tmp && openssl req -x509 -newkey rsa:2048 -nodes -keyout t.key -out t.crt -days 1 -subj "/CN=test"
   timeout 600 openssl s_server -quiet -accept 8443 -cert t.crt -key t.key -www
   ```

2. 用 [itdog 网站测速](https://www.itdog.cn/http/) 测试 `https://<香港IP>:8443/`。
3. 失败率明显低于上海（目标 < 5%）才继续，否则换一个 IP 重试。

### 4.3 域名

在 `ztransfer.top` 的 DNS 里添加：

| 记录 | 类型 | 值 |
|---|---|---|
| `api` | A | 香港服务器 IP |

然后申请 Let's Encrypt 正规证书，App 会通过 `https://api.ztransfer.top` 访问。连接看起来与普通网站一致，不再是「裸 IP + 自签证书」。

### 4.4 迁移清单

在香港服务器上：

- [ ] 安装与上海相同版本的 Node（当前为 v22.20.0），放到 `/opt/node`。
- [ ] 停掉上海服务的写入后，整体复制 `/opt/ztransfer-license/`，包括：
  - `license-server.js`、`config.json`
  - `license.db`（激活码、订单）
  - `pricing.json`、`app-latest.json`
  - 签名私钥，以及原有 TLS 证书和私钥（`tlsCertPath` / `tlsKeyPath`）。**必须沿用原证书**：旧版本 App 内置了它的指纹（`CERT_PIN_B64`）。
  - `backup.sh`，以及 cron 定时任务 `20 3 * * * /opt/ztransfer-license/backup.sh`
- [ ] 安装 `server/ztransfer-license.service` 到 systemd，并创建 `ztlicense` 用户。
- [ ] 修改 `config.json` 中的 `payNotifyUrl`，改为新地址。
- [ ] 登录虎皮椒商户后台，检查是否配置了回调地址或 IP 白名单，同步更新。
- [ ] 在本机验证 `curl -k https://127.0.0.1:8443/healthz` 返回 `{"ok":true}`。
- [ ] 在 443 端口用 Let's Encrypt 证书提供同一服务（Nginx 反向代理到 8443，或 Node 直接加载新证书）。

在上海服务器上：

- [ ] 把 8443 改为**转发到香港**（例如 `nginx stream` 或 `socat`），不再单独运行一份数据库，避免两边数据分叉。
- [ ] 旧 IP 解除拦截后，旧版本 App 会通过这条转发自动恢复。

### 4.5 App 改动（必须发新版本）

`app/src/main/java/com/ztransfer/license/LicenseManager.kt`：

- [ ] `SERVERS` 改为多地址，按顺序尝试：

  ```kotlin
  private val SERVERS = listOf(
      "https://api.ztransfer.top",
      "https://106.15.239.203:8443",
  )
  ```

- [ ] 证书校验按地址区分：
  - 域名地址：系统 CA 校验 + 主机名校验（正规证书）。
  - 旧 IP 地址：维持现有 `pinnedSocketFactory` 指纹校验。
- [ ] 记住上一次成功的地址，下次优先使用，减少切换等待。
- [ ] 按 `AGENTS.md` 的发布流程打包上线，并通过 App 更新系统推送强制更新。

## 5. 中期：ICP 备案

- 备案系统：<https://beian.aliyun.com/>（免费）
- 前提：
  - 阿里云国内服务器购买时长满 **3 个月**（含续费）。当前这台轻量服务器不足时，续费即可。
  - 域名 `ztransfer.top` 已在注册商完成**实名认证**。
- 需要准备：身份证、手机号，以及阿里云 App 人脸核验。如有公司或个体工商户执照，优先用企业主体（带付费功能的 App 用个人主体，部分省份审核更严）。
- 同时提交 **App 备案**（2023 年起国内上架 App 必须有）。
- 耗时：阿里云初审 1–2 个工作日，管局审核 1–3 周。
- 备案期间：备案域名**不要**解析到上海服务器，按阿里云要求保持关闭。

备案通过后：

1. 将 `api.ztransfer.top` 解析回国内服务器（或新增 `cn-api.ztransfer.top`），配置正规证书。
2. App 服务器列表把国内备案地址放在第一位，香港作为备用。

## 6. 申诉误拦截

拦截发生在运营商网络，可以并行申诉：

- 电信 10000、联通 10010、移动 10086：说明「正常软件授权服务的服务器 IP 被误拦截」，提供 IP `106.15.239.203`、端口、开始时间（2026-10-13 12:40），并询问拦截原因。
- 12321 网络不良与垃圾信息举报受理中心：<https://www.12321.cn/>
- 问到具体原因后，再决定是否需要调整（例如更换正规商户收款通道）。

## 7. 验证方法

| 目的 | 命令 / 工具 |
|---|---|
| 服务本身是否正常 | 在服务器上运行 `curl -k https://127.0.0.1:8443/healthz` |
| 全国连通率 | [itdog 网站测速](https://www.itdog.cn/http/) 测 `https://<地址>/healthz` |
| 海外连通 | [check-host.net](https://check-host.net/) |
| 确认是否为注入的 RST | 在服务器上运行 `tcpdump -i any -nn -v "tcp port 8443 and host <客户端IP>"`，看 RST 的 TTL 是否与正常包不同、负载是否为 `01 02 … 09 00` |

注意：抓包过滤**不要**排除服务器内网 IP（`172.24.28.131`）。外部流量进入服务器时，目标地址就是这个内网 IP。

## 8. 安全加固（尽快处理）

- [ ] 立即修改 root 密码。2026-10-13 时过去 24 小时内有 7930 次 SSH 密码登录失败，存在暴力破解。
- [ ] 改为仅允许密钥登录：在 `/etc/ssh/sshd_config` 中设置 `PasswordAuthentication no`，并在轻量服务器防火墙中把 22 端口限制为常用 IP。
- [ ] 确认 `/opt/wxtool_server`（`wxtool_server.service`，监听 0.0.0.0:8000，以 root 身份运行，2026-07-31 启动）的来源。如果不是自己部署的，按入侵处理：保留证据，检查 `/root/.ssh/authorized_keys`、crontab、systemd 单元，必要时重装系统。
- [ ] 不需要的端口（8000、9443 等）从防火墙中删除。

## 9. 回滚

- 服务端改动之前已有备份，例如 `/opt/ztransfer-license/license-server.js.bak-20261013-163732`。拷回原文件后执行 `systemctl restart ztransfer-license`。
- App 多地址版本保留旧 IP 作为最后一个候选，香港不可用时会自动回到原地址。
