# 授权服务临时迁移到腾讯云

记录日期：2026-10-15

这次把授权服务从阿里云 `106.15.239.203:8443` 临时搬到腾讯云轻量 `122.51.32.193` 的 443 端口，对外地址是 `https://www.au9999.net`。自己的域名 `ztransfer.top` 仍在备案，解析继续暂停。备案通过后的正式切换仍按 [`docs/待做/备案通过后迁移授权服务.md`](../待做/备案通过后迁移授权服务.md) 执行。

本文只记做法和当时的落地结果。管理员令牌、虎皮椒密钥、签发私钥和数据库都不写入文档。

## 为什么这样迁

阿里云这台机器的 HTTPS 在运营商侧被重置，和证书、端口无关。备案不会把 `106.15.239.203` 放出来。裸 IP 加自签证书是当时被识别成异常 HTTPS 的形态。

正规形态是：已备案域名解析到国内云厂商的公网 IP，443 端口使用公共证书机构签发的证书。`ztransfer.top` 的备案号还没下来，备案期间这个域名不能解析到国内服务器。朋友的 `au9999.net` 已经在腾讯云备案（闽ICP备2025102086号-2），`www` 的 A 记录当时已经指向 `122.51.32.193`，所以用 `www.au9999.net` 做临时入口。

根域名 `au9999.net` 指向另一台机器 `95.169.11.62`，没有改动。`apk.ztransfer.top` 继续指向香港 OSS。`wxtool` 没有装到新服务器。

2026-10-15 核对时：服务端程序与仓库 `server/license-server.js` 的 SHA-256 一致，签发私钥与 App 内置公钥配对，数据库完整性正常。当时账本为 351 个激活码、345 条绑定、305 笔已付款订单。定价与旧服务器一致：年费 19.99 元，永久版 59.99 元。对外更新信息仍是 1.94，因为 1.95 还没发到 OSS。

## 1. 登录新服务器

在操作的 Mac 上生成一把只给这台机器用的密钥，并把主机别名写进 `~/.ssh/config`：

```sshconfig
Host ztransfer-tx
  HostName 122.51.32.193
  User root
  IdentityFile ~/.ssh/ztransfer_tencent_ed25519
  IdentitiesOnly yes
```

腾讯云网页登录框里的「密钥验证」要的是已经授权过的私钥，用来让网页自己登录。把 `.pub` 公钥传上去会报格式不正确。公钥要在服务器里追加到 `root` 的 `authorized_keys`。

进机器用网页终端的「密码验证」、上方的「免密连接 (TAT)」，或下方的「VNC登录」。进去后执行：

```sh
mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo '这里换成公钥一行' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

之后从 Mac 执行 `ssh ztransfer-tx`。私钥留在本机，不进仓库。

这台 Mac 上的 Clash 会把该 IP 送进 `utun`（网关 `198.18.0.1`）。直接 `curl` 域名会得到假的握手失败。核对公网是否真的到达服务器时，绑定物理网卡并绕过代理，例如：

```sh
curl -sS --interface en0 --noproxy '*' \
  --resolve www.au9999.net:443:122.51.32.193 \
  https://www.au9999.net/healthz
```

系统防火墙 `firewalld` 在这台机器上是关闭的。端口放行以腾讯云轻量控制台的「防火墙」为准。当时 22 和 80 已经放行，443 没有。80 上没有程序时，外网连接会立刻被拒绝，说明包进了机器；443 超时且服务器抓包为空，说明包被云防火墙丢掉。在控制台增加一条 TCP 443、来源 `0.0.0.0/0`、策略允许。

## 2. 申请正式证书

`www` 已经解析到这台机器，用 HTTP-01。现有的 `apk.ztransfer.top` 续期脚本只能给那个名字写阿里云 TXT，不能拿来签 `www.au9999.net`。

签发时 80 端口必须空着。OpenCloudOS 9 的 EPOL 源里有 certbot：

```sh
dnf install -y certbot
certbot certonly --standalone -d www.au9999.net \
  --agree-tos --register-unsafely-without-email \
  --non-interactive --preferred-challenges http
systemctl enable --now certbot-renew.timer
```

证书在：

- `/etc/letsencrypt/live/www.au9999.net/fullchain.pem`
- `/etc/letsencrypt/live/www.au9999.net/privkey.pem`

授权进程以 `ztlicense` 运行，读不到 root 专用的 Let's Encrypt 目录。把证书复制到服务目录，续期后也要复制并重启，因为进程只在启动时读取证书：

```sh
install -d -o ztlicense -g ztlicense -m 750 /opt/ztransfer-license/certs
install -o ztlicense -g ztlicense -m 644 \
  /etc/letsencrypt/live/www.au9999.net/fullchain.pem \
  /opt/ztransfer-license/certs/fullchain.pem
install -o ztlicense -g ztlicense -m 600 \
  /etc/letsencrypt/live/www.au9999.net/privkey.pem \
  /opt/ztransfer-license/certs/privkey.pem
```

`/etc/letsencrypt/renewal-hooks/deploy/ztransfer-license.sh` 做同样的复制，然后 `systemctl restart ztransfer-license`。续期仍用 standalone，所以 80 端口要留给 certbot，授权服务只听 443。

证书名称只写 `www.au9999.net`。根域名、`ztransfer.top`、`api.ztransfer.top` 都不放进这张证书。

## 3. 安装运行环境

按 `server/部署指南.md` 安装 Node，版本不低于 22.13，这次用的是 v22.20.0：

```sh
curl -fsSL https://npmmirror.com/mirrors/node/v22.20.0/node-v22.20.0-linux-x64.tar.xz -o /tmp/node.tar.xz
mkdir -p /opt/node
tar -xJf /tmp/node.tar.xz -C /opt/node --strip-components=1
```

创建系统用户，目录为 `/opt/ztransfer-license`。程序文件用仓库里的 `server/license-server.js`。旧服务器上那份和仓库只差换行，以仓库为准。

`ztlicense` 不能直接绑定 443。部署用的 systemd 单元在仓库模板之外加了绑定能力，写在 `/etc/systemd/system/ztransfer-license.service`：

```ini
[Unit]
Description=ZTransfer license server
After=network.target

[Service]
Type=simple
User=ztlicense
Group=ztlicense
WorkingDirectory=/opt/ztransfer-license
ExecStart=/opt/node/bin/node /opt/ztransfer-license/license-server.js /opt/ztransfer-license/config.json
Restart=always
RestartSec=3
AmbientCapabilities=CAP_NET_BIND_SERVICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/opt/ztransfer-license

[Install]
WantedBy=multi-user.target
```

仓库里的 `server/ztransfer-license.service` 仍是旧机器的 8443 模板，不能原样覆盖这台机器上的单元。

## 4. 搬走密钥、配置和账本

必须原样带走的只有签发私钥 `signing-key.pem`。换掉之后，已经发出的通行证全部无法续签。`config.json` 里的管理员令牌和虎皮椒配置也原样保留，这样本机已保存的 `admin-token.txt` 继续有效。

当时这台 Mac 登不上旧服务器。材料来自 2026-10-13 20:23 的本机备份 `~/ZTransfer-server-backups/20261013-202319`：

- `extracted/license.db.snapshot`：当时完整性检查通过，346 个激活码、471 笔订单。用这份快照，不用正在写入的 `license.db` 直接拷贝。
- `extracted/opt/ztransfer-license/signing-key.pem`
- `extracted/opt/ztransfer-license/config.json`
- `extracted/opt/ztransfer-license/pricing.json`

备份之后到迁走之前，旧服务器仍在写入。新服务器访问旧服务器的 HTTPS 是通的，就用管理员接口 `GET /admin/codes` 把激活码、绑定和激活历史覆盖进这份快照。覆盖后是 350 个激活码，最晚一张创建于 2026-10-14 17:21 UTC。

订单行仍以备份为准。备份之后新产生的 4 个激活码，码和绑定都在新库里，对应订单行留在旧服务器。这 4 个码可以激活；要退款时到旧服务器查订单。`paid_unbound` 当时是 0，没有另补订单。

`app-latest.json` 不看备份。备份里还是 1.93。上线前从旧服务器的 `GET /v1/app/latest` 取回 1.94 的发布记录再放上。

`config.json` 只改这几项，其余字段不动：

| 字段 | 新值 |
|---|---|
| `port` | `443` |
| `dbPath` | `/opt/ztransfer-license/license.db` |
| `tlsCertPath` | `/opt/ztransfer-license/certs/fullchain.pem` |
| `tlsKeyPath` | `/opt/ztransfer-license/certs/privkey.pem` |
| `signingKeyPath` | `/opt/ztransfer-license/signing-key.pem` |
| `payNotifyUrl` | `https://www.au9999.net/pay/notify` |

文件权限：`config.json`、`signing-key.pem`、`license.db`、证书私钥为 `600`，属主 `ztlicense`。定价和 `app-latest.json`、程序文件为 `640`。

先在服务器本机确认：

```sh
curl -sS --resolve www.au9999.net:443:127.0.0.1 https://www.au9999.net/healthz
```

返回 `{"ok":true}`，证书名称是 `www.au9999.net`，颁发机构是 Let's Encrypt。然后再从外网用上一节的绕过代理命令看同一地址。定价、当前版本和下载地址要与旧服务器的公开接口一致。

旧服务器不要在新地址确认可用之前关掉。两台同时开着时，旧版 App 仍会把新激活和付款写到旧库，新版 App 写到新库，两边不会自动合并。

## 5. 客户端和管理工具

`app/src/main/java/com/ztransfer/license/LicenseManager.kt`：

- `SERVERS` 只有 `https://www.au9999.net`。
- 去掉自签证书指纹和自定义信任管理器，HTTPS 交给系统证书库校验主机名。正式证书会续期，不把叶子证书钉死。
- 通行证签名公钥 `PUBLIC_KEY_B64` 不变。它对应的是签发私钥，不是 TLS 证书。
- `HOLD_PRO_IF_RENEW_UNREACHABLE` 保持 `true`。续签连不上时，已签名且年费未到期的用户不降级。等新地址稳定、在网设备完成一轮续签后，另发一版再改回 `false`。

`app/build.gradle.kts` 这次改为 `versionName` 1.95、`versionCode` 68。已安装的 1.94 仍访问 `https://106.15.239.203:8443`，收不到应用内更新。用户用固定地址覆盖安装一次。装上能访问当前授权域名的版本之后，再换域名就可以走应用内更新，条件是旧域名在新包装发出去之前仍然可用。

`server/admin.ps1` 的默认服务器改为 `https://www.au9999.net`，默认按系统证书校验。图形界面读的是同一个 `$Server`，侧边栏应显示 `www.au9999.net`。发码、台账、解绑、吊销和发布都打到这台新服务器。

环境变量 `ZT_SERVER` 或 `ZT_SERVER_PIN` 如果还留着，会继续打旧地址，或因为旧指纹对不上而拒绝连接。正常使用时清掉这两个变量。只有临时连回旧的自签地址时才设置 `ZT_SERVER_PIN`。

设置页手动检查更新失败时，复制 `https://apk.ztransfer.top/ZTransfer.apk`，并提示三行：检查更新失败、已复制下载地址、请到浏览器下载。后台自动检查失败时不弹，也不改剪贴板。

## 6. 自己的域名先不要写进 App

`api.ztransfer.top` 在备案完成前没有解析，也没有证书。写进 `SERVERS` 后，临时域名正常时用不上；临时域名失败时，客户端会再空等一次连接超时。备案号下来、A 记录指向 `122.51.32.193`、并且 443 上有包含该名字的正式证书之后，再把 `https://api.ztransfer.top` 放成第一地址。`www.au9999.net` 可以在那一版里留作第二地址。

朋友的域名不能长期占用。切回自己的域名并确认用户能连上之后，再停掉 `www.au9999.net` 上的授权服务，并把解析从这台机器拿开。停掉之前，已经装了临时域名版本的用户需要先通过应用内更新拿到指向 `api.ztransfer.top` 的包。一直停留在旧阿里云地址上的用户，临时域名关掉后仍然只能用固定安装包链接覆盖安装一次。

## 7. 以后再搬一次时的顺序

1. 新地址先有公共证书，防火墙放行 22 和 443。80 只在签发和续期时需要。
2. 安装 Node 22.13 或更高，部署当前仓库的 `server/license-server.js`。
3. 复制签发私钥、管理员令牌、虎皮椒配置。私钥必须是正在使用的那一把。
4. 数据库用 SQLite 备份或一致性快照，再把备份之后的激活码、绑定和激活历史补上。正在使用的 `license.db` 不要直接当最终文件拷走。
5. 发布记录从线上 `GET /v1/app/latest` 取，不从旧备份取。
6. 本机 `healthz` 通过后，再让域名指向新机器。
7. 外网核对证书名称、定价、更新信息和一笔真实的付款、激活。
8. 改 App 的 `SERVERS` 和管理工具默认地址，提高 `versionCode`，把安装包发到 OSS 固定地址。
9. 旧地址保持可用，直到依赖它的已安装版本都有路可更新。然后才停旧服务。签发私钥和数据库先留着。
