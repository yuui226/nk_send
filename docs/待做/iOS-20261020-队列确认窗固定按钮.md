## 实现

- 找到原有闪现/错起点的核心缺陷：Android `genieRow` 返回面板局部坐标，而 iOS `row` 返回所给坐标系下的绝对坐标；iOS `rowAbove` 却再次做 `panel.maxY - row.y`，导致向上动画整体多偏移一整块面板高度。改为直接反射 `-row.y`，展开终点与真实面板重合、收回终点落在按钮上缘；原时长/曲线/横向口宽保持。
- 两个 FAB 各保留 58×58 按钮、原 12pt 顶部间距及底栏位置；确认卡使用零占位覆盖 Layout，以自然高度、最大 260pt 宽度放在按钮上方 12pt，右缘对齐，不参与按钮列排版。
- 原生 Genie 宿主新增可选的右侧固定按钮宽度锚点，在真实 bounds 已确定的同一次布局中换算，删除队列的全局坐标 State/Preference 回传。其他弹窗未设置此参数，继续原显式锚点规则。
- 取消/再次点击/遮罩/控制事件维持反向收回和中途反转；确认独立标记，内容保持完整尺寸，以原关闭时钟的进度淡出，按钮仅局部观察同一进度。确认瞬间冻结按钮启用外观，后续任务准入变化不导致先置灰。
- 到零时直接完成按钮退场，避免从 opacity=1 重新播放第二次消失；若重试又立即失败、再次符合条件，从零重新入场，不遗留透明但仍占用点击的按钮。没有新增持续动画时钟或延后业务清空/重试。

开发侧 3/3 完成。旧 UI 测试曾要求重试按钮上移，该预期依据旧安卓占位规则；本轮按用户新规则修正，不能沿用旧通过记录证明本轮完成。

- `queue-confirm-before`（`/tmp/ztransfer-1020-queue-confirm-before.{log,xcresult}`）：真实界面基线 1/1 失败，`TEST FAILED` / exit 65。打开清空确认卡后，重试按钮 y=676→527.67，实际上移 148.33pt；清空按钮静态终点本轮基线没有检出漂移，不将此结果冒充中间帧已复现。
- 第一版 `queue-confirm-fixed`：9 项中 2 项弹簧模型通过、7 项失败。覆盖布局内的尺寸 Preference 未推动展开，真实触摸后 mounted=1 而窗口仍透明；新增组件测试的标签 Preference 也未读到数据。放弃此尺寸回传方式，动画锚点改在原生宿主布局时直接依据实际宽度计算；保留其余调用方原先的显式锚点路径。

- 第三版 `queue-confirm-placement`：真实 UI 的固定按钮/取消、确认重试后立即再次失败两个专项均通过，组件测试仍失败。继续定位发现第一版把显隐动画初值统一设成 false，空内容的 onAppear 不能可靠启动“首次进入已有任务”的按钮；改为按实际 visible/mounted 初始化，保留后续显隐过渡。该缺陷与前两轮探针未返回的问题相关，不仅作为测试夹具问题处理。
