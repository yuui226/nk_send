# iOS 触感场景与震感设计

基准：本地 Android `25860ae6`；iOS 起点 `2720a274`。2026-10-19 用户要求先整理安卓触发场景，再利用 iPhone 马达设计不同震感并应用。**这是已授权的震感平台差异**：保留操作、准入、取消和状态边缘，不要求复制 Android CLOCK_TICK/LONG_PRESS 的物理波形，不修改手势时长与动画。

## iPhone 震感方案

高频刻度采用复用的 UISelectionFeedbackGenerator；操作反馈复用 UIKit soft/light/medium/rigid，不为每个格子创建引擎。连接/传输完成及蓄力使用一个按需启动、自动休眠的 Core Haptics 引擎；无硬件/引擎不可用时退回系统反馈。无音频、无帧循环、无定时补震。

| 语义 | 设计参数（强度0–1） |
| --- | --- |
| selection | 系统 selection，跨档才触发 |
| toggle | rigid 0.45 |
| navigation / preview | soft 0.45 / soft 0.70 |
| favorite | soft 0.85 |
| action / enqueue | light 0.65 / medium 0.75 |
| focusStarted / focusLocked | light 0.35 / rigid 0.65 |
| shutter | rigid 1.00 |
| contentReady | light 0.45 |
| connectionReady | 瞬态0 ms(0.35,锐度0.40)、100 ms(0.75,0.65) |
| transferComplete | 瞬态0 ms(0.25,0.30)、70 ms(0.45,0.50)、160 ms(0.80,0.65) |
| failure | 系统 error |
| celebration | soft 0.80 |
| holdConfirmed | rigid 0.85 |
| 蓄力 | 随现有手势期限生成2–8个由稀到密、渐强的瞬态；强度0.12→0.46，锐度0.25→0.70，最后14%期限安静；完成另给确认，取消立即停止 |

UIKit 强度是相对请求，不保证不同 iPhone 物理振幅完全相等。场景差异应能辨别，不能靠增加长时间强震制造存在感。自动重连轮询、列表滚动、监看帧更新、速度读数/进度动画、灯泡、普通关闭按钮不新增震动。iOS 原有设置/筛选入口的轻点仍保留，改归 navigation；这是已有 iOS 反馈，不冒称安卓另有相同调用。

Apple 依据：[Playing haptics](https://developer.apple.com/design/human-interface-guidelines/playing-haptics)、[Preparing your app to play haptics](https://developer.apple.com/documentation/corehaptics/preparing-your-app-to-play-haptics)。强调因果一致、克制、硬件降级和中断后不回放旧手势。

## 实现与验证记录

- `DesignSystem/HapticPolicy.swift` 保存16种语义、原生震感参数和有限蓄力波形；`ZTransferHaptics.swift` 统一偏好门控、同步长按去重与物理渲染。全仓 UIKit 反馈发生器及 Core Haptics 引擎的创建均集中于这里。多个控件仅有轻量所有权；旧控件取消/完成不干扰当前控件。进入后台、关闭触感、引擎中断停止自定义播放器，不重放旧操作；每次引擎启动刷新代次，忽略旧回调。
- `SettingsView`、`PhotoFilterPopupOverlay`、`PhotoEffectsEditorView`、`PhotoLUTChooser`、`PhotoEffectsMasterSwitch`、`DetentWheel` 接入设置、筛选及效果两入口；无全局按钮自动震动。
- `PhotoListView` / `PhotoPreviewView` / `PhotoCropEditor` 接入预览、分组、入队、FHD和裁切。裁切原先在确认闭包和入袋动画各 tick 一次，现只在成功准入后的入袋节点一次 enqueue。反向长按先结束蓄力，业务准入成功才发 enqueue，拒绝不发成功反馈。普通200 ms预览不新增蓄力。
- `ConnectionPage`、`GPSConnectionControl`、`RemoteViewModel`、`RemoteShutterButton`、`RemoteLUTPanel`、`RemoteView`、`PremiumFireworks` 接入连接/对焦/快门/结果反馈；补STA主动搜索（忙态不震）。GPS与快门各自持有长按所有权，面板关闭不误取消别处蓄力。监看端侧录制仍无实现。
- 第一轮 `/tmp/ztransfer-1019-haptics-1.log`、同名 `.xcresult`：18/18模型/组件专项通过，真实触摸4项仅1项通过（总19/22），`TEST FAILED`、exit65。新增 SwiftUI `LongPressGesture.updating` 虽能得到开始/取消，但在现有 exclusive 组合中破坏了短按和滚动；不得以逻辑测试通过认作完成。
- 撤回上述接法，复用 `ZTransferButtonMotionController` 内已有窗口级被动触摸观察器。探针仅报告按下/移动取消/松手，不识别手势、不阻止滚动、不发业务动作；按钮原8 pt、照片12 pt容差独立。只有反向照片挂探针。仍使用原始 exclusive 长按/点击组合，所有手势时长不改。`ButtonInteractionTrace` 仅显式UI测试开启时记录触感事件，正常启动不记录、不建时钟。
- 第二轮 `/tmp/ztransfer-1019-haptics-2.log`、同名 `.xcresult`：33/33通过，0失败/跳过，`TEST SUCCEEDED`、exit0。包含10个触感专项、14个按钮模型/宿主专项，以及9个真实触摸UI专项。加上首轮已通过且未受后续观察器修改影响的6个快门和2个真实监看模型专项，两轮按测试标识去重 **41/41最终通过（32模型/组件、9真实触摸UI）**，不是55个不同用例。汇总 `/tmp/ztransfer-1019-haptics-results.json`。
- 第二轮实际触摸记录：普通/连拍长按回调208/203 ms，预览挂载441/435 ms；反向入队按下4 ms开始蓄力，262 ms长按识别并停止蓄力、267 ms唯一入队确认；滚动119 ms停止蓄力、122 ms开始实际滚动，未入队/预览；拨轮458 ms完成，GPS804 ms完成触感、850 ms关闭。都是模拟器逻辑/触摸记录，**不是物理马达出力时延**。事件附件位于 `/tmp/ztransfer-1019-haptics-2-attachments/`。
- 全仓复查：不存在散落的 UIImpact/UISelection/UINotification 发生器或额外 Core Haptics 引擎创建；没有新增 CADisplayLink、重复计时器、后台补震或音频会话改动。`git diff --check`通过，测试进程均已结束。仅SDK版本解析既有 `invalidDigitCount`诊断，不影响实际测试结果。
- 未执行 Android 测试、全套iOS测试、实机马达/功耗/中断故障注入/不同机型体验验收。后续真机重点感受：拨轮连调轻重、250/450/800 ms蓄力、入队单次落定、对焦与快门区分、连接/传完收束，以及全局开关关闭后的静默。实机未验收不标记为“震感完美”。
