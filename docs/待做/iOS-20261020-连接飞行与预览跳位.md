## 实际问题与修复

1. Root 原先在连接前后两个结构分支中分别构建 Home。改为稳定的同一个兄弟节点，复用已测量卡片与图标；交接任务按动画开始日期启动，并按该日期算剩余时长，消除对 session 回调与动画状态写入顺序的依赖。图标、免费/高级光效、连接发现和目录扫描逻辑不改。
2. 预览原先对 `ignoresSafeArea` 容器本身做缩放。实际展开记录显示图片视口从 **402×656 突变到 402×752**，缩略图顶部同一阶段出现 **194→132→158pt** 的跳动。单纯固定 TabView 子页尺寸仍失败，另一次记录为 **194→110→158pt**。最终把不参与变换的全屏 GeometryReader 放在外层，TabView 与图片变换放在其内部；视口始终为 **402×752**，展开的图片矩形保持连续轨迹。FHD 更新原透明度与布局规则保留。
3. 原页偏移以缩放后的左边距除宽度得出。实际上滑从 `.upward` 变成 `.rejected`，测得伪横翻偏移 **0.011111…** 超过原 0.01 门槛。两矩形 SwiftUI preference 抵消方案只能修复上滑，展开阶段仍有约 -0.06 假偏移，因此已撤回。最终使用独立 `PhotoPreviewPagerObserver` 在分页 UIScrollView 自身坐标读取页位置：仅观察 contentOffset/布局，合并回调，持有弱页面引用，卸载撤观察，无持续帧钟。上滑不再移除命中子树，只锁横翻；缩放/透明度按安卓的 **96pt** 阈值计算，不再误用 132pt 顶点。
4. 最后实际截图发现 FHD 淡入完成后旧缩略图仍永久不透明，宽高比不同时露出多余旧画面。按安卓 `effectiveFhdAlpha < 1` 规则，加入叶节点 `AnimatableModifier`：淡入全程保留缩略图，到实际渲染终点才隐藏，不按 @State 目标值在第一帧移除。前后截图已查看，残留旧图消失；图片加载、EXIF 与手动旋转业务保持原有逻辑。
