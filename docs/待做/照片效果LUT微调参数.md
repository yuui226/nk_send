# 照片效果 LUT 微调参数

状态：待实现

## 目标

在照片效果的 LUT 分区中，保留现有 LUT 选择和浓度调整，并允许用户对 LUT 结果做少量、可控的后期微调。预览和最终导出的效果必须一致，已经入队的任务必须保留入队时的完整参数。

LUT 分区中的“强度”改名为“浓度”。浓度仍然表示 LUT 结果与原图之间的混合比例；内部字段和旧持久化键可以继续使用 `intensity`，避免无意义的数据迁移。其他既有照片滤镜是否改名不在本次范围内。

## 第一阶段参数

每一个参数使用一个独立波轮：

1. LUT：选择、关闭和切换 LUT。沿用已有的文件夹、分类、收藏和长按选择逻辑。
2. 浓度：LUT 与原图的混合比例。默认 80%，保留现有档位和范围。
3. 对比度：整体明暗反差，默认 0。
4. 饱和度：整体颜色浓度，默认 0。
5. 高光：亮部的压缩或提升，默认 0。
6. 阴影：暗部的提升或压低，默认 0。

锐度、降噪、颗粒感、色温、色调、色相和局部调整不放入第一阶段。降噪需要邻域运算，颗粒需要稳定随机种子，色温/色调/色相需要明确工作色彩空间，暂时加入会明显增加复杂度和验证成本。

## 参数范围与行为

- 中性值统一为 0；波轮回到 0 时必须得到不额外修正的结果。
- 参数范围先采用保守范围：对比度、饱和度、高光、阴影均为 -100 到 +100。
- 需要根据实际照片验证后再决定是否缩小可用范围；不能让极端值产生 NaN、溢出或整张纯黑/纯白。
- RGB 输出统一在 0..1 或 0..255 范围内夹取，Alpha 保持原值。
- 每个 LUT 单独保存浓度、对比度、饱和度、高光和阴影。关闭 LUT 时保留这些值，重新启用该 LUT 后恢复。
- 切换到另一个 LUT 时读取另一个 LUT 的参数；没有历史参数时使用默认值。
- 参数记录使用现有 LUT 的稳定内容标识（digest/snapshot key），不直接把完整 URI 作为业务身份；URI 只作为找回文件的来源信息。文件移动、重新授权或目录更换不能让同一份 LUT 产生一组无法清理的重复参数。
- LUT 关闭选项不应清除任何参数或收藏状态。

## 建议的处理顺序

```text
解码原图
→ LUT 映射
→ 按浓度与原图混合
→ 高光/阴影
→ 对比度
→ 饱和度
→ 边框、水印
→ 编码与保存
```

高光和阴影应使用基于亮度的软权重，而不是简单按 RGB 通道截断：

- 阴影权重在低亮度区域最高，向中间调平滑衰减。
- 高光权重在高亮度区域最高，向中间调平滑衰减。
- 过渡必须连续，避免在某个亮度阈值产生断层或光晕。

对比度围绕中点调整，饱和度围绕灰度亮度调整。第一版不改变色相，避免肤色和品牌色漂移。所有公式明确工作在当前项目既有的 sRGB 8-bit 处理域中；第一版不引入新的色彩空间转换。

## UI 方案

当前 LUT 选择波轮、浓度波轮和收藏按钮保留。新增一个“微调”入口，点击后显示同一 LUT 分区下的紧凑波轮区域：

```text
LUT选择   浓度   收藏
对比度    饱和度  高光    阴影    重置
``` 

“浓度”仍然是 LUT 参数，不再同时显示“强度”。“微调”入口只负责展开四个修正波轮；LUT 选择和浓度继续留在原来的主行，避免一个分区出现两个同义入口。

- 每个参数一个紧凑型波轮，沿用项目现有波轮组件和触感反馈。
- 入口展开和收起复用现有通用展开动画，不新写一套弹窗动画。
- 参数较多时允许换成两行，但不出现横向滚动，也不遮挡生成按钮。
- “重置”只恢复当前 LUT 的五个参数，不清除 LUT 文件夹、收藏和其他照片效果设置。
- 参数在调整时实时更新预览；拖动波轮不触发文件重新读取或重新解析 `.cube` 文件。

## 持久化与队列快照

建议在 `PhotoLutStore` 中按 LUT 的稳定 digest/snapshot key 保存一个版本化参数对象。浓度仍沿用现有
`PhotoFilterSelection.intensityPercent` 字段；`LutAdjustments` 只保存四个新增微调值，避免同一参数出现两份状态：

```text
lut_adjustments_v1:<digest> = {
  contrast: 0,
  saturation: 0,
  highlights: 0,
  shadows: 0
}
```

实际可以沿用现有 SharedPreferences 或一个小型 JSON 记录，但必须集中由 `PhotoLutStore` 读写、规范化和清理，不让 UI 或队列直接拼接持久化键。旧的 `strength:<uri>` 继续作为浓度的兼容来源；新增四个微调值不使用 URI 作为身份，也不因为换目录或重新授权而复制一份。

入队时将 LUT 的稳定标识、LUT 内容快照/已有 snapshot 引用、浓度和四个微调值一起写入任务。之后用户切换 LUT 或修改参数，不得改变已经入队的任务。

预览、普通生成、裁切后生成、已有原图派生生成和重试生成都必须使用同一份参数快照。没有 LUT 的普通滤镜流程不受影响。

## 性能与实现边界

当前项目已经有：

- `CubePhotoFilterParameters` / `PhotoCubeMapper`；
- Native16K 与 Kotlin fallback；
- 分区处理和复用 scratch buffer 的原图导出链路；
- `PhotoLutStore` 的 LUT snapshot 和强度持久化。

实现应扩展现有 `PhotoFilterSelection` 和 `PhotoFilterRenderer`，不要另起一套 LUT 渲染器。

### 维护边界

建立一个集中、可测试的 `LutAdjustments` 数据类，包含对比度、饱和度、高光和阴影；浓度继续由 `PhotoFilterSelection` 承载，并在入口统一做范围规范化。颜色公式集中在一个 `LutColorPipeline`/等价的共享层中：输入像素、LUT、参数，输出一个确定的 RGBA 结果。

1. LUT 解析、缓存和 3D 映射保持不变。
2. 先实现并测试 Kotlin 参考公式；预览、导出和重试都必须调用它或调用与它逐项对齐的执行器。
3. Native 只是该公式的加速后端，不能拥有另一套参数含义。接入 Native 前必须用固定像素样本与 Kotlin 参考结果逐通道比较，允许误差范围写成测试常量。
4. 如果 Native 扩展无法在第一阶段完成，暂时统一走已有的 Kotlin 分区处理也比维护两套不一致的颜色逻辑更稳妥；只有性能测量证明必要时才接入 Native。
5. 预览若使用 GPU shader，也必须以同一参数顺序和同一公式为准，并做 CPU/GPU 样本对照；不允许仅为预览另写近似算法。Native LUT 映射完成后也必须执行同一个微调后处理；第一版可以在同一分区缓冲区上追加一次原地后处理，不能漏掉参数或复制整张原图。
6. 调整波轮只更新参数，不重新读取文件、不重新解析 `.cube`、不复制整张原图；渲染时继续复用现有分区和 scratch buffer。

这样后续增加锐度或颗粒时，只需扩展参数模型和同一条管线，不会在 UI、导出、预览各处各写一份规则。

## 可靠性要求

- 参数值必须被限制在合法范围内，防止异常输入导致渲染崩溃。
- LUT 读取失败时保留原有错误提示，微调参数不得影响 LUT 文件夹扫描。
- 生成失败时原图必须保持不变，队列卡片应显示可读错误。
- 预览与导出至少用同一组样张对比：肤色、天空、高光灯、暗部、低饱和灰色物体。
- 检查极端参数、关闭 LUT、切换 LUT、重启应用、重新入队和生成重试。
- 检查裁切入队、已有原图派生、传输失败重试，以及 LUT 文件夹更换后旧任务仍按入队快照生成。
- 检查参数调整过程中只更新内存选择状态和对应 digest 记录，不重新扫描目录、不重新解析 cube、不影响传输线程。

## 方案审查结论

- 参数职责已分开：浓度沿用旧字段，四个微调值由 `LutAdjustments` 统一承载；关闭 LUT 不会丢值。
- 身份固定为内容 digest，避免 URI 变化造成重复参数和无法清理的脏数据。
- 预览、普通生成、裁切生成和重试都接受同一个不可变 `PhotoFilterSelection` 快照；入队后不再读取当前 UI 状态。
- 成片输出指纹必须包含 LUT 身份、浓度和四个微调值；调整参数后不能复用旧的效果图文件。
- Native、Kotlin、GPU 只能是同一公式的不同执行后端；全部微调为 0 时走中性值快速路径，不增加旧任务的额外开销。
- 锐度、降噪、颗粒、色温、色调和色相继续留在后续阶段，避免第一阶段引入邻域运算或新的色彩空间规则。

## 已参考的实现方向

- GPUImage 将亮度、对比度、饱和度和 LUT 作为独立滤镜，并通过 LUT 强度控制原图与 LUT 结果的混合：[GPUImage](https://github.com/BradLarson/GPUImage)。
- Google Filament 的 `ColorGrading` 将曝光、对比度、饱和度、阴影/高光和 3D LUT 视为同一条颜色分级管线，适合作为参数职责和处理顺序的参考：[Filament ColorGrading](https://github.com/google/filament/blob/main/filament/include/filament/ColorGrading.h)。
- Android LUT builder 项目强调预览 shader 与 CPU 导出使用同一套颜色管线，这一点适合本项目避免“预览正常、导出不同”的问题：[luxbuilder](https://github.com/lovelaced/luxbuilder)。

这些项目只作为算法和管线设计参考，不直接引入依赖，避免增大 APK 和引入许可证、性能及兼容性风险。
