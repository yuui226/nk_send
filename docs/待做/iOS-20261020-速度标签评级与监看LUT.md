## 行为依据与改动

### R01

安卓 `TransferScreen.kt` 的文件大小、速度、耗时行与 `TransferInfoPill`：高 20、横向内边距 7、圆角 6、间隔 5，`animateContentSize` 为 140ms / FastOutSlowIn，缩放和宽度以左端为锚。用户明确要求速度不能出现省略号。

iOS 已有左端锚定与 140ms 宽度动画，但数字受父行提议宽度压缩，测得的是截断后的宽度。真实卡片把 `9.9 MB/s` 改为 `999.9 MB/s` 时，反而由 58pt 缩为 52.33pt。现在仅给速度数字内容保留横向自然尺寸，沿用已有宽度动画；其他信息标签的受限布局不变。截图确认完整显示，向右变宽后可缩回，左端不动。

### R02

安卓 `FileListScreen.kt` 4714–4765 行、`PhotoRatingScan.kt` 49–76 行：加载中的评级开关仍可点击，关闭会清缓存并重置结果；重新开启重新读取。iOS 评级控制器已有取消代次和缓存清理，本轮发现问题在点击入口：`FilterChip` 把进度文字作为单项拨轮的选项身份，每次进度刷新都会替换 `DetentWheel` 的手势身份，按下到松手之间发生刷新即吞掉点击。

现在这个动作按钮保持固定选项身份，显示文字可独立更新。没有新增评级缓存、后台扫描或改变扫描策略。真实按钮每 20ms 更新进度，持续按住 180ms 后松手仍可停止；停止/重开/再次停止均通过。控制器回归覆盖先取得一项结果、第二项在途时停止，立即清空，再开启重新读全部文件；旧请求迟到不写回新一轮结果。

### R03

安卓依据：`RemoteLutPanel.kt`、`LutCategoryList.kt`、`RemoteChoicePopup.kt`、`RemoteScreen.kt` 的工具点击/旋转/隐藏/选目录流程，以及 `lut/LutMonitorState.kt`。此前 iOS 使用系统底部抽屉及分类下拉菜单，不能作为此交互已复刻的证据；本轮补齐此缺口。

- 使用监看工具按钮旁的 `RemoteChoicePopup` 与共享 Genie 展开/收起，透明外部点击层；不新增全屏变暗。沿用展开 320ms / cubic(0.16,0.40,0.22,1)、收起 350ms / cubic(0.30,0.18,0.60,1)，中断按当前进度续接。横竖屏使用同一旋转坐标系，间隔 6、边距 8，横屏空间较多时向上展开。无文件宽 260，有文件宽 320，按可用屏幕范围限制高度。
- 顶部固定“关闭 / 文件夹”，等宽、间隔 8、高至少 32；分类和文件列表按 36:64 分列，间隔 6，各自独立滚动。分类行横 8/纵 10，文件行横 12/纵 8，14pt/20 行高、最多两行；选中分类背景 .14、文件 .08，加载沿用 600ms FastOutSlowIn 的 1↔.5 原生透明度动画。
- 初次定位当前选中分类/文件；切换分类重建右列滚动位置，后台不变目录刷新保留正在浏览的位置。复用现有目录索引及虚拟化列表，预先按受限可视高度计算尺寸，不为大目录逐条测字或先撑满再跳高。
- 选中高亮、加载等待、首个实际 GPU 呈现后提交/持久化并收起、同项直接收起、关闭清除，以及失败保持旧效果，继续使用原监看 LUT 状态机。照片效果与监看 LUT、拍照与录像模式的配置仍独立。
- 选目录时弹窗保留，取消应回到原弹窗；失败使用安卓资源提示。其他监看面板互斥、旋转/管理工具收起，隐藏 LUT 工具关闭当前模式 LUT。iOS 暂不提供端侧录制的已接受差异不变。
