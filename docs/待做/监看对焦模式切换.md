# 监看对焦模式切换

2026-10-01。状态：方案与代码已完成；真机写入权限待用户验证。

## 目标与边界

新增切换 AF-S、AF-C、AF-A、AF-F、MF 的小工具。它改变相机的对焦模式，与“对焦区域”和“对焦框显示”分别独立。拍照、录像、AP、STA、USB 共用协议调用和菜单，不增加后台高频轮询，不切完整 PC 控制模式，不引入第三方库。

当前读数、可选值和写入权限均以相机为准。不将 App 上次选择自动写回相机。工具隐藏仅关闭菜单，不改变机内模式；布局排序与显隐继续使用现有照片／录像各自配置。

## 调查依据

- [尼康 Z30 官方对焦说明](https://onlinemanual.nikonimglib.com/z30/zh-cn/05-01.html)：AF-A 为照片限定，AF-F 为录像限定；微点与动态区域也受对焦模式限制。因此不能硬编码所有模式都显示同一组选项，修改后不能继续使用旧的区域能力缓存。
- [libgphoto2 config.c](https://github.com/gphoto/libgphoto2/blob/master/camlibs/ptp2/config.c)：标准 FocusMode 支持读写，尼康 0x8010～0x8013 分别为 AF-S/C/A/F，1 为 MF；旧 AutofocusMode 与 LiveViewAFFocus 另有独立映射。只是参考协议事实，不复制整库。
- [PTP 属性定义](https://github.com/gphoto/libgphoto2/blob/master/camlibs/ptp2/ptp.h)：FocusMode 0x500A、LiveViewAFFocus 0xD061、AutofocusMode 0xD161。
- 项目已有 rcGetFocusMode、rcGetParam、rcSetValueVerified、RemoteCameraToolPanel：读数、描述符、写后回读、菜单动画可复用。rcGetFocusMode 特意用成功的属性值读取，不能退回失败描述里的默认值冒充 MF。

公开实现证明路线成熟，不证明每个型号、镜头和连接方式都可写。物理 MF 开关、相机忙、拍照／录像切换可能改变权限。不得为了可写绕过相机状态约束。

## 协议与名称

优先 0x500A；不支持时回退 0xD061，再回退 0xD161。优先选择类型可信、明确可写且带枚举选项的属性。标准属性只读时继续检查厂商属性；全部不可写则保留首个可信描述用于不可用判定，不强行写入。UINT16 标准属性与 UINT8 厂商属性分别校验；未知类型不写。

| 属性 | 已知映射 | 注意事项 |
|---|---|---|
| 0x500A | 1 MF；2 AF；3 AF Macro；0x8010 AF-S；0x8011 AF-C；0x8012 AF-A；0x8013 AF-F | 选项只来自当前描述符 |
| 0xD061 | 0 AF-S；1 AF-C；2 AF-F；3 固定 MF；4 可选 MF；5 AF-A | 不把 2 当成 AF-A |
| 0xD161 | 0 AF-S；1 AF-C；2 AF-A | 项目曾观察 3/4 出现在 AF 异常后，继续保留未知编号，不能盲目标为 MF |

按钮短名称统一来源于实际读取结果。未知模式显示中性占位；菜单未知值显示相机选项编号，不编造名称。失败读取不能更新成猜测的 MF。没有强制照片／录像静态白名单，避免误删新机型真实支持项。

## 交互

- 工具名称“对焦模式”，按钮显示实际短值，例如 AF-S、AF-C、MF。未知时显示 MODE；与表示显示开关的 AF 工具区分。
- 点击打开既有 RemoteChoicePopup，宽度按内容自适应，选项简短单列，当前项亮起，无额外说明段落。
- 首次读取期间按钮转圈，拿到内容后再播通用展开动画。选择期间当前目标项呼吸，成功回读后收起；失败留在菜单并提示。
- 复用现有横竖屏锚点和上下空间判断，不另起全屏页。不为新工具另造菜单动画。
- 关闭菜单不会撤销已经发出的相机设置；写入及结果收尾受控完成，不把成功只理解为响应码 OK。

## 切换事务与状态联动

1. 点击选择后同步标记设置忙。半按、点按、拍照和开始／停止录像不能在设置事务中插入；正在进行的 AF 或快门事务也不能被设置打断。
2. 获取相机身份和模式快照；写前重新核对物理照片／录像拨杆，描述符、可写性、目标值仍存在。
3. 若 App 启动过主体追踪，先正常结束追踪；结束失败则不写模式。清除本地旧追踪标记，不能保留假成功框。
4. 通过既有有界忙重试、写后回读确认目标值；不设置无限重试、额外轮询或重启 Live View。
5. 不论成功或拒绝，只要事务尝试写过且仍为同一相机／模式，都刷新实际模式和 MF 判定；避免失败时相机实际已变而 UI 仍保留旧值。成功再收起。
6. 清理旧点按反馈与合焦状态、使旧帧框失效；新帧恢复实际框。对焦区域菜单每次打开重新读取，不常驻缓存旧能力。
7. 拨杆切换或换相机使旧菜单失效，旧完成回调不能污染新会话。录像中可否修改由实时能力决定，录像开始／停止事务期间不允许修改。

## 性能与维护

首次菜单读取与写入沿用通用路径；菜单关闭不增加取值。现有对焦模式事件刷新和读数复用，工具本身只显示已有状态。标准属性成功则不额外读两个厂商属性。不对每帧解析模式，不影响 LUT／波形图或传输生成流程。

共同的相机菜单保留原有白平衡与区域的读写内容；白平衡、区域与模式共享一个写入忙状态，防止快速换菜单后交错写入。实现后检查所有枚举分支、图标、三种语言资源与工具显隐入口。

### 整体复查（2026-10-01）

发现并修正：原来只有对焦模式设置占用忙状态，先写区域再切换模式仍可能交错。现将三个相机工具菜单统一互斥；菜单切换不取消已经发送的写入，但新菜单不能重复提交。发送前显式检查协程取消，避免已关闭菜单继续发出尚未发送的设置。没有新增定时查询或后台任务。

### 实机反馈修正

模式按钮固定 36dp 占位，避免文字切换加载指示造成工具栏重新分列。修正遇到标准只读属性就提前结束能力检查的问题，继续查找厂商明确可写的描述符；具体相机的权限仍以实机响应为准。

对焦模式工具每次打开自动记录简短诊断：版本、机型、连接方式、照片／录像状态、三个候选属性的响应与类型、最终选中属性及可选值、写入和回读结果。日志窗直接显示并复制本次报告，保留最近 80 行；不再运行此前的对焦点定时采样。退出监看保存最近报告，复制不再额外截短。

实机反馈：AF-A 显示为“相机选项 5”，补充 LiveViewAFFocus（0xD061）的 5→AF-A 名称；其他属性的 5 不套用此映射。菜单与当前模式文字共用映射，不修改写入值或权限。
