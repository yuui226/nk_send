# 监看 LUT：文件夹与选择菜单

日期：2026-09-28
状态：实现中；解析器已通过针对性单元测试，GPU 与菜单已初步接入，状态审查、设备验证尚未完成。本文记录交互与实现边界，不代表功能已完成，也不代表渲染路线已验证。

## 目标

用户指定一个 LUT 文件夹，Z传自动列出其中可用的 `.cube` 文件，选择后应用到实时监看。文件由用户自己管理；重装 App 后只需重新选择原文件夹，无需逐个导入。

## 已确认交互

- [ ] **01 工具入口**：监看工具栏增加 LUT 按钮，接入现有排序、显隐和配置机制。启用 LUT 时按钮亮起。点击工具按钮只打开选择列表，与白平衡一致；不直接切换 LUT 开关，不设置长按关闭或独立关闭按钮。隐藏工具按既有规则关闭效果。
- [ ] **02 通用菜单**：复用白平衡等选择菜单的公共呼出／收回动画、主题和定位规则。宽度随内容自适应，同时受可用屏幕宽度约束；长文件名省略，不能撑出屏幕。选项太多时允许纵向滚动。不增加独立设置页面或重复确认步骤。
- [ ] **03 未设置文件夹**：菜单仅显示简短引导和“选择文件夹”。建议文案：**“选择存放 .cube 文件的文件夹”**。下方显示辅助说明：**“仅影响监看，不改变相机原片”**。
- [ ] **04 文件夹为空／无匹配文件**：菜单仅显示 **“未找到 .cube 文件”** 和 **“更换文件夹”** 按钮。不增加“重新扫描”按钮；重新打开菜单自动刷新。
- [ ] **05 非空菜单**：依次显示“关闭”、LUT 文件列表，最后显示低频操作“更换文件夹”。当前选项亮起，不增加对号或管理按钮；沿用现有选择菜单视觉规范。
- [ ] **06 即选即用**：点击 LUT 后加载并应用，成功后收起菜单；用户要关闭效果时，先点击 LUT 工具按钮打开列表，再选择第一项“关闭”，恢复未套 LUT 的画面并收起菜单。关闭菜单本身不关闭 LUT。首次选择文件夹后不自动应用第一项，由用户选择。
- [ ] **07 文件命名**：显示文件名，隐藏 `.cube` 后缀，按文件名稳定排序。用户通过文件管理器添加、删除、重命名文件；App 不提供单文件导入、重命名、删除界面。
- [ ] **08 简短引导**：避免大段教程。**“仅影响监看，不改变相机原片”仅在未设置文件夹时显示**；已设置但为空／无匹配文件、正常 LUT 列表均不显示该说明。未设置时按钮为“选择文件夹”；已设置但为空时仅显示“未找到 .cube 文件”和“更换文件夹”按钮。

非空菜单示意（名称仅为示例，不代表提供内置 LUT）：

```text
关闭
人像暖调
胶片风格
N-Log 转换
──────────
更换文件夹
```

## 文件夹、加载与恢复

- [ ] **09 授权与持久化**：使用系统文件夹选择器并保存可持久化读取授权，拍照和录像共用文件夹，但分别记住所选 LUT 和关闭状态；切换模式按对应配置恢复，并遵守 LUT 与伪色互斥规则。普通重启无需重选；重装后需重新授权，重新扫描即可恢复列表，不承诺恢复卸载前的选中项。
- [ ] **10 扫描范围**：只扫描所选文件夹的直接子文件，扩展名 `.cube` 不区分大小写，不递归子文件夹。
- [ ] **11 刷新时机**：选定文件夹或每次打开 LUT 菜单时异步刷新；已有列表可先显示，禁止在监看热路径持续扫描。扫描阶段只读取文件信息，不解析全部 LUT。
- [ ] **12 按需解析**：选择具体文件后才读取、校验和解析。明确区分“没有匹配文件”和“有文件但格式不支持／内容损坏”。不支持时简短提示，保留此前效果。首次失败则保持关闭。
- [ ] **13 取消与权限失效**：取消系统选择器保留原配置和效果；新文件夹的读取授权取得且首次枚举成功（允许为空）后才提交目录变更，关闭旧 LUT，清除两个模式对旧目录的选择，展示新列表让用户重新选择，不按同名文件自动匹配。Provider 返回明确的不存在结果时提示“文件夹不存在”，权限失效时提示“无法访问文件夹”，均提供“选择文件夹”并关闭依赖该目录的效果。不影响监看连接。
- [ ] **14 文件变化**：仅当扫描成功且确认当前文件已删除时，关闭效果并简短提示；临时扫描失败显示“读取文件夹失败”，保留原配置和已有可用效果，不当作空文件夹或删除，不清空列表。成功扫描但无匹配文件则显示“未找到 .cube 文件”＋“更换文件夹”。同名文件内容改变时不能长期复用旧解析结果。缓存按文件标识及可用的修改信息校验。
- [ ] **15 并发与生命周期**：快速换 LUT、关闭、换目录、离开监看后，过期加载结果不能重新启用效果。LUT 加载或临时扫描失败不能清空已有可用配置；更换目录成功则按第 13 条清除旧目录选择。
- [ ] **16 加载反馈**：点击选项后菜单保持打开，该选项以轻微呼吸效果表示加载；成功应用后收起，失败则保留菜单和此前效果并简短提示。等待期间仍可选择“关闭”或另一项，旧请求结果不得覆盖新选择。不让加载占位弹窗吞掉公共呼出动画，不增加“确认应用”操作。长时间文件读取不得阻塞主线程或取景帧处理。

## 画面处理边界

- [ ] **17 仅监看**：不修改相机参数、机内照片／视频，不改变传输、裁切及照片效果生成链路；端侧录制默认不写入 LUT。
- [ ] **18 曝光辅助**：直方图、波形图、斑马纹继续分析套 LUT 前的监看输入。此输入不等于传感器原始数据。**LUT 与伪色直接互斥，后开启者关闭前一个**：LUT 成功应用时关闭伪色；开启伪色时关闭 LUT，并取消尚未完成的 LUT 加载。关闭任一功能都不自动恢复另一个。LUT 加载失败不关闭正在使用的伪色。互斥后的关闭状态写入对应配置，避免重进页面或异步加载完成后重新叠加。此互斥不影响直方图、波形图和斑马纹。
- [ ] **19 第一版范围**：文件夹选择、列表、应用、关闭即可。不加浓度滑杆、LUT 专用曝光调整、混合模式或自动套用 N-Log 转换。
- [ ] **20 性能**：禁止逐帧重新解析 LUT，避免逐帧大对象分配；采用适合现有渲染链路的颜色处理方式。关闭时不产生额外逐帧计算，缓存有明确容量和释放规则。

## 实现前需要验证的事项

- [ ] **21 输入色彩性质**：Z传接收的是相机 Live View JPEG，不等于未经转换的 N-Log。验证目标机型的拍照／录像模式及机内视图辅助是否改变输入；不能因用户使用 N-Log 录制就自动套用转换 LUT。
- [ ] **22 文件格式支持范围**：`.cube` 是候选文件类型，不表示所有变体都支持。实现时明确 1D／3D、网格尺寸、输入域及容量限制；不支持的变体明确报错，不静默错误解析。
- [ ] **23 验收**：覆盖空目录、取消选择、授权失效、重启恢复、删除／覆盖文件、损坏文件、快速切换、横竖布局、长文件名、多选项滚动、曝光辅助和端侧录制隔离。核对帧率、延迟与内存开销。

## 最终技术实施方案（2026-09-28 调研补充，待实现验证）

### 24 技术选型

采用 **Kotlin 有界流式解析 + OpenGL ES GPU 查表 + 独立监看图像层**。不引入整套 GPUImage、Media3 或新的 C/C++ 滤镜库。不为此增加 APK 的原生架构库，不提供 CPU 逐像素实时回退。

第一版优先使用 OpenGL ES 3.0 的 3D LUT 纹理，维护一套颜色处理实现。运行时验证 EGL 上下文、纹理尺寸、格式与采样能力；Android 系统版本足够不代表 GPU 必然满足要求。不要通过强制 Manifest 硬件要求限制整个 App 安装。无法支持时仅拒绝启用 LUT，提示“此设备暂不支持 LUT 监看”，原监看及其他功能继续工作。

此处是技术实施选择，不等于已测得全机型兼容。若实际设备覆盖不够，再独立评估 GLES 2.0 图集方案；第一版不支持的设备范围必须在交付时明确，不能宣传为所有 Android 8+ 设备均支持 LUT。不能在未经验证时静默降低颜色精度。AGSL 从 API 33 起可用，暂不维护第二套实现。

### 25 文件解析与支持范围

第一版支持独立 3D `.cube`：整数网格边长 2–65，重点验证 17、33、65。支持注释、空白行、BOM、TITLE、LUT_3D_SIZE、DOMAIN_MIN／DOMAIN_MAX；无显式 DOMAIN 时使用标准默认范围。按格式规定的 R 最快变化次序组织颜色，不能混用参考库自有数组排列。

明确拒绝 1D、1D+3D 组合、暂不支持的范围扩展指令，以及无法正确解释的关键指令。DOMAIN 还需可由 GPU 正常 Float32 运算可靠表达；拒绝非零次正规端点、次正规差值或倒数，避免驱动 flush-to-zero 后映射出错。不得悄悄忽略它们后返回错误颜色。

- 先校验网格，再分配连续 FloatArray；不使用三层对象数组。
- 预期数据行数严格等于 N³，每行三个有限浮点数；拒绝重复冲突头、数据缺失／多余、NaN、Infinity、非法 DOMAIN 和整数溢出。
- 流式读取，初始限制为文件最多 32 MiB、单行最多 8 KiB；读取时实际计数，不能只相信 Provider 的文件大小。达到限制立即中止并提示，不把全文一次性读进内存。
- 允许合理的负输出和大于 1 的输出，不能在解析阶段一概裁掉；超过所选 GPU 数值格式可表达范围则明确拒绝。输入和输出最终处理见第 27 条。
- 上述尺寸与文件限制为第一版工程边界，后续调整必须补对应测试。

### 26 选择与原子切换

1. 在 IO 线程打开文档流，在后台解析与校验。待加载项显示轻微呼吸，当前有效效果和已选项高亮继续保留；加载项不能提前冒充当前已应用项。
2. 将解析结果交给唯一 GL 线程，创建候选 LUT 纹理，完成着色器与纹理有效性检查。
3. 对比目录、拍照／录像模式、选择请求和页面会话的 generation；过期结果释放，不更新配置或画面。
4. 候选资源就绪后准备首帧。将候选请求号带到 UI，UI 再次确认该请求仍有效后，在同一状态更新中切换有效 LUT、关闭伪色、保存当前选择并收起菜单；GL 发布结果前也检查请求号。须等 TextureView 对应候选帧已就绪再隐藏旧图层，不能仅凭上传完成／调用 swapBuffers 就宣告屏幕已切换。解析成功本身不算应用成功。
5. 失败释放候选资源，保留旧效果与旧选择；关闭操作和开启伪色均取消待处理请求，后到结果不能复活 LUT。

更换文件夹遵循第 13 条：新目录成功选定后关闭旧效果，不能用第 26 条的“保留旧效果”跨目录继续展示。

### 27 色彩与精度

监看输入是当前解码后的 Live View JPEG 像素，不读取相机视频原片，不把 LUT 当作自动识别 N-Log 的机制。第一版按 SDR 监看颜色映射定义实现，不承诺 HDR／专业校色监视器一致性。

- 使用 RGBA16F LUT 纹理保存半精度浮点表项，保持 CPU 解析数据为 Float32；不把 LUT 无条件量化为 8 位 PNG。65³ RGBA16F 的有效表数据约 2.10 MiB，不含驱动开销。
- 正确映射输入 DOMAIN，超出定义域的输入采用边界钳制；纹理采样位置对齐节点中心，避免半纹素偏移。GL_CLAMP_TO_EDGE，不生成 mipmap。
- 使用三线性插值。不要宣称与使用四面体插值的后期软件逐像素一致。
- 颜色表作为数据纹理处理，不自动施加 sRGB 解码。监看源的颜色空间、上传纹理及输出 surface 约定必须一致；禁止盲目加入 gamma 转换或重复线性化。恒等 LUT 必须与原链路对照验证。
- LUT 浮点输出在 SDR 显示输出端处理超范围值，不在读取文件时损失原始表数据。无法识别的输入色彩状态不伪装成精确 Log 还原。

### 28 图像显示层接入

现有链路：相机 JPEG → Bitmap 解码 → RemoteLiveFrame → Compose Image。只替换其中的图像显示部分，不重写相机取帧、解码、曝光分析或录制流程。

建议用 AndroidView 承载 TextureView，由单独 EGL／GL 线程绘制，便于复用现有 Compose 层级、裁剪和淡入淡出。TextureView 本身有额外合成成本，不把它当作零开销；必须通过第 33 条的性能验证。不要先改成会影响叠加与遮挡关系的独立 SurfaceView。

- 参考线、对焦框、水平仪、DISP、音频电平、曝光分析层保持在图像层上方，不被 LUT 染色。
- 复用当前画面矩形、旋转、反挤压、缩放和拖动坐标，不能再计算一套不一致的 fitCenter；点按对焦坐标不变。
- LUT 未启用时走现有 Compose 显示，无 LUT GL 持续绘制线程和额外帧上传。
- 启用时保留原画面直到候选输出就绪，避免黑闪；仅过渡阶段允许双层绘制，稳定后不在底下永久重复画原图。
- 暂时失去 surface／GL context 时保留有效选择并有限次重建；持续失败提示并关闭效果，恢复原画面，禁止无限重试。

### 29 热路径与帧所有权

- 不重复 JPEG 解码，不每帧读取或解析 LUT，不每帧生成新的着色器。
- LUT 每次选择只上传一次，画面纹理按尺寸分配后更新；尺寸变化才重新分配。
- 新渲染器最多保留一个正在上传的帧和一个待处理最新帧，后来的帧覆盖待处理帧。不为每一帧向 Handler 无限排队。
- 没有新帧、LUT 或显示变换时不主动持续绘制；不强制凑 60 帧，不积压旧画面制造延迟。
- 生产监看路径不执行 glReadPixels、GPU 转 Bitmap 或重新 JPEG 编码（离线 GPU 验证测试允许回读结果）。原有 JPEG 解码和纹理上传仍有成本，不宣称零拷贝。
- 显式约定 Bitmap 所有权：借用的帧在上传完成前不能被回收或复用；丢弃引用不等于直接 recycle。必须核对现有预览和录制消费者，不能误释放共享帧。
- GL 对象在所属线程创建和销毁，UI 线程不等待 fence、磁盘读取或 GL 完成；退出页面、后台暂停与断线均取消无效请求和待处理帧。

### 30 缓存与文件变化

只保留当前有效 LUT 和至多一个切换中的候选 LUT，不缓存整个文件夹的解析结果或缩略图。候选解析、纹理准备串行化；快速选择只替换待处理请求，取消并释放旧候选后再分配新候选，不能为每次点击创建并行的大数组和纹理。第一版无需持久化编译后的 GPU 资源。

目录 URI、文档 ID、大小与修改信息用于识别候选文件；这些信息可能缺失或不可靠。每次用户选择或重新进入监看恢复效果都重新读取所选文件；同一活跃页面因旋转／surface 重建而恢复时复用已解析的有效表，不重新读盘。文件读取时并在流式读取中计算内容摘要；菜单扫描只读元数据，不能为了判断变化把全目录文件读一遍。

已启用文件在扫描中确认发生变化时，重新加载候选，成功后替换；读取失败时不误判删除。未报告可靠修改信息的 Provider，不承诺文件变化能立即被发现；用户重新选择该项必须可强制重读。同一项不能简单因“已选中”而永远跳过文件读取。

### 31 其他功能隔离

曝光分析继续使用原始监看 Bitmap。端侧录制继续使用原录制输入，不从 LUT surface 抓取画面；普通 JPG／RAW／视频传输、照片效果、无损裁切全部不受影响。

切换拍照／录像时取消旧模式加载，再恢复新模式选择；必须统一执行 LUT 与伪色互斥状态更新，不能只在按钮点击回调里互斥。隐藏工具、恢复配置、重新连接同样经过这一个入口。

### 33 验证与性能门槛

先做最小垂直验证：一张确定颜色的测试图＋恒等 LUT＋一个非平凡 LUT，验证 GPU 输出正确，再接实时帧与菜单。

- 解析：不同尺寸、通道顺序、非默认 DOMAIN、科学计数法、注释／BOM、非法数值、文件截断、超大文件、1D／组合格式明确拒绝。
- 颜色：恒等映射、红蓝交换、灰阶渐变、边界颜色，与独立 Float32 CPU 三线性参考实现对照；CPU 参考只用于测试，不进生产逐帧路径。建议目标恒等图每通道误差不超过 1 个 8 位码值，普通参考样例不超过 2，超标必须定位而不是放宽到肉眼看不出来。
- 绘制：横竖布局、沉浸全屏、反挤压、缩放拖动、点按对焦、参考线与分析层不染色、快速切换、黑屏恢复与前后台切换。
- 录制：开启 LUT 前后端侧录制仍保留原始监看颜色；伪色互斥、拍照录像分别记忆、加载失败保持旧效果。
- 性能：同设备、同画面分辨率与同相机帧率比较关闭／开启 LUT；记录帧间隔、显示帧龄、GL 上传及绘制耗时、内存、温升和安装包差异。持续监看至少 10 分钟，多次进出／切换检查泄漏。
- 初始验收目标：渲染端无持续排队，额外处理的 P95 耗时在一帧预算内，稳定输出帧率下降不超过 10%，内存随操作不持续增长。它们是待实测目标，不是已经保证的性能。
- 至少覆盖一台性能较弱设备、一台主流设备及用户关心的华为兼容环境；不能用桌面解析测试代替设备渲染验证。真机测试安排由用户协调，不自动启动模拟器。

## 闭环审查补充（2026-09-28）

### 35 状态与互斥的唯一规则

分别维护持久化的“用户配置”、运行时的“有效效果”和“待处理请求”，不以一个 enabled 布尔量兼任三者。渲染资源不能持久化。

| 事件 | 立即处理 | 最终状态 |
|---|---|---|
| 首次选 LUT／替换 LUT | 待选项呼吸，保留当前效果 | 首帧就绪且请求仍有效后才提交新选择 |
| 手动点列表“关闭” | 使待处理请求失效，显示原画面 | 当前拍照／录像模式配置记为关闭，释放 LUT GPU 资源 |
| 开启伪色 | 使 LUT 待处理请求失效 | 当前模式 LUT 关闭并保存，伪色开启 |
| LUT 加载失败 | 清理候选，提示一次 | 保留已有有效 LUT 或伪色，不保存失败选择 |
| 加载时收起菜单 | 取消这次尚未提交的用户选择 | 保留此前效果；不同于已启用后收起菜单，后者不关闭效果 |
| 切换拍照／录像 | 取消旧模式请求，移除旧模式 LUT | 恢复目标模式配置；失败则显示原画面并提示，不保留错误模式的 LUT |
| 监看暂停、断线、退出页面 | 使页面请求失效，清理待处理帧与 GL 资源 | 保留用户选择；下一次有效会话按配置恢复 |
| 持续 GPU 故障 | 停止重试、提示一次、恢复原画面 | 本次页面会话禁用失败效果；保留文件选择供用户重试，不能无限自动恢复 |

现有 `remote_exposure_assist`（伪色／斑马纹）是全局状态，本次不顺带改成两套配置。规则如下：

- 用户开启伪色只关闭当前模式 LUT，不抹掉另一模式保存的 LUT。
- 切换模式时，若目标模式保存了启用的 LUT，成功恢复后关闭全局伪色；若目标模式 LUT 关闭则保留现有伪色状态。恢复中不展示上一模式的 LUT。
- 恢复失败不能为了“将要开启 LUT”而提前关闭伪色。
- 隐藏当前模式的 LUT 工具，关闭该模式效果并保存；恢复工具可见性不自动开启。不能因另一模式的布局里隐藏该工具，误关当前模式的效果。
- LUT 与伪色所有入口共用状态协调器；斑马纹不受 LUT 开关影响。

### 36 文件夹操作的完整事务

- 打开系统选择器时先取消待提交的 LUT 选择；已生效配置保留。系统选择器可能使 Activity 暂停或重建，结果由可恢复的 Activity Result 处理接收，不能依赖仍存活的弹窗对象。
- 目录只有在可持久化读取授权取得且枚举完成后才算更换成功。枚举成功且为空是有效新目录，进入空状态；取消、授权失败、枚举失败均保留旧目录和配置。
- 成功替换后释放不再使用的旧 URI 授权；重选相同 URI 不重复释放当前有效授权。仅请求读取权限，不移动、删除或修改用户文件。
- 从系统选择器返回后，页面仍为有效监看会话时自动展示新列表／空提示；若已离开监看，只保存结果，不强行弹出页面或启用效果。
- 不将 `exists()==false`、查询异常或超时一律解释为目录被删除。只有确切证据使用“文件夹不存在”；不能区分原因时统一显示“无法访问文件夹”。
- 扫描异常且旧效果仍有效时，保留旧列表中的第一项“关闭”，使用户始终能够关闭效果；其余读取失败信息保持简短，提供更换文件夹入口。
- 全部 `.cube` 文件都不支持时仍是非空列表：用户选中时说明不支持，不能显示“未找到 .cube 文件”。
- 重名或大小写不同的文件以文档 ID 区分，排序增加稳定次关键字，不以去后缀显示名作为身份。视觉重名时补简短区分，不修改磁盘文件。

### 37 无帧、超时和取消

- 未连接或尚无有效监看帧时允许扫描／选目录，但不无限等待“首帧成功”。选 LUT 时简短提示“监看画面就绪后再试”，保留先前配置。
- 候选加载在用户等待超过 10 秒时结束等待并提示“读取 LUT 超时”，恢复原有效选项。查询枚举也采用有界等待，不把超时结果当成空列表。
- 协程超时不保证中止 Provider 的阻塞读取。能使用 CancellationSignal 的查询传入取消信号，文件流在结束时关闭；迟到结果凭请求号丢弃。读取任务限定并发为 1，不因重试无限开线程。若旧读取仍阻塞，不再启动第二个读取，保持菜单可关闭并提示稍后重试。
- 32 MiB／8 KiB 限制必须在分配前、读取过程中执行，不能先用无界 readLine/readText 分配后再校验。解析循环定期检查取消，枚举失败或取消不可触发删除判断。
- 初始目录规模保护为最多检查 10,000 个直接子项；超过时提示“文件夹文件过多，请选择专用文件夹”，不将截断结果当作完整清单。该数值是工程限额，调整需有对应大目录测试。

### 38 渲染资源与错误恢复补全

- 当前 LUT 的解析数组保留用于同页面 context 重建；候选首帧提交后释放旧表和旧纹理。不长期同时保留 Float32、半精度上传缓冲、Bitmap 三套 LUT 表。
- 统计实际峰值预算：当前／候选 Float32 RGB 表、RGBA16F 纹理、上传缓冲、最多两张新增持有帧，以及 EGL 缓冲和驱动内存。2.10 MiB 只是单张 65³ LUT 纹理数据，不能宣传为功能全部内存占用。
- 纹理输入输出行方向、Bitmap stride、alpha 和预乘规则均须验证；LUT alpha 固定为 1，不能意外改变监看透明度。
- 页面已销毁时，GL 完成回调不得触碰 Compose 状态；正常资源释放在 GL 线程执行，context 已丢失则按 EGL 生命周期放弃失效句柄，不能在新 context 中删除复用的旧编号。
- surface 正常重建不计为错误；实际 GL 故障每次有效页面会话最多自动重建一次，再失败回到原画面，等待用户显式重试。不得把驱动超时等临时故障一概提示为“设备不支持”。
- 恢复原画面要覆盖真实的首帧与图层交接，不能仅设 enabled=false 留下黑色 TextureView 遮挡；隐藏图层也必须停止提交帧。
