# 全局触感反馈梳理与优化方案

2026-09-26。调查基于提交 88473510；本文为设计建议，尚未实施批量修改。

## 现有基础与明确发现

- ui/util/Haptics.kt 集中提供 tick、longPress、success、failure 和 GPS 长按蓄力。普通反馈使用 Android 系统常量；自定义蓄力直接使用 Vibrator。
- 当前 tick 同时用于开关、拨轮、入队、开始操作等不同语义，尚无应用层频率控制。
- HomeScreen：STA 连接点击已补 tick；连接结果已有成功/失败反馈。
- FileListScreen / PhotoPreview：预览、入队、裁切操作已有反馈，整组入队一次，队列实际完成一次，跳过/取消不庆祝。
- RemoteScreen：参数变更、半按/点按对焦、拍照、相机录像、端侧录像保存已有不同程度反馈。TopIconToggle / GlassButton 本身不统一添加震动；工具栏切换、相机选择菜单、参考线选择、工具编辑未建立完整反馈规则。
- SettingsScreen / ReleaseCommitWheel：大量参数、布尔设置按档位触发 tick；照片效果与本地效果共用控件。触感开关自身目前使用 hapticsEnabled || isHapticsPreference，关闭时操作该开关仍有反馈，这是特例，需要明确产品规则。
- GPS 长按 800ms 使用十段逐渐增强的脉冲并在确认时补重点击。未检查幅度控制能力；没有显式触摸用途属性。不能仅凭普通 performHapticFeedback 的行为，声称这条直接 Vibrator 路径也完全遵循系统触摸震动设置。
- 缩略图 combinedClickable 没有显式关闭内建长按触感，同时 onPreview 会触发 longPress。应核对实际 Compose 版本默认行为，排除重复震动和绕过 App 开关；这是待核实风险，不是已经测到的双震。
- Android 旧版 failure 的第二次 tick 延迟65ms，回调只检查 View 是否挂载，不重新检查最新 App 开关。自定义蓄力取消受旧 enabled 实例影响，也需要生命周期清理。
- FireworksOverlay 按每个烟花爆点 tick，属于装饰性触感，应降低优先级并避免与业务成功重复。

## 场景清单

| 场景 | 当前情况 | 建议 |
|---|---|---|
| STA 点击连接、AP/USB手动重试 | STA已加，入口不完全统一 | 接受用户操作时轻点一次；自动发现不震 |
| 连接成功/失败 | 已有结果反馈 | 每次连接尝试只一次；轮询/重进页面不重播 |
| 设置、筛选、帮助气泡、白平衡/对焦区域/参考线开窗 | 不统一 | 用户点击按钮打开轻点一次；点击外部、返回关闭通常静默 |
| 菜单选择 | 监看三个选择窗缺少统一触感 | 选择不同值轻点一次；点击已选项关闭不重复震 |
| 快门/光圈/ISO/曝光补偿拨轮 | 已有tick | 有效跨档细刻度；合并高速跨多档；边界不重复震；网络确认不再逐档震 |
| 自动ISO、照片效果、滤镜/边框/水印等开关与档位 | 大量已有tick | 成功接受变化轻点一次，同值/恢复配置不震 |
| 数值滑动与连续调整 | 依控件回调 | 离散刻度、关键吸附点才震；不按每个像素/动画帧震 |
| 监看工具开关、DISP、旋转/全屏/锁定 | 不完整 | 有效切换一次轻点，动画开始/结束不额外震 |
| 工具拖动排序、隐藏/恢复 | 未形成规则 | 拿起一次，实际越过槽位轻刻度，放下仅在位置改变时确认；移动过程不连续震 |
| 点按/半按对焦 | 已有开始及部分后续tick | 区分按下与成功锁定，失败仅明确用户操作一次；持续AF追踪变化静默 |
| 拍照、机内录像开始/停止 | 已有tick/longPress | 接受动作与相机确认避免紧邻叠加；反馈不能冒充相机实际成功 |
| 端侧录制开始/暂停/继续/停止/保存 | 保存已有success | 控制动作轻点，保存成功一次确认；离开页面自动收尾不当作新的用户操作震动 |
| 长按预览、点击预览手势互换 | 共用预览回调longPress | 长按使用拿起感，普通点击不能因为共用回调也变成长按震感；清除组件默认重复来源 |
| 单张/整组/上滑加入队列 | 已有，整组一次 | 真正入队时一次；手势阈值提示与成功反馈去重；拒绝/撤销不播成功 |
| 裁切入口/比例/确认入队 | 已有tick | 比例变化轻点，确认以成功入队为准；缩放、移动、拖角不持续震 |
| 队列开始/暂停、重试、清空、单项取消 | 开始/暂停已有，其余需统一 | 执行动作一次，打开确认卡不播放成功；失败用短拒绝感 |
| 传输/生成完成 | 队列胶囊已有过滤 | 保留整批一次，不逐文件震；实时传输连续小批完成需合并；取消/全部跳过不庆祝 |
| GPS开关、长按关闭/重置、坐标查询/复制 | 有开关与蓄力 | 保留有意义反馈，提前松手立即停止，退出页面/关闭触感开关也停止；后台GPS刷新静默 |
| 激活、续费、购买结果 | 没有统一接入Haptics | 真正成功才确认一次，不按轮询震；失败仅面向当前用户操作 |
| 烟花等装饰 | 每个爆点tick | 降低频率，不叠加业务成功，不抢占操作触感 |
| 普通滚动、图片翻页、缩放拖动、菜单动画、后台预取/轮询 | 应保持安静 | 不补震动；无需给每个可点击控件都加入反馈 |

## 统一设计建议

1. 细刻度：拨轮、拖动换槽、离散吸附。强度最低；以状态变化触发，限制密集连续事件，不补发积压震动。
2. 轻点击：开关、菜单选择、开始动作、有效入队。短促一次；同值/禁用/重复点击无反馈。
3. 拿起/确认长按：进入预览、开始拖动等明确手势成立的瞬间，不在按下和松开重复播放。
4. 成功：连接完成、实际保存、整批完成。较明确但仍短促；与刚发生的轻点击适当合并。
5. 失败：明确失败时一次短拒绝反馈，自动重试、轮询失败不刷震动。

优先使用设备调校的系统触感，不用固定高幅度波形来模拟所有手机；硬件不支持细腻反馈时回退为更简单、克制的效果。遵循 App 触感开关与系统触摸反馈偏好。主线程只提交反馈，不进行等待。

默认保留开关自身“开启时立即体验一次”的能力；建议关闭后静默，关闭状态滑动经过开关不连续预演。此产品规则需确认后再实施。

## 实施顺序

- 第一批：开关覆盖与生命周期取消、默认长按重复风险、旧版延迟回调、无幅度控制设备蓄力回退。
- 第二批：菜单/小工具/拖动排序/队列操作的缺口，区分点击与长按预览，清除同次操作重复来源。
- 第三批：拨轮刻度限频、连续自动传输结果合并、低优先级装饰反馈。
- 最后在不同马达设备上校准。代码检查能保证时机和次数，不能保证所有手机同样细腻。
