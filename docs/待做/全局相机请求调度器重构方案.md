# 全局相机请求调度器重构方案

## 目标

将当前分散在 `CameraIoGate`、`NikonCamera` 各个读取函数和页面状态中的相机让路逻辑，整理为一个统一的事务调度器。

目标不是改变原有产品优先级，而是让每一次相机请求都明确声明类型、优先级、取消规则和诊断信息，避免评级、缩略图、传输和监看之间互相套锁、重复判断或形成自我等待。

星级读取也必须接入同一调度器。评级扫描只决定文件范围和解析结果，不再自己决定相机通道何时可用。

## 当前基线

当前代码已有 `CameraIoGate`，但它是“互斥锁 + 交互等待计数 + 传输切片”的组合：

- `withInteractive` / `withInteractiveTagged`：交互命令取得通道。
- `withInteractivePriority`：登记交互优先等待者，影响传输切片是否能够进入。
- `withTransferSlice`：传输、缩略图和部分后台读取使用，每次事务结束释放。
- `withDownloadActivity`：标记完整下载活动，供心跳和低优先级检查跳过。
- `withIdleCommand`：没有完整下载时才执行普通命令。
- `ioMutex`：仍被部分旧入口直接使用。

当前风险：

- 请求类型没有统一枚举，优先级由调用方隐式决定。
- 一个外层优先级预约包住整段业务时，内部再次申请通道可能自我等待。
- 直接使用 `ioMutex` 的旧入口可能绕过让路规则。
- 评级、视频评级、缩略图和传输对“一个事务”的边界定义不一致。
- 取消、断线和残留 PTP 响应的处理分散在各个函数。

### 当前评级实现的事实边界

当前代码还没有统一调度器。评级扫描外层通过 `withPhotoRatingPriority` 登记交互优先等待者；每次 JPG/NEF、视频或对象读取内部再调用 `withInteractiveTagged("RATING")`。因此当前实现仍是 `CameraIoGate` 的旧语义，不能描述成“每个评级事务已经由全局队列独立调度”。前一次把评级读取改成普通传输切片的临时实验已经回滚，当前工作区没有那项代码变更。

当前 STA 还存在一个边界：`recentThumbnailReady` 主要在已发布批次确认达到三个拍摄日时置位；少于三个实际拍摄日的相机内容，可能要等整批列表结束才满足条件，甚至不会启动评级扫描。这是待修正的现状差异。评级页离开、预览打开或传输进行时的暂停来自页面状态（传输中或预览中），不是监看页面直接持有评级锁。

## 不变的行为契约

调度器重构不能改变这些已经确定的行为：

1. PTP 命令和数据事务不可被中途打断，只能在完整事务之间切换。
2. 当前已经开始的传输分块必须完成，不能为了评级或缩略图强行截断。
3. 监看取帧、拍摄、录像、对焦、参数写入和大图预览优先于后台工作。
4. 可见区域和首屏远程缩略图优先于评级和旧缩略图预加载。
5. 内存、磁盘缓存命中不进入相机调度器，不产生相机请求，也不等待评级。
6. 相机断开时取消等待中的后台请求，正在进行的协议事务按现有异常收尾规则结束；不得把旧连接请求带入新连接。
7. 传输速度、监看帧率和照片生成计时不计入评级读取。
8. 调度器只控制相机通道，不控制本地解码、Compose 绘制、文件复制或照片生成线程。

## 统一请求类型与优先级

所有访问相机的操作必须通过一个事务入口声明 `RequestKind`。建议顺序如下：

| 优先级 | 请求类型 | 典型行为 | 事务边界 |
|---|---|---|---|
| P0 | `INTERACTIVE` | 监看取帧、对焦、拍摄、录像、参数写入、旋转等 | 单条命令或一个不可拆协议步骤 |
| P1 | `PREVIEW` | 当前高清大图、当前 EXIF、FHD | 当前照片的一次完整请求 |
| P2 | `TRANSFER` | 原片传输的一个分块、续传分块 | 一个完整数据分块 |
| P3 | `VISIBLE_THUMBNAIL` | 首屏和可见区域缺失缩略图 | 一张缩略图的一次请求 |
| P4 | `RATING` | JPG/NEF 文件头、MP4 评级结构、AP/USB 对象评级 | 一个文件头或一个评级结构小范围读取 |
| P5 | `BACKGROUND_THUMBNAIL` | 旧照片缩略图预加载 | 一张缩略图的一次请求 |
| P6 | `IDLE` | 心跳、普通事件检查、低优先级能力探测 | 一条独立命令 |

同一优先级内部按先到先执行。高优先级请求只在当前事务完成后取得通道，不能打断当前事务。

评级不是“整段扫描任务”的优先级；每一次文件读取才是一个 `RATING` 事务。评级扫描本身不得持有通道预约。

## 所有需要迁移的行为

### 监看与遥控

- Live View 取帧和增强取帧：`INTERACTIVE`，保持现有帧率让路规则。
- 自动对焦多步命令：每个不可拆步骤为 `INTERACTIVE`，步骤之间允许取帧或更高优先级操作。
- 拍照、开始/停止录像、参数写入、旋转和显示模式：`INTERACTIVE`。
- 曝光尺、剩余录像时长等低频读取：使用 `IDLE` 或专门的低优先级参数请求；拍摄、对焦和录像关键步骤自动让路。

### 大图预览

- 当前大图请求和当前 EXIF：`PREVIEW`。
- 预览打开时暂停整卡照片信息读取和远程缩略图。
- 退出预览时取消未完成的预览请求，已完成的本地结果保留。

### 传输

- 原片下载的每个 PTP 分块：`TRANSFER`。
- 当前分块不可抢占；分块之间允许 P0/P1 请求进入。
- 完整下载活动继续通过独立状态禁止心跳和低优先级目录探测插入。
- 传输速度只统计实际传输事务，不包含评级、预览和本地生成。

### 缩略图

- 内存/磁盘命中：完全绕过调度器。
- 首屏/可见区域远程缩略图：`VISIBLE_THUMBNAIL`。
- 旧照片后台预加载：`BACKGROUND_THUMBNAIL`。
- 每张缩略图请求独立占用一个事务；不能把整批缩略图包进一个长期锁。
- 评级开始前，最近三个拍摄日中仍需访问相机的缩略图完成、失败或确认无图；缓存命中不参与等待。

### 照片列表信息

- 整卡 `ObjectInfo` / 目录批次：低于可见缩略图，高于空闲检查；每批内部保持现有协议事务边界。
- 进入监看或大图时暂停新批次，当前已开始的单条请求自然收尾。
- 连接级列表状态和调度器事务状态分离，不能用页面是否可见直接持有相机锁。

### 星级读取

评级开关关闭时，不创建评级队列，不进入调度器。

开关开启后：

1. 列表按新到旧确定最近三个实际拍摄日。
2. 最近三个拍摄日的远程缩略图阶段完成后启动评级队列。
3. JPG/JPEG、NEF/NRW：读取受限文件头，每个文件头请求是一个 `RATING` 事务。
4. MOV/MP4：使用已经验证的 `moov/udta/NCDT/NCTG` 定位器，只读取定位所需区域；每个区域读取是一个 `RATING` 事务。
5. AP/USB 对象属性读取：每个对象属性命令是一个 `RATING` 事务。
6. JPG 与唯一同名 NEF 的评级投影保持现有规则，不重复读取相同来源。
7. 每个事务完成后立即释放通道；评级扫描不得持有全局优先预约。
8. 监看、拍摄、对焦、大图和传输请求到达时，评级在下一个事务边界让路。
9. 连接断开或页面任务取消时，清理剩余等待项；不自动从头重扫。

评级结果只保存在当前连接的轻量内存代次中。未知、失败、不支持和确认 0 星必须继续区分，未知不能当作 0 星。

## 调度器 API 约束

建议提供单一入口：

```kotlin
suspend fun <T> withCameraTransaction(
    kind: CameraRequestKind,
    owner: String,
    block: suspend () -> T,
): T
```

约束：

- `block` 内不得再次调用 `withCameraTransaction`。
- 调度器自动记录排队、执行、取消、异常和释放时间。
- 取消等待中的请求只移除自己的队列节点。
- 取消执行中的请求必须执行现有 PTP 排空/关闭逻辑，不能直接把通道交给下一个请求。
- `ioMutex` 不再对业务层公开；迁移完成后删除直接使用路径。
- 旧 API 可暂时作为兼容适配层，但内部必须转发到统一入口，不能保留第二套锁逻辑。

## 迁移顺序

1. 为现有 `CameraIoGate` 增加 `RequestKind`、统一事务入口和调度诊断。
2. 先迁移测试覆盖最完整的传输分块、缩略图和监看命令。
3. 迁移大图、EXIF、目录批次和空闲检查。
4. 删除评级的整段优先预约，让照片、视频、对象评级都使用单事务 `RATING`。
5. 删除业务层直接 `ioMutex` 访问。
6. 增加嵌套事务、取消、优先级顺序、断线和传输分块不可抢占测试。
7. 最后再删除旧适配 API，避免一次改动同时改变协议行为和页面状态。

## 必须验证的闭环

- 评级开关关闭时，调度器中没有评级请求。
- 评级开启后，最近三个拍摄日完成锚点后才开始；缓存命中不等待。
- 47/52 场景中，最后的 MP4 评级事务能够完成，不出现外层预约和内层请求互等。
- 监看、拍摄、传输分块到达时，评级只在事务边界让路。
- 评级不会改变缩略图列表顺序、首屏出现时间、传输速度统计或照片生成计时。
- 断线、页面离开、切换连接和重复打开筛选窗不会重复建立扫描或遗留队列节点。
- 诊断日志只记录关键统计：队列等待、当前请求类型、单事务耗时、扫描进度、取消/失败原因和最终结果。
