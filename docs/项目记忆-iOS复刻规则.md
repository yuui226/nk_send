# iOS 复刻项目记忆

这份记录是 `ios` 分支的长期约束，后续实现、审查和验收都必须遵守。每次开始或恢复 iOS 工作时先阅读本文及当前任务记录；切换任务、交给子 agent 或上下文恢复时仍须遵守。具体任务进度见 [iOS 原生复刻计划与任务清单](技术调研/iOS原生复刻计划与任务清单.md)。

## 不可变原则

1. 安卓端是唯一事实来源。实现前必须阅读对应安卓页面、ViewModel、状态 reducer、协议和测试；不能凭经验臆造。
2. iOS 必须复刻安卓的所有用户可观察结果：页面结构、元素位置、显隐条件、文本、字号、操作、手势、动画触发/中断/恢复、逻辑、判断、状态流转、错误、取消、重试和持久化。
3. 文本逐字一致，包括标点、空格、大小写和版本号格式。安卓没有的文本、按钮、页面、入口、跳转、提示和源码/项目地址不得添加。
4. iOS 代码只放在 `ios/`，可以用 SwiftUI/UIKit/Core Image/Metal 等平台实现，但平台差异不能改变行为结果。确实无法一致时先讨论并记录原因。
5. 公共组件、常量、字体、颜色、状态模型和动画应集中复用，保持职责清晰、高性能、可测试和可维护；不使用临时占位或重复代码堆砌表面效果。
6. 每个任务必须完成正常路径、边界、错误、取消、恢复、动画和验证后，才能在清单中勾选。编译或接口存在不代表完成；未执行的测试如实记录。
7. 未经用户明确要求，不自动构建、安装、提交或推送。需要真机构建时集中到验证节点并先取得确认。
   - 当前用户要求由主 agent 自己完成；未再次要求并行协作前，不主动派子 agent。用户要求先查看真机现状时，先确认连接并截图，再依据实际画面修改，不用源码推测代替已请求的真机检查。
8. 动画逐项对照安卓的时长、延迟、曲线/弹簧参数、位移、缩放、透明度、交错顺序、手势进度，以及连续触发、中断和恢复行为；不以系统默认动画或大致相似作为完成依据。性能优化必须保持既有行为。
9. 复用组件和逻辑不能合并安卓原本独立的业务状态。例如工作台照片效果与相机传输照片效果可以复用编辑控件、模型类型和渲染器，但各自的配置、草稿和持久化作用域必须按安卓保持独立。相同职责集中实现，不同职责清晰分离，不为抽公用代码改动安卓结构。

当前清单总进度：**2/62**。该数字只统计已经闭环验收的任务，不统计局部修复。

## 本轮确认的执行口径

> 用户原话：你需要复刻安卓端所有ui所有动画所有逻辑和状态流转,不自己臆想,完全参照安卓,不写多余的文本,不做多余的界面和按钮,合理封装与复用组件,保持高效优雅编码,不能写屎山难以维护部分, 写在文档中并且放在项目记忆中,时刻遵守

- 复刻范围覆盖安卓端已有的全部页面和模式：USB 有线、Wi‑Fi STA、Wi‑Fi AP、GPS/BLE、照片列表、大图预览、传输队列、设置、工作台，以及它们的弹窗、手势和动画。
- 每个模式都沿用安卓端已经验证过的判断顺序和状态流转；不能因为 iOS 采用 SwiftUI/UIKit 就重新设计一套逻辑。
- 实现阶段先对照安卓源码、资源和测试建立证据，再写 iOS 代码；发现安卓与 iOS 平台能力无法一一对应时暂停该差异点，记录原因并与用户讨论。
- 当前任务清单中的“已修”只表示局部代码已落地；只有正常、边界、异常、取消、恢复、动画和验证都闭环，才允许勾选并增加进度。
- 后续每次实现或审查都必须先回答：安卓对应代码在哪里、iOS 的用户可观察结果如何逐项对应、哪些异常/取消/恢复路径已验证；没有证据就保持未完成，不用“看起来差不多”替代验收。
