# 监看双轴姿态诊断

状态：已接入 512-byte v1 双轴姿态；等待真机验证绘制方向和更多机型兼容性。

## 首轮实测与实现

Z30 / V1.20 / AP / 拍照模式 / 0x9428，四组完整姿态各 7 帧。右倾组在收到的文档中截断，未作为证据。

- 大端 16.16 环角：+404 滚转，+408 俯仰，超过 180° 转为负角。
- 放平约 (-0.64°, -1.04°)，抬头 (-0.58°, +15.35°)，低头 (-3.96°, -11.91°)，左倾 (+17.48°, -2.82°)。
- 按已验证的帧头格式读取，不限制 Z30 名称；其他机型同格式仍需进一步实测。
- 旧协议、1024 字节头、未知版本、越界角度、两轴全零保留区不输出双轴。
- 两轴精确为零也暂时回退单轴：在未确认有效标志前，不把空白块当作水平。
- 有效帧头数据每 250ms 供水平仪更新，同时跳过 0xD067 查询；超过 1.5 秒无新帧或字段失效，回退属性读取。
- 滚转直径线穿过圆心并随滚转旋转；俯仰线与它平行，沿垂直方向偏移，长度按圆内弦计算，不越出圆边。固定水平参考只保留两侧短刻度。
- 滚转线和俯仰中心标记分别提示对齐，双轴均对齐时圆环也变绿。单轴回退保持原有最近 90° 轴对齐逻辑。俯仰位移在 ±30° 封顶。
- 已用报告中的四组原始字段进行自动测试。竖拍、右倾、极端俯仰及其他机型的方向和失效行为仍待实机确认。

## 操作

进入监看并保持实时画面，打开调试窗中的「姿态诊断」。依次摆好以下姿势后点击「采集」，保持约两秒：

1. 相机放平。
2. 镜头向上抬约 20°，尽量不左右倾斜。
3. 镜头向下压约 20°，尽量不左右倾斜。
4. 从相机后方看，机身向左倾约 20°，尽量不抬头低头。
5. 从相机后方看，机身向右倾约 20°，尽量不抬头低头。

完成后点击专用的「复制报告」，把全文反馈。报告仅在本次监看页面内保留，离开页面前务必复制。关闭调试窗取消正在采集的一步，已完成步骤保留。断流或数据不足可重试；切换机型、模式、连接或协议后请重新开始。

## 实现边界

- 被动采样现有监看数据，不增加相机命令，不切换协议、不改变相机设置。
- 每步最多 8 个样本，间隔至少 250ms，窗口约两秒；至少 5 帧且时间跨度至少一秒才接受。
- 只复制 JPEG 起点之前的帧头，最多 4096 字节。报告不保留 JPEG 内容。
- 记录实际取帧操作码、帧头长度、每帧单调时钟时间、机型、固件、连接及模式信息。
- 不与普通调试日志混排，避免日志截断。可复制已经完成的部分步骤。
- 不自动把未知字节判作俯仰角，也不把全零字段当作已支持。

## 调查依据与后续

已有旧协议的公开实现，可作为候选编码参考：

- [DslrDashboard PtpLiveViewObject](https://github.com/deas/dslrdashboard/blob/master/DslrDashboard/src/com/dslr/dashboard/PtpLiveViewObject.java)：部分机型帧头解析滚转、俯仰，使用有符号 16.16 定点数。
- [digiCamControl NikonD500Base](https://github.com/dukus/digiCamControl/blob/master/CameraControl.Devices/Nikon/NikonD500Base.cs)：旧取帧路径解析 LevelAngleRolling / LevelAnglePitching。
- [NX Tether 官方说明](https://nikonimglib.com/nx_tether/onlinehelp/en/03_liveview_window_15.html)：监看支持滚转和俯仰显示，但其监看支持范围不含 Z30，不能直接推断 Z30 的协议支持。

Z传优先使用 0x9428，按已有回退规则可能使用 0x9203；不同帧头布局不能套用相同偏移。拿到报告后先比较两组独立动作的字段响应，再验证字节序、比例、正负、无效值和竖拍行为。确认机型/头型后才接入绘制。不用照片 EXIF 或手机姿态代替相机实时俯仰。


## 第二轮竖拍实测与修复

Z30 / V1.20 / STA / 0x9428 / 512 字节头，三组各 8 帧，滚转约 +90°。

- 全部 24 帧的 +408 都为 FFFFFFFF，+412 为有效角度；此前按 +408 解析导致整组姿态无效并回退单轴，这就是俯仰线消失的原因。
- +412 归一化平均值：镜头朝前 -0.99°、抬头 +19.71°、低头 -20.40°。
- 已加入竖拍替代轴：仅滚转位于竖拍区间，且 +408 明确为 FFFFFFFF 时读取 +412；其他异常值不触发替换，替代轴仍检查数值范围。
- 横拍继续读取 +408；未知帧头仍保留原回退策略。没有增加相机请求。
- 回归测试包含横拍原始字段、竖拍原始字段、双轴均无效和非哨兵异常值。
- 本轮并未提供反向竖拍（滚转约 -90°）实测；该方向需继续核对机内显示。


## 绘制方向修正

绘制使用相机实际滚转角，不再把角度折算到最近 90° 轴。相机竖拍时直径线及俯仰弦一起转为竖向，位移仍垂直于两条线。对齐判断继续以最近 90° 轴为准。跨 ±180° 的动画使用连续展开角度，避免反向整圈旋转；圆周上下左右均有短参考刻度。角度数据解析及字段切换未改变。


## 第三轮反向竖拍实测与修复

Z30 / V1.20 / STA / 0x9428 / 512 字节头，三组各 8 帧，滚转约 270°。+408 均为 FFFFFFFF，+412 仍为有效轴，但零点为 180°，方向与正向竖拍相反。

- 仅在替代轴已启用且滚转位于 225°～315° 时，用 `180° - 原始角度` 换算俯仰；之后继续验证 ±90° 范围。
- 三组平均值：朝前 +1.10°、抬头 +22.98°、低头 -14.48°。
- 之前未转换零点导致触发角度范围拒绝，整组双轴失效并回退单轴。此次修复没有放宽有效值范围。
- 增加反向竖拍原始样本、精确零点、无效哨兵和异常角度的回归测试；横拍与正向竖拍测试仍通过。
- 原始数据已确认该方向的角度换算；最终绘制方向仍以真机对照为准。


## 第四轮倒置横拍实测与修复

Z30 / V1.20 / STA / 0x9428 / 512 字节头，三组各 8 帧，滚转约 180°。+408 为有效俯仰轴，+412 均为 FFFFFFFF；朝前原始角度约 179°、抬头约 163°、低头约 201°。

- 当滚转位于 135°～225°、使用主轴且 +412 明确无效时，以 `180° - 原始角度` 归一化，继续执行 ±90° 有效性检查。
- 四种朝向均已有 Z30 原始报告依据，新增倒置横拍三组样本、零点、无效哨兵及异常值测试。

| 朝向 | 实测滚转角附近 | 有效俯仰字段 | 俯仰换算 |
| --- | --- | --- | --- |
| 正向横拍 | 0° | +408 | 将环角归一化为正负角 |
| 正向竖拍 | 90° | +412（+408 无效） | 将环角归一化为正负角 |
| 倒置横拍 | 180° | +408（+412 无效） | 180° − 原始角度 |
| 反向竖拍 | 270° | +412（+408 无效） | 180° − 原始角度 |

上述是四个稳定朝向的实测规则；跨朝向切换边界、极端俯仰和其他机型仍不能仅凭这四组报告宣称全部验证。
