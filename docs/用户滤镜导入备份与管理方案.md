# 用户滤镜导入、备份与管理方案

> 状态：方案设计稿<br>
> 日期：2026-08-11<br>
> 目标版本：待定<br>
> 功能分支：`feature/2026-08-11`

## 一、背景与目标

ZTransfer 当前已经具备照片滤镜选择、强度调节和渲染能力，但可用滤镜由 App 内置，用户不能自行扩展。

本功能将建立一套本地“滤镜库”，允许用户导入 Nikon NP3 滤镜、为滤镜自定义名称、控制哪些滤镜出现在日常选择列表中，并将全部用户滤镜备份为一个文件，以便换机或重装后恢复。

本期目标如下：

1. 支持从系统文件选择器导入 `.np3` 文件。
2. 支持在导入时为滤镜自定义名称。
3. 支持显示或隐藏任意滤镜，精简日常滤镜列表。
4. 支持重命名和删除用户导入的滤镜。
5. 支持将全部用户滤镜及管理配置备份为一个文件。
6. 支持从备份文件合并恢复滤镜库。
7. 只提供一个管理入口，但导入并设为可见的滤镜可供 App 中所有现有滤镜使用场景选择。

## 二、范围定义

### 2.1 本期包含

- NP3 文件选择、校验和解析。
- 用户滤镜的本地持久化。
- 用户滤镜的自定义命名、重命名和删除。
- 内置滤镜与用户滤镜的统一列表。
- 滤镜显示范围的多选管理。
- 用户滤镜整库备份。
- 用户滤镜整库恢复。
- 导入、恢复、删除和异常场景的用户反馈。

### 2.2 本期不包含

- 云端同步。
- 滤镜商店、分享社区或在线下载。
- 在设置弹窗中增加第二个管理入口。
- 直接编辑 NP3 的各项参数。
- NCP 等其他滤镜文件格式。
- 保证与 Nikon RAW 开发管线逐像素一致。

### 2.3 核心约束

- 滤镜管理只有一个入口，位于“边框 · 水印 · 滤镜”手机照片工作台。
- 设置弹窗继续只负责选择和使用滤镜，不放置导入、删除、备份或恢复按钮。
- “无滤镜”始终存在，不参与隐藏和删除。
- 内置滤镜可以隐藏，但不能重命名或删除。
- 用户滤镜即使被隐藏，也仍然保存在滤镜库中并参与整库备份。

## 三、用户流程

### 3.1 导入单个 NP3 滤镜

1. 用户打开“边框 · 水印 · 滤镜”工作台。
2. 点击滤镜卡片右上角的“滤镜库”。
3. 在滤镜管理页点击“导入 NP3 滤镜”。
4. App 调用系统文件选择器，允许用户选择一个 `.np3` 文件。
5. App 在后台读取文件，并执行扩展名、文件大小、文件结构和参数范围校验。
6. 文件有效时，App 解析可支持的滤镜参数。
7. App 弹出命名窗口，默认名称优先使用 NP3 内部名称，其次使用文件名。
8. 用户确认名称后，App 将原始 NP3 和解析结果保存到应用私有目录。
9. 新滤镜默认设为可见，并立即出现在所有滤镜选择列表中。
10. App 显示“滤镜已导入”的结果提示。

如果文件无效或解析失败，不进入命名步骤，也不写入滤镜库。

### 3.2 设置滤镜可见性

1. 滤镜管理页展示全部内置滤镜和用户滤镜。
2. 每个滤镜左侧提供复选框。
3. 勾选表示该滤镜出现在日常滤镜选择列表中；取消勾选表示隐藏。
4. 勾选状态即时保存，无需额外点击“保存”。
5. 页面顶部显示“已显示数量 / 总数量”。

如果用户隐藏了当前正在使用的滤镜，App 应提示：

> 当前正在使用此滤镜。隐藏后将关闭当前滤镜效果，是否继续？

确认后将当前滤镜切换为“无滤镜”；取消则保持该滤镜可见。

允许隐藏全部实际滤镜，此时使用端只保留“无滤镜”。

### 3.3 重命名用户滤镜

1. 用户点击用户滤镜右侧的更多菜单。
2. 选择“重命名”。
3. 弹出文本输入窗口并填入当前名称。
4. 用户确认后立即更新滤镜库和所有使用端显示名称。

重命名只修改展示名称，不改变滤镜 ID、参数、当前选择状态或备份去重结果。

### 3.4 删除用户滤镜

1. 用户点击用户滤镜右侧的更多菜单。
2. 选择“删除”。
3. App 弹出确认窗口，显示将被删除的滤镜名称。
4. 用户确认后，App 删除该滤镜的原始 NP3、解析参数和管理记录。
5. App 更新所有滤镜选择列表，并显示“滤镜已删除”。

删除属于不可撤销操作，确认窗口建议使用以下文案：

> 删除“我的暖调人像”？<br>
> 此操作会从本机移除该滤镜，无法撤销。已经生成的照片不会受到影响。

删除规则：

- 内置滤镜不提供删除按钮。
- 如果删除的是当前正在使用的滤镜，确认窗口需额外说明删除后将关闭当前滤镜效果。
- 删除当前滤镜后，当前选择切换为“无滤镜”。
- 删除操作不影响已经导出的照片。
- 删除后仍可通过之前创建的备份文件重新恢复。
- 删除过程中先更新索引，再以安全方式清理文件；若文件清理失败，应记录并在后续启动时清理孤立文件，不能让滤镜列表处于半删除状态。

### 3.5 备份全部用户滤镜

1. 用户在滤镜管理页点击“备份全部”。
2. App 调用系统“创建文档”界面，让用户选择保存位置。
3. App 将全部用户滤镜和管理配置写入一个 ZTransfer 滤镜备份文件。
4. 写入成功后显示文件名和成功提示。

建议文件名：

```text
ZTransfer-Filters-20260811-153000.ztfilters
```

备份范围：

- 全部用户滤镜，包括当前隐藏的滤镜。
- 用户自定义名称。
- 原始 NP3 文件。
- App 已解析的滤镜参数。
- 用户滤镜的显示/隐藏状态。
- 内置滤镜的显示/隐藏状态。
- 备份格式版本、解析器版本和创建时间。

不纳入备份：

- 用户照片和已生成的效果图。
- 水印、边框和当前滤镜强度等其他工作台设置。
- 内置滤镜的原始数据；内置滤镜由 App 自身提供，只备份它们的可见性。

当没有任何用户滤镜时，“备份全部”保持可用，因为用户仍可能需要备份内置滤镜的显示配置；界面需要明确提示备份中不包含用户滤镜。

### 3.6 恢复滤镜备份

1. 用户在滤镜管理页点击“恢复备份”。
2. App 调用系统文件选择器选择 `.ztfilters` 文件。
3. App 校验文件结构、格式版本、清单和内部文件哈希。
4. App 展示恢复确认信息，包括备份时间和包含的用户滤镜数量。
5. 用户确认后执行合并恢复。
6. 恢复完成后显示结果摘要。

结果摘要示例：

> 恢复完成：新增 6 个，更新 2 个，跳过 3 个，失败 0 个。

默认恢复策略为“合并恢复”：

- 不删除本机已有滤镜。
- 使用 NP3 原始内容的 SHA-256 识别同一个滤镜。
- 相同内容只保留一份，避免重复恢复。
- 备份中的自定义名称和可见性可以更新同一滤镜的本地记录。
- 不同内容但同名时，两者均保留，新恢复的名称自动追加“(2)”“(3)”等序号。
- 单个滤镜损坏时跳过该项并继续恢复其他滤镜。
- 整个备份清单损坏或版本完全不兼容时终止恢复，不修改现有滤镜库。

“覆盖恢复”不作为首版入口，避免误删本机滤镜。后续如确有完整换机还原需求，可增加带强提醒的覆盖模式。

## 四、界面与按钮设计

### 4.1 唯一入口位置

现有工作台布局为：顶部栏、图片预览、滤镜卡片、边框水印编辑器和生成按钮。

在现有滤镜卡片顶部增加一行紧凑标题，右侧放置唯一入口“滤镜库”：

```text
┌──────────────────────────────────┐
│ 照片滤镜                 [滤镜库 ›] │
│                                  │
│ [滤镜选择滚轮]     [强度选择滚轮]    │
└──────────────────────────────────┘
```

按钮建议：

- 使用调节滑杆、叠层卡片或滤镜列表图标。
- 采用小型玻璃文字按钮，与现有工作台视觉语言一致。
- 按钮高度约 32–36dp，触控区域不小于 44dp。
- 不放到工作台顶部栏，避免与“选择/更换照片”按钮争夺空间。
- 设置弹窗中的滤镜卡片不显示此入口。

### 4.2 滤镜管理页

```text
‹  滤镜管理                         7/12 显示

┌──────────────────────────────────┐
│          ＋ 导入 NP3 滤镜          │
└──────────────────────────────────┘

[ 恢复备份 ]                 [ 备份全部 ]

显示在滤镜列表中                         [全选]

☑ 森屿青                             内置
☑ 柔暖人像                           内置
☑ 我的暖调人像                       导入  ⋮
☐ 夜景蓝调                           导入  ⋮
```

布局建议：

- “导入 NP3 滤镜”是全宽主按钮，高度 48–50dp，使用当前主题强调色。
- “恢复备份”和“备份全部”是两个等宽次级描边按钮。
- 使用“备份”而不是“导出滤镜”，避免与工作台的照片导出产生混淆。
- 用户滤镜显示“导入”标签，并提供更多菜单。
- 内置滤镜显示“内置”标签，不显示更多菜单。
- 首版可以不提供搜索框；当滤镜总数超过约 12 个时再显示搜索框。
- 列表较长时，顶部操作区固定或快速收起，列表保持顺畅滚动。

### 4.3 导入命名窗口

```text
导入滤镜

文件：Portrait-Warm.np3
名称：[ 我的暖调人像             ]

                    [取消] [导入]
```

名称规则：

- 去除首尾空格。
- 不允许空名称。
- 建议限制为 1–40 个字符。
- 不同滤镜允许使用相同名称，但 App 应自动追加序号，减少日常选择时的歧义。

### 4.4 用户滤镜更多菜单

```text
┌──────────┐
│ 重命名    │
│ 删除      │
└──────────┘
```

“删除”使用危险操作颜色，但不应在列表行上直接放置垃圾桶按钮，避免用户滚动或勾选时误触。

## 五、数据设计

### 5.1 滤镜统一模型

建议在现有 `PhotoFilterPreset` 之上增加来源和管理信息，逻辑上至少包含：

```text
id                  稳定滤镜 ID
sourceType          BUILT_IN / IMPORTED_NP3
displayName         用户看到的名称
sourceFileName      原始文件名，仅用户滤镜存在
sourceSha256        NP3 原始内容哈希
parserVersion       解析器版本
parameters          已解析的滤镜参数
visible             是否出现在使用端
createdAt           导入时间
updatedAt           最近修改时间
```

用户滤镜 ID 应由 NP3 内容哈希和必要的解析器版本稳定生成，不使用展示名称。这样重命名不会破坏当前选择、去重和备份恢复。

### 5.2 保存原始 NP3 和解析参数

虽然滤镜参数数据量较小，仍建议同时保存：

- 原始 NP3：用于精确备份、兼容验证和未来重新解析。
- 解析参数：用于 App 启动后快速加载和直接渲染。

原始文件和索引都放在应用私有目录中，不依赖用户持续授予原文件 URI 权限。

### 5.3 本地目录建议

```text
files/
└── photo_filters/
    ├── library.json
    └── imported/
        ├── {sha256}.np3
        └── ...
```

`library.json` 记录用户名称、可见性、参数和版本；`imported` 保存原始 NP3。

索引更新应使用“临时文件写完后原子替换”。导入、恢复和删除均不能直接覆盖唯一有效索引。

### 5.4 备份文件格式

建议 `.ztfilters` 使用 ZIP 容器，内部结构如下：

```text
manifest.json
filters/
├── {sha256-1}.np3
├── {sha256-2}.np3
└── ...
```

`manifest.json` 包含：

- `schemaVersion`
- `createdAt`
- `appVersion`
- `parserVersion`
- 用户滤镜清单和参数
- 内置、用户滤镜的可见性
- 每个 NP3 的文件大小和 SHA-256

恢复时必须限制压缩包总大小、单文件大小、条目数量和解压路径，防止恶意或损坏文件导致内存、磁盘或路径穿越问题。

## 六、NP3 解析与效果边界

App 当前渲染模型已经支持以下 NP3 对应参数：

- 对比度。
- 高光、阴影、白色、黑色。
- 饱和度。
- 八个颜色区间的色相、色度和亮度。
- 色调曲线。

当前内置 NP3 滤镜是预先转换并硬编码的，仓库中尚无通用 NP3 文件解析器。因此实现导入前必须完成：

1. 收集来自不同相机或 NX Studio 版本的真实 NP3 样本。
2. 明确 NP3 文件结构、字节序、版本差异和字段校验规则。
3. 建立解析器测试样本和预期参数。
4. 对 App 暂不支持的字段给出明确兼容策略。

首版应将“复刻效果”定义为：读取并应用 App 当前支持的 NP3 参数，尽量接近原效果，但不承诺与 Nikon RAW 开发结果逐像素一致。

如果 NP3 中存在无法支持的有效参数，可以允许导入，同时提示：

> 滤镜已导入；部分相机专用参数暂不支持，显示效果可能与 Nikon 软件略有差异。

如果核心颜色或曲线数据无法读取，则应拒绝导入，避免生成名义存在但效果明显错误的滤镜。

## 七、状态与兼容规则

- App 启动时加载“内置滤镜 + 用户滤镜”，再按可见性生成使用端列表。
- 设置页和手机照片工作台共享同一个可见滤镜列表。
- 当前选择的滤镜 ID 仍然有效时继续使用。
- 当前滤镜被删除或确认隐藏后，自动关闭滤镜效果。
- 用户滤镜文件缺失或损坏时跳过该项、记录错误并保持 App 可用。
- 升级解析器时，可利用保存的原始 NP3 在后台重新生成解析参数。
- 旧备份由 `schemaVersion` 决定是否迁移、部分恢复或拒绝恢复。
- 新版备份不应在无法理解字段时静默覆盖旧数据。

## 八、异常与提示

至少覆盖以下场景：

| 场景 | 建议处理 |
| --- | --- |
| 用户取消文件选择 | 不提示错误，不改变状态 |
| 文件扩展名不是 NP3 | 提示“请选择 NP3 滤镜文件” |
| 文件损坏或格式不支持 | 提示“无法读取此 NP3 文件” |
| 只支持部分参数 | 允许导入并提示兼容性限制 |
| 重复导入同一 NP3 | 提示已存在，可选择保留或修改现有名称 |
| 名称为空 | 禁止确认 |
| 导入时存储空间不足 | 不写入索引，提示空间不足 |
| 删除当前滤镜 | 二次确认，并说明将关闭当前效果 |
| 备份写入失败 | 删除未完成输出并提示失败 |
| 备份整体损坏 | 终止恢复，现有滤镜库保持不变 |
| 备份中单项损坏 | 跳过损坏项，继续恢复并汇总结果 |
| 恢复时空间不足 | 终止或部分回滚，不能留下半写入索引 |

## 九、建议实施顺序

为了降低一次性改动风险，建议按以下顺序实现：

1. NP3 通用解析器、样本和单元测试。
2. 用户滤镜仓库、稳定 ID、原始文件和参数持久化。
3. 将 ViewModel 的滤镜来源改为内置与用户滤镜合并。
4. 滤镜管理页和唯一入口。
5. 导入、命名、重命名、显示/隐藏和删除。
6. `.ztfilters` 备份生成。
7. 合并恢复、冲突处理和恢复摘要。
8. 全链路测试、异常测试和真机文件选择验证。

## 十、验收标准

### 10.1 导入

- 能从系统文件选择器选择有效 NP3。
- 无效文件不会写入滤镜库。
- 用户可以在导入时修改名称。
- 导入后无需重启即可在所有滤镜使用端看到新滤镜。
- 重复导入不会产生无法区分的重复记录。

### 10.2 显示管理

- 用户可以多选需要展示的滤镜。
- 隐藏项不出现在使用端，但仍保留在管理页和备份中。
- “无滤镜”始终可选。
- 当前滤镜被隐藏时有明确提示并按确认结果处理。

### 10.3 重命名和删除

- 用户滤镜可以重命名，重命名后效果和选择状态不变。
- 用户滤镜可以删除，删除前必须二次确认。
- 删除后原始文件、参数和索引均得到一致处理。
- 删除当前滤镜后自动关闭当前效果。
- 内置滤镜不能被重命名或删除。

### 10.4 备份和恢复

- 一次备份生成一个文件，并包含全部用户滤镜和可见性配置。
- 隐藏滤镜也能被备份和恢复。
- 恢复默认与本机滤镜合并，不删除现有项。
- 同一 NP3 多次恢复不会产生重复滤镜。
- 部分条目损坏时能恢复其他有效滤镜并展示结果。
- 整体恢复失败时不破坏已有滤镜库。

### 10.5 稳定性

- 导入、解析、备份和恢复不阻塞主线程。
- 大文件、损坏文件和低存储空间不会导致 App 崩溃。
- App 被中断后不会留下可见的半导入或半删除记录。
- 原有内置滤镜、强度调节、边框、水印和照片导出功能保持正常。

## 十一、待确认事项

1. 导入、备份、恢复和用户滤镜管理是否限制为 Pro 权益。
2. 需要兼容哪些相机或 Nikon 软件版本生成的 NP3。
3. 是否能提供多份真实 NP3 样本以及对应的 Nikon 软件预览参考图。
4. 同一个 NP3 再次导入时，是直接提示已存在，还是允许更新现有滤镜名称。
5. 备份恢复时是否需要包含当前正在使用的滤镜和强度；本方案默认不包含。
6. 后续是否需要“覆盖恢复”；本方案首版只提供更安全的合并恢复。
7. 滤镜数量达到多少时启用搜索框；本方案建议超过约 12 个后显示。
