iOS STA 模式：行为优先级与加载策略

这份表格按当前 iOS 代码整理，描述“现在会怎样”，不是未来设计。STA 是 Wi‑Fi STA 连接；同一套相机 I/O 门控也用于 USB/AP，差异已在对应行标出。代码证据列给出主要实现文件。

监看复核结果见第五至八节。下方优先级是功能让路概览，不是严格的全局抢占队列；传输/监看同时运行的时序仍需验证。

三、功能之间的让路规则

当前功能占用资源会暂停谁释放后谁恢复特殊说明
传输TransferQueue + CameraIOGate transfer slice后台缩略图、空闲探测；列表元数据只在普通锁可用时执行。缩略图填充 worker 在 transferBusy 变为 false 后 wake。传输设置 transfersBusy，下载活动跨越整个文件；分片之间允许交互操作插队。
监看RemoteViewModel Live View 通道扫描、缩略图远程读取和后台填充。监看清理回调后按条件恢复；重新核对 handle 时放弃旧扫描快照，保留已有列表和缩略图。快速进退仍待验证。监看期间可继续使用已有内存/磁盘数据，不为显示旧缓存而发起新的后台相机读取。
FHD/EXIF 预览interactive reservation + ordinary command缩略图填充和文件扫描等待；传输等当前 slice 结束。预览 reservation 释放后，扫描从既有游标继续，缩略图 worker wake。预览优先级覆盖普通列表读取，但不取消整个传输任务。
本地/照片效果预览效果渲染 gate只阻塞后台缩略图填充，不阻塞文件元数据扫描。效果预览完成后后台填充恢复。这是本地渲染资源竞争，和相机 I/O 的交互 reservation 分开。
设置、传输队列页面UI 路由，不直接占用相机 I/O不应清除文件列表或缩略图缓存。返回照片列表复用同一会话模型和已有缓存。只有用户明确下拉刷新/新会话/连接恢复等边界才会触发扫描。

四、需要注意的边界

  • “文件列表每次读取新的”和“缩略图复用缓存”是有意分开的：列表必须以相机当前 handle 为准，缩略图则可以按稳定 key 复用。
  • 每批 12 个是普通扫描和后台填充的稳定窗口；STA 直读首屏的 1/3/12 预热序列是当前 iOS 代码明确写出的低延迟策略，并非所有 STA 批次都固定为 12。
  • 缓存命中不代表一定跳过 UI 重建：路由返回时 SwiftUI 单元可能重新创建，但数据源会先从会话模型和 PhotoThumbnailStore 的内存/磁盘缓存返回，不应重新访问相机。
  • 传输、监看和预览的优先级是相机 I/O 优先级；它不等同于 UI 动画层级，也不改变已经完成的文件传输状态。

八、尚不能作出“完整对齐”结论的边界

  • 缓存基准：两端都有返回后查询最新 handle、保留已有行和处理增删的路径。这只能说明实现方向一致；扫描中途抢占、首批前退出、相机删除/新增、失败时保留旧行仍需验证。
  • 事件消费者交接：列表后台轮询有 remoteActive 门控，但进入监看时已经在途的 GetEvent、事件 socket 与监看消费者的交接，还需时序测试；不能只凭门控变量断言绝不丢事件。
  • 并发功能：传输中进监看、GPS 同时启用、断网重连、切后台/锁屏、快速关闭再打开，尚未完成跨模块时序验证；不能把这一页理解成严格的全局优先级证明。
  • 完整产品复刻：免费试用/高级版限制、音频权限及录制保存、所有语言文案、全套对焦框反馈动画、所有工具参数和布局尺寸，还没有在本轮逐项验收。M31 已确认录制入口功能不一致，不能据此反推其余权限与保存规则已检查完。
  • 验证依据：已阅读安卓 RemoteLiveViewSchedulingTest、RemoteBatteryTest、RemoteAutoIsoTest 的对应规则；测试源码是行为依据，不是本轮运行通过的记录。iOS 已存在的 RemoteLifecycleTests 也不覆盖以上全部条目。
