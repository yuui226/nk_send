# 无存储卡时紧急直存手机可行性调研

> 调研日期：2026-09-05  
> 目标机型：优先 Nikon Z 30，后续按协议能力扩展其他 Nikon 机型  
> 目标功能：相机未插存储卡时，预先连接 Z传，将新拍静态照片立即保存到手机  
> 结论性质：文档、开源协议实现和现有代码审查结论；尚未完成 Z 30 无卡真机验证

## 一、结论

**可以实现，但产品必须定义为“拍摄前连接、拍后立即直存手机”，不能定义为“拍完以后从相机内存恢复照片”。**

Nikon Z 30 在普通无卡模式下允许快门动作和 Demo 回放，但不会把照片记录成可下载文件。因此：

| 场景 | 结论 | 说明 |
|---|---|---|
| 无卡普通拍摄，之后才连接 Z传 | 不可实现 | 相机没有生成可通过 PTP 枚举和下载的持久照片对象 |
| 拍摄前已连接 Z传，由 App 快门触发并立即下载 | 可实现 | 通过 Nikon SDRAM 联机拍摄流程完成，USB 最有把握 |
| 拍摄前已连接 Z传，按相机机身快门并立即下载 | 原理可行，需真机验证 | 需要进入允许机身操作的联机控制模式，并将记录目标切到 SDRAM |
| Z 30 USB 无卡直存 | 高可行性 | Nikon 官方 NX Tether 支持 Z 30，并支持只保存到计算机 |
| Z 30 当前智能设备 Wi-Fi AP 无卡直存 | 中等可行性 | 现有遥控命令链路可复用，但 Nikon 没有对该组合给出官方保证 |
| 无卡录像 | 不可实现 | Nikon 官方联机说明仍要求视频模式插入存储卡 |

建议把产品功能命名为：

- **无卡紧急直存**
- 或 **手机联机存储**

界面必须持续提示“相机内无卡、手机是唯一副本；显示保存成功前不要断开连接”。

## 二、为什么不能事后找回 Demo 照片

Z 30 官方手册对“无存储卡时允许释放”的描述是：快门可以释放，但照片不会被记录，回放时显示 `Demo`。屏幕能显示刚拍画面，只说明传感器处理链和临时工作缓冲中曾存在图像数据，不表示相机生成了可供 PTP 下载的文件。

普通照片浏览依赖以下对象模型：

1. `GetStorageIDs` 获取存储介质；
2. `GetObjectHandles` 获取介质内文件句柄；
3. `GetObjectInfo` 和 `GetObject` 读取文件。

没有存储卡时，普通无卡拍摄不会把 Demo 图像注册到该对象模型中。之后再打开 Z传，没有稳定句柄可供查询，也没有可靠的恢复时机。

Z 30 的普通 Wi-Fi 自动上传也属于“先写卡、再上传”：Nikon 官方说明上传只在照片已记录到存储卡后开始。这条链路不能拿来实现无卡直存。

因此必须把以下产品边界写死：

- 不承诺恢复连接 Z传之前拍摄的无卡照片；
- 不把 Demo 回放解释成“照片仍保存在机身里”；
- 不提供“扫描相机内存找回照片”的误导性入口。

## 三、可行原理：Nikon SDRAM 联机拍摄

联机拍摄与普通无卡释放是两条不同流程。控制端在拍摄前已经连接相机，并明确要求把本次照片写入相机 SDRAM；照片生成后，相机发出事件，控制端立即读取临时对象并保存到外部设备。

现代 Nikon 机身优先使用：

| 项目 | 值 | 含义 |
|---|---|---|
| 操作码 | `0x9207` | `InitiateCaptureRecInMedia` |
| 参数 1 | `0xFFFFFFFF` | 拍摄前不执行 AF |
| 参数 1 | `0xFFFFFFFE` | 拍摄前执行 AF |
| 参数 2 | `0` | 保存到存储卡 |
| 参数 2 | `1` | 保存到 SDRAM，由控制端立即下载 |

旧机型可能使用：

| 操作码 | 含义 |
|---|---|
| `0x90C0` | 拍摄到 SDRAM |
| `0x90CB` | AF 后拍摄到 SDRAM |
| `0x90C3` | 删除 SDRAM 图像 |
| `0x940C` | 取消 SDRAM 中的图像 |

关键事件包括：

| 事件码 | 含义 |
|---|---|
| `0xC101` | `ObjectAddedInSDRAM`，参数通常携带临时对象句柄 |
| `0xC102` | `CaptureCompleteRecInSdram` |
| `0x4002` | 标准 `ObjectAdded`，部分机型或模式可能使用 |
| `0x400D` | 标准 `CaptureComplete` |

libgphoto2 的 Nikon 实现明确指出：SDRAM 对象不会出现在普通 `GetObjectHandles` 结果中，必须在拍摄流程内立即下载。部分机型使用或重复使用伪句柄 `0xFFFF0001`，因此不能把它当成可长期保存、稍后下载的文件标识。

### 推荐协议时序

```text
准备手机目标目录并确认可写
        ↓
进入相机控制模式，确认 SDRAM 拍摄能力
        ↓
先启动事件等待器
        ↓
发送 0x9207(AF 参数, 1=SDRAM)
        ↓
轮询 DeviceReady，并收集 ObjectAddedInSDRAM / CaptureComplete
        ↓
对每个临时对象执行 GetObjectInfo → GetObject
        ↓
写入临时文件 → 校验长度 → 关闭输出流 → 改为正式文件名
        ↓
清理相机 SDRAM
        ↓
界面显示“已安全保存”，才允许下一张
```

监听器必须在发送快门命令前完成注册，避免小文件生成过快导致事件丢失。

## 四、官方和第三方证据

### 4.1 Nikon 官方证据

1. [Z 30：无存储卡时允许释放](https://onlinemanual.nikonimglib.com/z30/en/09-06-32.html)：普通无卡释放不会记录照片，只显示 Demo。
2. [Z 30：通过 Wi-Fi 上传照片](https://onlinemanual.nikonimglib.com/z30/en/10-02.html)：普通自动上传要求照片先记录到存储卡。
3. [NX Tether：选择保存目标](https://nikonimglib.com/nx_tether/onlinehelp/en/02_choose_a_destination_7.html)：静态照片目标可以选择 `Computer`、`Computer + Card` 或 `Card`。
4. [NX Tether：故障排查](https://nikonimglib.com/nx_tether/onlinehelp/en/06_experiencing_trouble_29.html)：只有选择 `Computer + Card`、`Card` 或视频模式时才明确要求插卡。
5. [NX Tether 窗口](https://nikonimglib.com/nx_tether/onlinehelp/en/01_the_nx_tether_window_2.html)：不支持 NX Tether Live View 的界面示例直接使用 Z 30，并仍提供上述保存目标。
6. [NX Tether：连接相机](https://nikonimglib.com/nx_tether/onlinehelp/en/02_connect_the_camera_and_computer_4.html)：Z 30 被列为不能使用 NX Tether 无线连接的机型，官方路径要求 USB。
7. [Camera Control Pro 2：启用机身控制](https://nikonimglib.com/ccp2/onlinehelp/en/10_camera_menu_01.html)：Nikon 联机控制体系允许启用机身控件并直接从相机拍照，但是否能在 Z传当前 Z 30 会话中复现仍需实测。

上述证据链可以证明“无卡静态照片联机直存”是 Nikon 体系内存在的正式能力；不能仅凭文档证明 Z传当前 Wi-Fi AP 会话一定支持该能力。

### 4.2 开源协议证据

1. [libgphoto2 Nikon PTP 定义](https://raw.githubusercontent.com/gphoto/libgphoto2/master/camlibs/ptp2/ptp.h)：`0x9207` 的第二参数为 `SDRAM=1`、`Card=0`，并定义了 SDRAM 拍摄和清理操作码。
2. [libgphoto2 Nikon 拍摄实现](https://raw.githubusercontent.com/gphoto/libgphoto2/master/camlibs/ptp2/library.c)：实现了事件等待、临时句柄、`GetObjectInfo`、立即下载和清理流程。
3. [libgphoto2 支持机型列表](https://gphoto.sourceforge.io/proj/libgphoto2/support.php)：Z 30 标注支持 Image Capture、Trigger Capture、Live View 和 Configuration。
4. [gPhoto 远程控制说明](https://gphoto.sourceforge.io/doc/remote/)：部分 Nikon 可把拍摄目标设为 SDRAM，且必须在同一调用/连接中立即下载，否则连接关闭后对象会消失。

## 五、Z传现有代码审查

现有代码已经具备大部分底层能力，但当前业务流程明确只支持“拍到卡，再从照片列表下载”。

### 5.1 当前阻塞点

[`RemoteLab.kt`](../../app/src/main/java/com/ztransfer/protocol/RemoteLab.kt) 中的 `rcCapture()` 当前固定调用：

```kotlin
cmdBusyRetry(Lab.NK_CAPTURE_REC_IN_MEDIA, -1 /*no AF*/, 0 /*card*/)
```

也就是说，当前遥控快门的目标始终是存储卡。无卡时仅修改 UI 或重新扫描照片列表不会解决问题。

[`RemoteScreen.kt`](../../app/src/main/java/com/ztransfer/ui/screen/RemoteScreen.kt) 已经会等待 `ObjectAdded` 或 `ObjectAddedInSDRAM` 作为拍摄确认，但当前设计明确为“拍摄结果仅确认不入队，下载走照片列表”。SDRAM 对象不会进入普通列表，因此必须在事件回调中启动专用下载事务。

[`CameraViewModel.kt`](../../app/src/main/java/com/ztransfer/viewmodel/CameraViewModel.kt) 的普通扫描流程从 `GetStorageIDs` 开始；没有可用存储时会结束扫描并返回空列表。这对普通传图是正确行为，不应为了无卡直存而修改成伪造存储卡。

### 5.2 可复用能力

[`RemoteProtocolCodes.kt`](../../shared/src/commonMain/kotlin/com/ztransfer/protocol/RemoteProtocolCodes.kt) 已有：

- `NK_CAPTURE_REC_IN_MEDIA = 0x9207`
- `NK_CAPTURE_REC_IN_SDRAM = 0x90C0`
- `EVT_OBJECT_ADDED_SDRAM = 0xC101`
- `PROP_NK_RECORDING_MEDIA = 0xD10B`

[`RemoteLiveViewPolicy.kt`](../../shared/src/commonMain/kotlin/com/ztransfer/protocol/RemoteLiveViewPolicy.kt) 已把普通 `ObjectAdded` 和 SDRAM `ObjectAdded` 都视为拍摄完成候选事件。

[`NikonCamera.kt`](../../app/src/main/java/com/ztransfer/protocol/NikonCamera.kt) 已具备：

- `GetObjectInfo` 解析；
- `GetObject` 全量下载；
- 输出流写入和实际接收长度校验；
- USB、Wi-Fi AP 和 Wi-Fi STA 下的统一相机会话基础。

[`TransferViewModel.kt`](../../app/src/main/java/com/ztransfer/viewmodel/TransferViewModel.kt) 已具备 SAF 目标文件、缓冲输出流、传输进度和文件改名等能力，可抽取或复用其中不依赖照片列表任务的部分。

### 5.3 结论

这不是从零开发协议，但也不能只把 `0 /*card*/` 改成 `1 /*sdram*/`。真正工作量集中在：

- 专用拍摄下载状态机；
- 多对象事件聚合；
- 临时文件和原子完成语义；
- SDRAM 清理；
- 掉线、进程退出和空间不足时的安全提示；
- 不同机型、固件和连接模式的能力门控。

## 六、建议实现方案

### 6.1 独立会话，不接入普通照片列表扫描

建议新增独立的 `CardlessDirectSaveSession`（名称仅示意），负责一次无卡直存会话，不要把 SDRAM 对象塞进普通卡片照片列表后再下载。

建议状态：

```text
Idle
  → PreparingDestination
  → Ready
  → Capturing
  → WaitingForObjects
  → Downloading
  → Verifying
  → CleaningCameraBuffer
  → Saved
  → Ready

任意阶段失败 → Failed（明确说明本张是否可能丢失）
```

同一时刻只允许一个拍摄下载事务。第一版在当前一张完成前禁用下一次快门。

### 6.2 能力门控

进入功能前检查：

1. 相机会话已经连接且稳定；
2. `OperationsSupported` 包含 `0x9207`，或包含可用的 `0x90C0`/`0x90CB` 回退；
3. 支持 `GetObjectInfo` 和 `GetObject`；
4. 存在可用的 Nikon 事件轮询路径；
5. 手机目标目录仍有写权限；
6. 手机剩余空间高于安全阈值；
7. 当前不是视频模式；
8. 当前没有照片传输、文件扫描或另一条相机事务占用通道。

不能只根据机型字符串启用。应以相机实际广告的操作码为第一层门控，再叠加“机型 + 固件 + 连接方式”的真机验证白名单。新世代机身在智能设备模式下可能隐藏或锁定遥控操作码，详见[无线遥控相机调研](无线遥控相机调研.md)。

### 6.3 拍摄和事件处理

第一选择：

```text
0x9207(0xFFFFFFFF 或 0xFFFFFFFE, 1)
```

只有相机不支持现代命令时，才按实际广告能力回退 `0x90C0` 或 `0x90CB`。

事件处理要求：

- 拍摄前先 arm 事件等待器；
- 同时等待对象新增和拍摄完成，避免只收到完成事件就结束；
- 接受 `0xC101`、`0xC102`、`0x4002` 和 `0x400D` 的机型差异；
- 新增 `0xC102 CaptureCompleteRecInSdram` 常量和名称；
- RAW+JPEG 可能产生多个对象，必须全部保存；
- 收到完成事件后仍需短暂 drain 已在途的对象事件；
- 不允许仅凭响应码 `0x2001` 宣布照片已经安全保存。

### 6.4 手机落盘事务

每个对象应执行：

1. `GetObjectInfo(handle)` 获取格式、文件名和声明大小；
2. 在最终目录创建临时文件，或先写 App 私有临时文件；
3. `GetObject(handle)` 流式写入，不把整张 NEF 放进内存；
4. 关闭并 flush 输出流；
5. 声明大小已知时，核对实际接收字节数；
6. 可选做 JPEG/NEF 最小文件头检查；
7. 成功后改为正式文件名；
8. 只有正式文件可重新打开且长度正确，UI 才显示“已保存”；
9. 随后清理 SDRAM 临时对象。

当前普通下载支持续传，但无卡直存不能承诺跨断线续传：SDRAM 句柄可能失效或被复用。连接仍在且对象仍有效时可以做有限重试；一旦会话断开，应按“本张可能已丢失”处理。

### 6.5 SDRAM 清理

下载成功后，按机型能力尝试：

1. 标准 `DeleteObject(handle, 0)`；
2. Nikon `0x90C3 DelImageSDRAM(handle)`；
3. 会话终止或异常收尾时使用 `0x940C CancelImagesInSDRAM`，仅在相机明确支持时调用。

不同机型对清理命令的返回行为不同。真机验证必须确认：连续拍摄不会因未释放 SDRAM 最终卡死，也不会在清理阶段误删存储卡文件。

### 6.6 机身快门支持

“按相机机身快门，自动保存手机”比 App 快门多一层控制模式问题。可能需要：

- 将 `0xD10B RecordingMedia` 设置为 SDRAM；
- 进入相机控制模式；
- 启用机身控件；
- 持续监听由机身快门产生的 `ObjectAddedInSDRAM`；
- 离开模式时恢复原属性。

Nikon 桌面联机软件证明这种交互在 Nikon 体系内存在，但当前智能设备遥控会话可能锁住机身操作。第一版不要把机身快门作为上线前置条件，应先交付 App 内快门，再通过 USB 抓包和 Z 30 真机测试确认机身流程。

## 七、连接方式优先级

### 7.1 第一优先：USB

原因：

- Nikon 官方对 Z 30 的 NX Tether 路径要求 USB；
- Z传已经支持 Android USB PTP；
- 全尺寸 JPEG/NEF 下载速度和稳定性高于相机 AP Wi-Fi；
- 不受 Wi-Fi 切网、系统网络选择和射频干扰影响；
- 更适合“手机是唯一副本”的高风险模式。

第一版建议范围：**Z 30 + USB + App 内单张快门 + JPEG/NEF 直存**。

### 7.2 第二优先：当前 Wi-Fi AP

Z传当前遥控页已经能在 Z 30 智能设备 AP 会话中执行写卡拍摄，因此将同一 `0x9207` 的目标参数改为 SDRAM 具有协议依据。仍需验证：

- 智能设备模式是否接受参数 2 为 `1`；
- 是否发出 `0xC101`；
- `GetObjectInfo`/`GetObject` 是否允许读取临时句柄；
- Live View 重启是否影响临时对象；
- NEF 和 RAW+JPEG 在当前 PTP/IP 会话中的耗时与超时；
- Wi-Fi 短暂丢包是否会造成对象不可恢复。

Nikon 文档只说明 NX Tether 不支持 Z 30 无线连接，这不能证明 Z传使用的智能设备 PTP/IP 一定失败，但意味着 Wi-Fi 只能在真机通过后按“已验证组合”开放。

### 7.3 Wi-Fi STA 和新世代机身

STA 照片浏览能力不等于相机控制能力。必须独立检查拍摄操作码和事件通道，不能因为 STA 能列出存储卡照片就默认支持 SDRAM 拍摄。

Z 8、Z 9、Z f、Z 6III 等新世代机身在部分智能设备模式下存在私有认证和操作码隐藏问题。功能应按运行时能力和真机白名单开放，不承诺一次实现覆盖所有 Nikon 机型。

## 八、产品和安全约束

### 8.1 必须阻止拍摄的情况

- 手机目录权限失效；
- 手机空间不足或无法估算；
- 上一张仍未完成下载；
- 相机正在录像；
- 相机连接不稳定；
- App 无法保持前台或前台服务；
- 相机未通过 SDRAM 能力检测。

应尽量在发出快门命令之前发现问题，因为拍摄之后再发现手机无法写入，照片可能没有任何副本。

### 8.2 UI 状态语义

至少区分：

- **正在拍摄**：相机已接受命令，但还没有对象；
- **正在接收**：已经拿到临时对象，手机文件尚不安全；
- **正在确认保存**：数据完成，正在关闭和改名；
- **已安全保存**：最终文件已验证；
- **保存失败，本张可能丢失**：不能使用普通“传输失败，稍后重试”的轻量提示。

不能在收到 `ObjectAdded` 或快门命令返回 OK 时就显示成功。

### 8.3 第一版明确不支持

- 连接前拍摄的 Demo 照片恢复；
- 视频无卡录制；
- 高速连拍；
- 多张同时在 SDRAM 排队；
- 跨断线续传；
- 后台静默无限拍摄；
- 未经验证机型的自动开放。

## 九、Z 30 真机验证清单

### 9.1 最小协议实验

先在开发者面板增加一次性实验入口，不接正式 UI：

1. Z 30 取出存储卡；
2. USB 连接 Z传并记录机型、固件、`OperationsSupported`；
3. 预先启动事件轮询；
4. 发送 `0x9207(0xFFFFFFFF, 1)`；
5. 记录完整响应码和事件序列；
6. 对事件句柄调用 `GetObjectInfo`；
7. 使用 `GetObject` 保存到 App 临时目录；
8. 比对声明大小、实收大小、文件格式和可解码性；
9. 清理 SDRAM；
10. 重复 20 次，确认临时句柄是否复用以及是否发生缓冲耗尽。

只有最小实验成功，才进入正式 UI 开发。

### 9.2 功能矩阵

### 9.3 上线准入条件

建议至少满足：

- Z 30 USB 下 JPEG、NEF、RAW+JPEG 均通过；
- 100 次连续单拍无漏图、错图或 SDRAM 堵塞；
- 任一失败路径都不会显示假成功；
- 最终文件大小和格式校验通过；
- 断线时能明确说明当前照片可能无法恢复；
- 退出模式后相机记录目标和控制状态恢复正常；
- 插回存储卡后普通拍摄、照片列表和传输流程不受影响。

Wi-Fi 和机身快门应分别设置独立上线门槛，不应因为 USB App 快门已通过而自动开放。

## 十、建议实施阶段

### 阶段 0：真机协议验证

- 只做开发者面板实验；
- 验证 Z 30 USB 无卡 `0x9207(..., 1)`；
- 收集事件、句柄、对象信息和清理行为。

### 阶段 1：USB 最小可用版本

- App 内单张快门；
- JPEG 和 NEF；
- 独立目标目录；
- 临时文件、长度校验、成功确认；
- 禁用连拍和视频。

### 阶段 2：完整静态照片格式

- RAW+JPEG 多对象；
- 长曝光；
- 更完整的异常恢复；
- Live View 拍后恢复。

### 阶段 3：Wi-Fi AP

- 只对真机验证过的“机型 + 固件”开放；
- 增加更醒目的断线风险提示；
- 根据 NEF 实测时长调整超时和前台保活。

### 阶段 4：机身快门和更多机型

- 验证 `RecordingMedia`、控制模式和机身控件；
- 建立能力白名单；
- 扩展其他 Nikon Z 和 DSLR 机型。

## 十一、最终决策建议

建议立项，优先完成 **Z 30 USB 无卡紧急直存**。

它能在忘带卡、卡损坏或临时没有可用卡时提供真实的应急价值，而且 Z传已有 USB PTP、遥控拍摄、事件轮询和文件下载基础，新增工作主要是把这些能力组织成可靠的 SDRAM 直存事务。

同时必须坚持三条边界：

1. **先连接，再拍摄**；连接前的 Demo 照片无法救回。
2. **保存成功前没有副本保障**；断线可能永久丢失当前照片。
3. **首版只做 USB 单张静态照片**；Wi-Fi、机身快门、连拍和更多机型逐项真机验证后再开放。
