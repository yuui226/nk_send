# iOS 照片列表入队动画修复

## 行为依据

- 安卓列表的 `QueueFlightGhost` 先以进度 0 挂载，再用 560 ms 的
  `CubicBezier(0.5, 0, 0.8, 0.35)` 沿二次贝塞尔曲线飞入队列胶囊。
- 安卓预览页在飞行动画前显式预留 32 ms（两帧），避免纹理和动画起点在同一帧提交。
- 单张和连拍预览都落在队列承载区右缘向内 28 pt 的位置；抵达前 6% 才淡出。

## iOS 修复

- 列表与预览残影改为由 `TimelineView` 根据不可变起始时间逐帧计算；起始时间预留
  32 ms，避免 SwiftUI 合并插入态与终点态导致动画完全不显示。
- 预览残影同样先挂载，再启动飞行；优先复用页面已显示的大图，其次使用内存缩略图，不新增相机读取。
- 预览主图的上抛与弹簧回位改为先后执行，避免同一轮更新中的两次位移写入被合并为最终的零位移。
- 预览改为对路径参数做逐帧插值，恢复弧线轨迹，并把落点统一到胶囊右缘内侧。
- 单张残影不再套用连拍卡片的偏移和倾斜；连拍仍显示最多三层叠片。
- 落点不再取独立的推算锚点，直接测量当前可见队列胶囊；胶囊右缘固定，落点始终为其
  右缘向内 28 pt、垂直居中。
- 日期整组入队复刻安卓两幕时序：最多 8 个可见缩略图在 420 ms 内错峰汇聚到分组
  “+”按钮，再由三层卡片摞用 560 ms 飞入胶囊。
- 抵达后右上控件先在 110 ms 内放大到 1.18 倍，再以 stiffness 200、damping ratio 0.5
  的等效物理弹簧回落。
- 队列数字不再在点击时提前增加。飞行动画开始前记录当前可见队列数量作为基线；真实队列可先入队并开始传输，但新增部分在残影抵达前被隐藏。残影命中胶囊时释放对应数量并触发反馈，因此数字与命中发生在同一时刻。入队失败或预览提前关闭走取消路径，只释放占位，不触发命中反馈。

- 2026-09-18 用户在模拟器确认入队动画已经出现；随后继续修正真实胶囊落点和安卓两幕式组动画。
