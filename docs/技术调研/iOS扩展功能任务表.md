## 范围与实现约束

1. 两处效果共用同一套配置、渲染及成片输出管线，不实现两套编辑器逻辑。优先复用 commonMain 中 filter/frame/effects 规则；Apple 仅实现图片、字体、文件和系统适配。
2. 遥控、监看、录像复用现有相机会话与命令串行通道；GPS 使用独立 BLE 通道，但统一设备身份与生命周期协调。禁止另建竞争的相机连接、目录或传输队列。
3. Android 功能、默认值、USB/AP/STA 行为不变，不升级依赖或重排工程来顺带实现本轮。部分效果 UI、监看图像统计仍耦合 Android；若需共享提取，先锁定基线、列出最小宿主接线变更再实施。不承诺“绝不改 Android 文件”，要求“不能改变 Android 功能”。
4. 会员、购买、支付、权益服务器和会员限额策略仍不实现。免费水印、监看时长等权益相关规则须在 X01 明确接口与当前语义，不擅自删除限制、解锁权益或改 Android/shared 策略；若 iOS 开放规则缺用户决定，单列待决项，不凭空选择。
5. 不恢复 iOS USB Host 或承诺无限后台传输/GPS。后台边界需 Apple 实测；权限只在用户操作对应功能时申请。已有照片 GPS 元数据读取、相机视频文件传输不是新增待做功能。
6. 对照 Android 实际能力，不新增未要求功能。像素核可精确对比；字体栅格化、色彩管理、编码器差异须有金样和明确容差，不能承诺所有平台输出文件逐字节相同。原片保留仍要求不变。
7. 现有 Swift/Native 尚未在 Mac 编译。可以继续在 Windows 写代码，但建议扩展前先完成原 M01/M02 的 Apple 编译基线，减少大批未验证代码累积；不把这条建议算作已验收或新增硬性授权。
