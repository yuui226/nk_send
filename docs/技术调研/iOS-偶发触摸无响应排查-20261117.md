# iOS 偶发触摸无响应排查

## 2026-11-18 当前进展

标准 iOS 17.2 / iPhone 13 已实际复现并修正触摸兼容问题。最终从正式工作区构建的同一测试产品，在 iOS 17.2 和 iOS 26.5 各通过 42 项定向测试，包括每台 25 项模型／宿主测试和 17 项真实触摸 UI 测试。两次均为 TEST EXECUTE SUCCEEDED / exit 0，日志为 `/tmp/ztransfer-ios172-confirmed-20261118.log`、`/tmp/ztransfer-ios265-confirmed-20261118.log`，保留同名 xcresult。源码调查、修复和双系统模拟器回归 3/3。用户 iOS 17.1.2 真机与实际 USB 相机待现场回测。以下早期记录保留用于追溯。

- 连接帮助触点实际落在 `PlatformViewHost<PlatformViewRepresentableAdaptor<PopupDragBoundary>>`。内部 UIKit 视图禁用交互后，iOS 17 的 SwiftUI 包装层仍可命中。组件现统一对包装层关闭命中，原生翻页器仍使用其区域注册判断模态屏障。
- 照片纯展示的图片包装也明确关闭 SwiftUI 命中。旧系统仍丢失 SwiftUI 独占长按与点击组合的短按回调。真实 RootView 中完全移除窗口反馈观察器后，短按仍失败。最终使用 UIKit 点击识别器等待长按识别器失败，长按仅在 began 触发，点击仅在 ended 触发。保留预览 200ms、传输 250ms、移动容差 12pt、离场输入门禁和辅助功能激活。
- 仅调整 Genie 外层命中、窗口反馈观察器准入或同时识别的对照均未修复复现，已经全部撤回。尝试同时观察 SwiftUI 长按和点击曾恢复预览，但两个滚动测试的日期行始终停在 98.4pt，该方案也已撤回。最终原生识别器方案已通过真实网格位移、滚动取消、长按时机及互斥验证。
- Read/Clear 的 44pt 矩形命中区域移入测试按钮标签，修正旧系统中夹具按钮未实际执行、trace 为空的问题。主题测试改为隔离持久化 suite 写入 LIQUID_GLASS，避免启动参数域持续覆盖写入造成假切换失败。旧系统毛玻璃回退和四项主题循环已实际通过。

8 项覆盖真实连接帮助、设置关开、模拟相机交接、普通照片轻触、普通及合集长按预览、反向轻触预览与长按传输、长按后的下一次点击、两种模式的滚动取消及网格位移、队列与监看往返、旧主题值迁移和选项循环。生产窗口观察器与触摸记录器保持原实现，所有临时诊断代码均留在隔离实验期间，最终产品中已撤除。行为依据为安卓 FileListScreen 的 combinedClickable、AnchorPopup 的模态规则和此前获准的 iOS 长按时长。

## 源码依据

- Android `HomeScreen.kt` 的连接卡片由图层呼吸驱动，USB 通过设备发现自动连接。iOS `ConnectionMethodCard` 用 `NativeAttentionHost` 承载卡片，呼吸由 Core Animation 执行。持续呼吸仅说明渲染动画存活，不能单凭它断言主线程或触摸派发正常。
- `ZTransferButtonSkin.defaultPreset` 在 iOS 26 起选择液态玻璃，旧系统选择毛玻璃。`init(storedValue:)` 和 `normalizedSkinPreset` 都将旧系统上的液态玻璃存储值解析为毛玻璃。`SettingsView.buttonSkinOptions` 只在 iOS 26 起加入液态玻璃，`visibleSkinPreset` 对非法或不可用选项显示毛玻璃。用户提出的主题兼容预期已有实现。
- 按钮材质 `ZTransferButtonMaterialSurface` 明确关闭命中测试。按钮通过原生 `Button` 触发业务动作，按压反馈的窗口观察器不取消、不延迟触摸，并禁止阻止其他识别器。源码检查未发现主题分支直接锁定业务操作。发现窗口观察器原本缺少触摸准入代理，对无关触点也进入 possible 周期，已收窄到反馈目标内。
- 连接页处于原生 `WorkspacePagingController` 的滚动容器内，卡片又有嵌套 `UIHostingController`。照片页网格使用 SwiftUI ScrollView 与互斥点击／长按，顶栏为滚动区域外的兄弟节点。这使滚动容器与手势兼容成为值得复现的方向，但当前证据不足以确认它就是现场原因。
- `RootView` 在文件夹书签恢复期间会关闭整个内容的命中测试，发现服务也等待恢复。文档提供者恢复在后台工作，系统调用没有明确完成时限。该路径值得专项检验，但持续未恢复与本次已成功进入照片列表的现象无法直接对应。
- 照片页在队列、监看转场期间关闭退出页输入，`WorkspacePageClock` 在动画结束、离页和后台收束状态。当前回归会覆盖队列往返后的照片交互，不能据此断言所有系统的所有中断均已覆盖。
- Android `BurstCollectionCell` 明确规定合集图片区轻触无动作，长按预览，底部按钮分别入队和展开。iOS `BurstThumbnailView` 与此一致。需要现场区分普通照片和叠放合集，不能把该既定行为直接当作故障根因。

Apple 的 iOS 18 发布说明记录过 SwiftUI 与 UIViewRepresentable 的触摸／手势修复。它只能支持跨版本验证的必要性，不能证明 Z传遇到了同一个系统问题。

来源为 <https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-18-release-notes>。

## 本轮改动

1. 增加 `ButtonInteractionUITests.testRealConnectionToPhotoListWithFrostedGlass`，从真实 RootView 启动，检查呼吸卡片里的连接帮助、设置开关、模拟连接交接、队列往返及普通照片预览。相机目录和传输使用现有 Debug 模拟入口，触摸通过 XCTest 真实注入。
2. 修正 `PhotoListAdmissionHarness`，显式选择文件夹保存。它原本创建合成本地文件与模拟文件夹授权，默认目的地改为相册后，既有队列测试错误地开始依赖 Photos 授权和合成文件导入。此修正属于测试环境。
3. `ZTransferButtonScrollContext.PressObserver` 加入准入代理，只接收命中现有反馈 probe 的触摸，并将 `allowedPressTypes` 显式设为空。它的职责是触摸反馈，没有硬件按键处理。Apple iOS 17 UIKit 发布说明记录了 `pressesBegan` 默认失败行为的变化，并说明未到终态的自定义识别器可能阻止依赖图复位。该说明特别指出 tvOS Select 按键场景，因此这里只据此明确输入作用域，不能将它当作 iPhone 现场因果的证明。新增定向断言验证准入、按键排除与不取消／延迟触摸。

第 3 项为防御性兼容修正，现场故障的因果验证仍待完成。当前无法对现场问题作出已消除的结论。

来源为 <https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-17-release-notes.md> 和 <https://developer.apple.com/documentation/uikit/uigesturerecognizer/allowedpresstypes>。
