# 计算机 Wi-Fi 客户端与智能设备 STA 模式

> 更新日期：2026-08-25  
> 当前状态：Z30 的“连接到计算机”路径已完成真机配对、照片列表、预览与原文件传输验证。本文用于区分它与新机型“连接至智能设备 → Wi-Fi连接（STA mode）”，并作为后续协议研究入口。

## 一、先说结论

“STA”只描述相机在 Wi-Fi 网络中的角色：相机作为客户端加入手机热点或路由器。它不代表相机上层连接的一定是手机应用。

尼康目前至少存在两条使用相同 Wi-Fi 拓扑、但配对身份和应用协议不同的路径：

```text
相机作为 Wi-Fi 客户端加入热点或路由器
├─ 连接到计算机
│  └─ 计算机配置文件 + PTP/IP（ZTransfer 当前实现）
└─ 连接至智能设备
   └─ Wi-Fi连接（STA mode）+ SnapBridge（尚未实现）
```

因此：

- 当前功能不是仅供老机型使用的临时绕路。新机型同样正式支持“连接到计算机 → Wi-Fi客户端模式”。
- 新机型“连接至智能设备 → Wi-Fi连接（STA mode）”是另一条智能设备连接路径，不能因为网络拓扑相同就视为与当前实现兼容。
- 在真正完成智能设备 STA 的发现、认证、配对和 PTP 能力验证前，不应使用它替换当前计算机配对实现。

## 二、两条路径的准确区别

| 对比项 | 计算机 Wi-Fi 客户端 | 智能设备 STA |
|---|---|---|
| Wi-Fi 拓扑 | 相机加入手机热点或路由器 | 相机加入手机热点或路由器 |
| Z30 菜单 | 设置菜单 → 连接到计算机 → 网络设定 | 不提供此智能设备 STA 入口 |
| 新机型菜单 | 网络菜单 → 连接到计算机 → 网络设定 → 创建配置文件 → 连接至现有网络 | 网络菜单 → 连接至智能设备 → Wi-Fi连接（STA mode） |
| 官方对端 | Wireless Transmitter Utility、NX Tether 等计算机软件 | SnapBridge/尼康影速传等智能设备应用 |
| 配置文件 | 计算机连接配置文件 | 智能设备连接配置文件 |
| 当前 ZTransfer 身份 | `PAIRED_COMPUTER` | 尚未实现和验证 |
| 当前 ZTransfer 支持 | 已支持 | 不支持 |

同一个热点只能解决 IP 层互通，不能消除配对身份、服务发现、会话初始化和操作码权限的差别。两个菜单产生的配置文件也不应假设可以互换。

## 三、ZTransfer 当前实现

代码内部仍使用 `WirelessMode.STA` 表示当前的“计算机 Wi-Fi 客户端”连接分支，这是实现名称，不等于尼康“连接至智能设备”的 STA 菜单。

当前 Z30 真机已经验证：

- 相机可以连接手机个人热点或路由器，并保存计算机网络配置文件。
- 首次连接可完成配对；后续可从相机选择已保存配置，无需重新输入热点密码。
- PTP/IP 命令通道、事件通道与会话可以建立。
- 可以读取存储卡对象句柄、生成照片列表、识别原文件名和拍摄日期。
- JPG、NEF 和视频可以加入队列并传输原文件。
- JPG 可从 MPF 独立预览图生成大图预览；NEF 可读取内嵌 JPEG 预览。
- 缩略图缓存、渐进式列表、断线重连和双卡筛选均有 STA 独立分支。

### Z30 的协议特征

Z30 在计算机配对会话中有一组需要兼容的行为：

- `GetObjectHandles` 可用，但 `GetObjectInfo` 对样本句柄返回 `0x200F`。
- `GetPartialObject`/直接对象读取可用，因此可以绕开 `GetObjectInfo` 完成目录、预览和传输。
- `GetFhdPicture (0x920F)` 与 `GetLargeThumb (0x90C4)` 返回 `0x200F`，不能用原图冒充 FHD。
- JPG 大图预览使用文件 MPF 索引中的独立 JPEG；NEF 使用文件内部 IFD/扫描得到的 JPEG 范围。
- 元数据、文件头、缩略图和预览范围均需缓存，避免复杂网络下重复探测。

这些兼容逻辑只属于 STA/计算机配对分支，不应进入 AP 或 USB 热路径。

## 四、哪个更快、哪个能力更强

### 可以确定的部分

- 两条路径若使用同一台相机、同一频段和同一热点，原文件持续传输的物理上限接近；名称中的“原生 STA”不会自动提高无线带宽。
- 实际速度主要由 2.4/5 GHz、相机无线芯片、热点质量、网络拥塞及相机 PTP 实现决定。
- 当前计算机模式已经能自由选择并传输 JPG、NEF 和视频原文件，这是 ZTransfer 的核心优势。

### 尚待真机确认的推测

- 智能设备 STA 可能提供更适合手机的发现、配对、重连、缩略图和元数据接口，因此首屏速度与连接体验可能更好。
- 它也可能限制 RAW、视频、原始尺寸或部分遥控能力。SnapBridge 官方帮助显示，这些能力会随机型和下载流程变化，不能假设智能设备 STA 一定更开放。
- 智能设备 STA 是否仍暴露标准 PTP/IP、是否复用 AP 模式的操作码、能否同时满足相册浏览与监看，均需抓包和真机验证。

结论：智能设备 STA 更可能“更适合手机”，但目前没有证据证明它在原图吞吐或可访问文件类型上全面强于计算机模式。

## 五、命名约定

为避免与尼康新机型的“Wi-Fi连接（STA mode）”菜单混淆，建议区分内部名称与用户名称：

| 场景 | 建议名称 |
|---|---|
| 代码内部现有分支 | `STA` / `PAIRED_COMPUTER`，暂不做无收益的全量重命名 |
| 当前用户入口 | “共享网络”或“计算机配对” |
| 新机型未来入口 | “智能设备 STA” |
| AP 用户入口 | “相机热点” |

帮助文案必须引导当前用户进入“连接到计算机”，不能引导至“连接至智能设备 → Wi-Fi连接（STA mode）”。

## 六、未来研究智能设备 STA 的验证清单

在取得支持机型后，将智能设备 STA 作为独立后端研究，不直接改写当前 STA、AP 或 USB 实现。

1. 记录机型、固件、菜单路径、热点频段以及是否要求 SnapBridge 先配对。
2. 抓取服务发现信息：mDNS 服务、TCP/UDP 端口、广播内容和相机 IP。
3. 对比 AP、计算机客户端、智能设备 STA 三种模式的初始化身份、GUID、认证数据和事件通道。
4. 记录 `GetDeviceInfo` 广告的操作码，并逐项验证：
   - 存储卡与对象枚举；
   - 文件名、日期、大小和双卡信息；
   - 缩略图、FHD/大图预览；
   - JPG、RAW、视频原文件读取；
   - 实时取景、遥控和事件；
   - 断线恢复及配置文件持久化。
5. 测量冷启动首屏、缓存首屏、100 张缩略图、FHD 预览和 1 GB 文件的耗时与吞吐。
6. 若能力足够，再新增独立连接类型和机型能力探测；不得让失败探测回落并污染 AP/USB 状态。

### 建议的采用标准

只有同时满足以下条件，智能设备 STA 才适合成为 ZTransfer 正式入口：

- 能由 App 主动浏览相机文件，而不是只能从相机端标记上传；
- 支持当前产品需要的 JPG、NEF、视频和原文件传输；
- 支持可靠的缩略图、日期、文件名和大图预览；
- 配对与重连至少不弱于当前计算机配置文件；
- 不降低监看、遥控、队列传输和已传判定的能力；
- 可以按机型安全降级，且完全不影响 AP 与 USB。
