# iOS 原生复刻总进度表

这份文档是后续唯一的进度跟踪入口。旧文档 [iOS 原生复刻计划与任务清单](./iOS原生复刻计划与任务清单.md) 只保留安卓源码依据、详细设计和历史记录；新功能必须先在旧文档找到安卓依据，再在本表登记实现和验证。

## 统计口径

- **已完成**：安卓源码对照、iOS 实现、正常/异常/取消/恢复路径和自动化或模拟器证据都闭环；真机实测由任务 60/61 统一记录。
- **进行中**：已有局部代码或测试，但本任务仍有明确缺口，不能算完成。
- **待开始**：还没有形成可验收的 iOS 闭环。
- 每完成一个任务或强相关的一组任务，更新状态、证据、提交和下一步；不把一次构建或一段局部修复计成完成。

## 状态转移规则

- **待开始 → 进行中**：已经找到安卓入口、状态/错误分支和动画依据，并开始建立对应的 iOS 代码路径。
- **进行中 → 已完成**：安卓依据、iOS 正常路径、错误/取消/恢复路径、动画/手势、持久化（如适用）和自动化/模拟器验证全部闭环；提交号和验证命令必须登记。
- **进行中 → 待开始**：审计确认现有代码只是误接接口、占位或没有可观察行为时，撤回到待开始，不保留虚假的“进度”。
- **已完成不得因真机未测回退**：真机设备操作统一记录在 19、60、61；若真机暴露代码缺口，则新建修复项并回退受影响的代码任务。
- **不使用主观百分比**：未闭环的局部代码只计入“进行中”，不折算成 0.3 项或“完成 80%”。

## 每次更新格式

每次推进只写下面五项，避免再次堆积漫无目的的过程记录：

1. **本次关闭的任务**：列出任务编号和名称；没有关闭就写“未关闭任务”。
2. **安卓依据**：文件、函数、资源或测试样本位置。
3. **iOS 改动**：实际文件和用户可观察结果。
4. **验证证据**：测试命令/结果、模拟器交互；真机结果单独写到 19、60、61。
5. **剩余阻塞**：只写能阻止该任务勾选的具体代码缺口，并给出下一步动作。

## 更新规则

- 每次提交只推进本表明确的一项或一个强相关小组，并填写提交号。
- 只要“未闭环项”仍有明确代码缺口，状态保持进行中；“已构建”或“已安装”不能单独改变状态。
- 真机拔插和 BLE/GPS 设备操作由用户在任务 60/61 集中验收；这些是最终回归记录，不是代码复刻的前置条件，也不要求额外提供相机日志样本。
