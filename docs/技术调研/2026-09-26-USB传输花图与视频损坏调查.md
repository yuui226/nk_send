# USB 传输花图与视频损坏调查

## 状态与结论边界

调查中；没有修改生产传输代码。用户报告：有线批量传照片后部分照片错位，视频局部花屏；读卡器查看正常；手机为华为 nova16，保存到内置存储。App 版本、系统版本、断线/重试经历尚不明确。

已证实附件主图存在可疑长零段，并已复现“同长度坏数据通过当前接收校验”。尚未在真实 USB 设备上复现零段产生过程，不能据此认定 App、华为系统、USB 驱动或相机 USB 固件是哪一方产生了零字节。视频未收到文件，不能把照片的具体损坏偏移推广到视频。

## 附件二进制证据

- 文件大小 10,173,197 字节；主图 5568×3712。
- EXIF：NIKON CORPORATION / NIKON Z50_2 / Ver.01.10，Orientation=1。
- 文件被 Pillow 识别为包含三张 JPEG 的 MPO：主图、640×424 预览、1620×1080 预览。这是容器中的独立图像，不是“三块错拼”的三个分块。
- 主图 EOI 在文件偏移 8,865,820，主 JPEG 长度 8,865,822，与 MP 索引声明一致。不能因此认定全文件与相机原文件等长，尚缺读卡器版本比较。
- 主图压缩扫描内部，偏移 `[3,145,728, 3,420,160)`（`[0x300000, 0x343000)`）是连续 274,432 字节（268 KiB）的 `00`。起点为 3 MiB，起止均 4 KiB 对齐；这只是定位线索，不足以证明具体写入层故障。
- 主图可被解码，但画面错位、出现灰带；JPEG 能打开并不代表内容完整。
- 从附件原始字节提取 1620×1080 内嵌预览并目视检查，人物和黑板位置正常。提取偏移 9,078,272，长度 1,094,925。没有把参考图重新编码再做二进制分析。
- 文件其他位置也存在 JPEG 附图头部填充零段，因此不能简单把“任何长零段”当作所有文件类型通用的失败标准。

推断：主图熵编码数据受损可以表现为解码后的块状错位，并不要求 App 真把三块图像重新排列。当前证据更支持内容数据异常，而不是单纯 Compose 绘制问题。读卡器正常是用户反馈，仍需要同一张原文件逐字节对照才能确认哪些字节被改动。

## 当前代码审查

### 暂未发现的常见错误

- `UsbPtpConnection.receiveDataTo` 顺序接收并同步调用 onChunk；NikonCamera 的 writeChunk 同步写 BufferedOutputStream，没有把共享 byte[] 交给后台队列后提前复用。
- USB 请求先 requestWait 完成，再按 ByteBuffer.position 取实际长度，读取余量保存在独立缓冲中。没有把申请长度直接当作实收长度。
- PTP 事务检查 transaction ID；数据相位与响应均消费。下载持有 CameraIoGate 的通道锁，预览/EXIF 不在一个数据事务中插入。
- USB 数据事务异常时关闭连接，避免从残留数据中继续解析下一事务。
- 正常 USB 小于等于 128 MiB、无续传的文件走 GetObject 全量读；该附件约 9.7 MiB，通常不走应用层 64 MiB 分块路径。因而不能把照片现象直接归因于“大文件分块排序”。
- 分块路径按实收长度推进，并校验最终字节数；旧的续传降级错位、按请求量跳过短读等问题在当前代码中已有防护。历史提交 e9632227 不能作为当前根因。

### 确认存在的校验缺口

1. **长度相同的内容异常无法识别。** 接收器检查容器结构、事务号、长度和响应码，没有内容校验；正常保存也没有与相机原数据或读取阶段摘要进行落盘回读比较。若中途一段被替换成等长零字节，仍可显示成功。此点已有故障注入测试。
2. **全量读取未再与已知 ObjectInfo 大小交叉核对。** NikonCamera.downloadToFile 全量路径比较实收与数据容器声明长度，却没有在 effectiveSize 已知时再比较它。若相机数据容器本身声明了错误的较短长度且返回成功，当前会放行。不是本附件根因的证据。
3. **完整大小半成品直接晋升正式文件。** TransferViewModel 在 partSize 等于对象大小时直接改名；先前“数据写完但响应失败/缺失”等路径保留的半成品，重试也会走此分支。只有长度证据，没有成功事务凭据或内容验证。会保留已有坏内容，但不能解释第一次是谁写坏。
4. **华为复制回退只核对字节数。** renameBroken 的既有处理针对改名失败，不能证明改名会篡改数据。copyAsFallback 仅校验复制总量，无法检测等长零段。必须记录本次实际走 rename 还是 full_copy 才能进一步定位。

## 已完成的可重复验证

新增 `UsbPayloadIntegrityInvestigationTest`，只用于调查：利用 JVM 反射创建无设备连接的实例，将合成 PTP 字节放入已接收缓冲，调用真实 receiveDataTo 解析/输出实现。

- 输入完整已知字节流，跨多次 256 KiB 输出回调：输出顺序与内容一致。
- 输入 6 MiB 数据，其中 3 MiB 起的 268 KiB 被人为置零，保持容器长度、事务号、成功响应不变：输出保留零段，responseCode=OK，written=expected，当前检查不报错。

**这个实验复现的是检测缺口，不是 USB/系统制造零段的原因；它没有覆盖真实 UsbRequest、DocumentsProvider 或手机存储。**

运行结果：上述 2 个测试及 CameraIoGateTest 的 10 个测试通过。没有连接用户手机、没有安装 APK，没有改动正常传输逻辑。

## 下一步优先顺序

1. 获取读卡器导出的同一张原始 JPG，与现有附件逐字节比较。先确认是否仅 `[0x300000,0x343000)` 不同、总长是否相同，以及其他差异范围。保留原始文件，避免聊天工具压缩或重新编码。
2. 同一原片在该手机上重新 USB 下载到干净测试目录，不复用已有文件/半成品。记录是否每次损坏、坏段偏移是否固定，以及本次 App/系统版本和保存模式。固定偏移与随机偏移只作进一步定位线索。
3. 针对测试包增加分阶段摘要：USB 回调收到的字节摘要、关闭后的临时文件回读摘要、改名/复制后的正式文件摘要。先限定诊断模式，避免给正常用户增加整文件回读开销。摘要不上传图像内容。
   - USB 接收摘要正确、临时文件不一致：定位写盘/Provider。
   - 临时文件正确、正式文件不一致：定位复制/改名后路径。
   - USB 接收数据就与读卡器原文件不同：继续查相机 USB 输出、Android USB 接收、驱动及链路；不能仅凭这个结果断言硬件责任。
4. 独立加固已确认的长度交叉校验、完整半成品晋升规则；不要用重编码、重新排列图片或禁止全部华为用户传输来掩盖根因。

## 官方参考

- Android UsbRequest：新 queue(ByteBuffer) 接口在 requestWait 返回前缓冲状态未定义；成功后 position 按实收字节数增加。当前代码在等待完成后取 position，与该契约一致。
  https://developer.android.com/reference/android/hardware/usb/UsbRequest
- Android UsbDeviceConnection：requestWait 可能返回不同端点的完成请求；当前代码单独处理 interrupt request。
  https://developer.android.com/reference/android/hardware/usb/UsbDeviceConnection

## 临时诊断实现

按用户要求直接在主源码中加入临时诊断，Release 同样启用，不设开关。

- 实际 USB 下载开始时，在用户选择的传输根目录新建 `ZTransfer_USB_时间戳_任务号.txt`；不放入应用私有目录。
- 流式记录 App 收到的 SHA-256、字节数及至少 64 KiB 的连续零段（最多列出 32 段，并保留总数）；不保存媒体内容到 TXT。
- 关闭输出流后回读临时文件，改名/复制后回读最终原图，逐阶段记录摘要是否一致。
- 记录 App/手机/系统/相机型号、源文件名、预期大小、续传偏移、保存方式与错误结果。
- 续传仅比较新传后缀，明确标注旧前缀未经验证。命中已存在文件、完整半成品直接改名的任务也生成 TXT，明确标记 NO_USB_DOWNLOAD；只回读现有文件，不虚构接收摘要。复测建议使用新建空目录。
- 裁切任务也记录未改动原片的接收/私有临时文件/最终原图；不把裁切后的文件与未裁切摘要误比较。
- 诊断不更改任务成功/失败判定，不自动重传。每个实际文件增加两次本地回读，因此此临时包可能较慢；不重复向相机请求完整文件。
- 报告在开始、各检查点及正常/异常结束时落盘。强制杀进程时可能只有此前检查点，报告每次写入后回读核对，写入失败记入系统日志并提示用户更换传输目录；不保证断电情况下完整报告。输出流 flush/close 抛错时也尝试回读临时文件，保留异常证据。
- Release 的 `minifyReleaseWithR8` 通过（包含 Release 编译与混淆）；摘要 2 项、USB 故障注入 2 项、CameraIoGate 10 项测试全部通过。尚未打包/安装或在华为真机验证目录提供器。
