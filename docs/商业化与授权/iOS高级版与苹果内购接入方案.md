## 1. 已确认的产品方向

- iOS 复刻安卓免费版限制、高级版权益及对应业务判断；支付与授权改为苹果内购。
- 一年高级版采用 **年度自动续期订阅**，用户可随时取消后续自动续费。取消续费不等于立即失去已经付费的剩余期限，也不等于退款。
- **人民币目标价暂定年费 ¥39.99／年、永久 ¥99.99。** 具体可选档位及其他地区价格待 App Store Connect 核对／配置；若不支持目标金额，不能擅自取相近价格作为用户已确认售价。实际 UI 和付款始终读取苹果商品价格。
- **保留年费的月均价展示。** 以苹果当前年度商品的 `price / 12` 计算，按该商品的币种与本地化格式显示；真实年度总价和每年扣费一次的说明必须同时清楚展示，月均价不暗示按月购买或扣费。不用安卓兜底价，不把新客月均价当作老用户实际下一期扣费金额。
- 永久高级版采用 **非消耗型内购**，一次购买、无订阅到期日；退款或撤销后需要重新判断可用权益。
- **退款后的处理复用免费版规则。** 由苹果处理退款，App 收到有效权益撤销后重新聚合；没有其他有效高级权益时，派生的 `isPro` 变为 `false`。不新增自有退款流程或独立申请按钮，不手动清标记冒充退款；永久退款但年费仍有效时仍是高级版。已入队任务水印按下面的快照规则保留。
- **提醒已确认精简：**成功传输后剩余 5、1 次时提示，当天去重；正常自动续费不催用户再买。免费 25 次额度不变。
- **已入队水印不变，用户明确规则优先：**相机传输后的派生图与本地批次都保留入队时已按权限计算的生效水印，后续升级、到期、退款或编辑设置均不回写；不能在轮到渲染时根据全局 `isPro` 再换成另一水印。
- 使用原生 StoreKit 2。当前需求可不自建支付服务器、激活服务器、账户系统或授权数据库；苹果保存交易，App 验证交易并落实功能权限。
- **iOS 不再使用自有激活码和授权设备码。** 权益属于购买所用的 Apple 账户（“媒体与购买项目”，可能与 iCloud 账户不同），不绑定某台设备；同账户换机／重装通过苹果恢复购买。App 不新增自有登录或“通过 Apple 登录”作为购买前置条件，也不把 `appAccountToken` 当成苹果账户 ID。
- **支持苹果优惠码：免费赠送与付费折扣。** 在 App Store Connect 配置，用户通过苹果兑换／按优惠价确认付款，App 验证交易后授予对应权益；不接收安卓码直接解锁。付费折扣是预设优惠价格，不是 App 自行对 `purchase()` 传一个减免金额；具体金额、期限和资格按活动另定，订阅优惠后的续费规则明确展示。兑换不自动取消原有年费。详见配套审查第 4 节。
- **两种商品均不开家庭共享。** 同一购买账户自己的受支持设备恢复不受影响；当前不考虑安卓付费用户迁移或补偿方案。
- **扣款宽限期启用 16 天，适用于已付费订阅续订。** 宽限期内保留高级功能；按苹果实际状态／截止时间判断，不在本地无条件给每个到期用户加 16 天。正式 App Store Connect 配置与沙盒加速环境均待验证。
- 开发阶段使用 StoreKit 本地测试及苹果沙盒，正式上架使用正式内购环境；测试购买不得作为正式环境付费凭证。
- 用户已接受年费转永久的替代流程：购买前说明不会自动取消，永久交付后引导到苹果管理页由用户取消旧年费，持续显示真实续订状态；不得声称自动取消，详见第 3 节。

## 2. 安卓功能基线

当前实现依据：

- `app/src/main/java/com/ztransfer/license/LicenseManager.kt`：免费额度、成功计数、监看时间和授权状态。
- `app/src/main/java/com/ztransfer/ui/screen/LicenseDialogs.kt`：免费／年费／永久的功能对比。
- `app/src/main/java/com/ztransfer/viewmodel/TransferViewModel.kt`：实际传输限制及完成记账。
- `RemoteScreen.kt`、`SettingsScreen.kt`、`LocalPhotoEffectsOverlay.kt`：监看、录制、自定义水印门控。
- `app/src/test/java/com/ztransfer/ui/screen/LicenseDialogPolicyTest.kt`：安卓购买／激活入口在相机网络下的行为；苹果支付需要单独适配，不能移植激活服务器探测。

| 功能 | 免费版 | 年费／永久高级版 |
|---|---|---|
| 完成传输数量 | 每个自然日 25 个，照片／视频／RAW 共用额度 | 不设此额度 |
| 单文件大小 | 400 × 1024 × 1024 字节；沿用安卓“400MB”文案 | 不设此限制 |
| 远程监看 | 每天累计 3 分钟 | 不限时 |
| 端侧录制 | 不开放 | 开放 |
| 效果图生成、滤镜、边框 | 开放 | 开放 |
| 水印 | 默认水印 | 自定义水印 |

- 只有实际传输成功才计数；入队、失败、取消、已存在跳过不扣次数。
- 免费版允许批量入队，队列实际开始任务时执行数量／大小检查，不能额外禁止批量操作。
- 监看按实际使用累计，退出停止计时，跨自然日重新记账；两类额度独立持久化。
- 免费额度是 App 的业务数据，苹果不负责统计；本方案不承诺跨设备统一免费额度。
- 高级版连接成功效果等其他 `isPro` 分支也要审查迁移，不能只接购买 UI。开发时继续逐处对照安卓源码和测试。
- `激活与付费设计.md` 是历史设计，其中“入队计数”“禁止免费批量”等旧规则不能作为本次基线。

### 实际执行细节，不能只照对比表实现

- **传输检查顺序：**先处理“已存在跳过”，再检查免费数量／大小。达到限制的任务标记失败并显示对应原因，队列继续处理后续任务，不清空队列。解锁后沿用重试入口，不擅自自动重传全部失败项。
- **唯一计数点：**安卓在正式文件落盘并完成改名／复制后计数；效果图后处理不再多扣一次。已存在跳过和现有“续传改名捷径”不经过该计数点，迁移时不能按所有 `COMPLETED` 状态变更一概加一。重复完成回调也不能重复记账。
- **监看起算：**参数加载完成且监看首帧显示（`onReady`）后才启动计时，加载等待不扣时长。安卓按秒累计；用尽后退出监看，在返回的照片列表提示，再次进入时直接提示额度已用尽。
- **监看持久化：**不能只在正常退出时结算。按安卓每秒累计保存已消费时长，退出／停止时收尾；系统挂起不保证退出回调。计时用单调经过时间，换日用本地日历；高级状态不启动免费倒计时，计时发布只影响余额相关 UI，不触发整页或交易刷新。进程中断时的持久化损失边界必须实际验证，不能凭调用保存接口就承诺零丢失。
- **水印实际执行：**默认水印依照安卓装饰开关与 `freeEditionPhotoFrameWatermark()` 规则使用，不代表所有免费输出都强加水印。设置编辑、本地工作台、图片导入、预览和最终渲染都要检查权限，不能只把控件置灰。
- **授权变化时的任务：**传输数量／大小限制仍在任务开始前检查，不逐块下载验权或掐断文件写入。用户确认录制安全停止／保存、已入队水印不变；录制收尾与监看免费余额衔接按配套 P04 验证。水印快照不是冻结全局高级资格，不豁免后续传输任务的数量／大小限制，也不允许新的高级操作。不得把“回到免费”实现成删除原文件或配置。
- **水印快照生命周期：**相机任务在正式入队时、本地批次在点击生成建立任务时，用当时权限与配置确定生效水印；查重、执行和原任务重试均使用同一快照，不因后处理稍后才建子任务而重新采样权限。新建／重新入队的新任务才使用当前权限。图片水印的素材引用也须保持不变，避免同路径素材被编辑覆盖或在旧任务完成前被清理；可复用不可变素材，无需为每张照片复制一份大图。
- **本地额度范围：**按设备本地自然日计账，不与 Apple 账户共享；升级付费不自动清空已有免费计数，回到免费时读取当天账本。卸载重装、改时钟／时区等边界需测试和说明，不宣称具有服务器级防绕过能力。

进一步代码审查发现：安卓监看页面剩余时间只在进入时初始化，运行中降级／跨日可能沿用旧值；麦克风授权返回后没有再次检查高级权限。安卓相机派生图在实际渲染前重新取权限，本地批次使用生成时快照；**iOS 已按用户最新要求统一为已入队水印不变，明确不复刻安卓相机派生图的执行前换水印行为**。具体代码事实和用户覆盖规则见配套审查第 5 节。

## 3. 年费用户购买永久版：平台限制与已确认流程

### 已核实的接口边界

普通 StoreKit 2 的年度订阅与非消耗型永久商品是两笔独立购买。永久商品不属于自动续期订阅组，不能依靠组内升级／降级自动替换年费，也不能承诺自动退回剩余年费。

当前选用的普通 StoreKit 2 方案没有让 App 直接替用户关闭续订的接口。`showManageSubscriptions(in:)`／`manageSubscriptionsSheet` 打开苹果系统管理页，由用户确认取消；接口返回只表示管理页结束，不能据此认定取消成功。必须刷新并读取经过验证的续订信息，例如 `willAutoRenew`。

苹果另有 Advanced Commerce API 的 `Cancel a Subscription` 服务端接口，需要满足适用资格、获得访问权限并签署附加协议。其资格主要面向大型内容目录、创作者订阅、订阅附加内容等场景，不能假定本项目已经符合条件；也不属于本次无自建后台的普通内购方案。若将来坚持全自动取消，需要独立评估资格及架构，不作为本轮实施前提。

依据：[管理订阅系统页](https://developer.apple.com/documentation/storekit/appstore/showmanagesubscriptions(in:))、[Advanced Commerce 资格及要求](https://developer.apple.com/in-app-purchase/advanced-commerce-api/)、[服务端取消接口](https://developer.apple.com/documentation/advancedcommerceapi/cancel-a-subscription)。

### 用户已确认的交互

1. 年费用户选永久版时，购买前明确说明：永久购买不会自动取消原年费，需要在苹果管理页关闭续订。
2. 永久购买通过苹果验证后立即开放永久权益，不把“已经取消年费”作为交付已付款权益的条件。
3. 若年费仍自动续订，提供直接打开苹果管理页的入口，帮助用户关闭；返回后刷新状态。
4. 仅在确认自动续费已关闭后移除提醒；用户未操作、状态未知或网络不可用时，不显示“已取消”。设置中继续保留管理入口和真实状态提示。
5. 永久权益优先于年费权益，但年费续订状态单独保存和展示，不能因“已永久”而隐藏仍在扣款的订阅。
6. 永久版退款后重新计算权益；若年费仍有效，可继续享有年费权限。任何情况下不自动替用户重新开启年费。

旧年度购买若处于待批准状态，可能在永久购买后才到账；跨设备购买同样可能改变组合。每次权益更新都要评估“永久＋年费续订”，不只在永久购买按钮成功时检查。

续订状态必须与对应年度商品／订阅组匹配。`willAutoRenew == false` 表示当前未开启下一期续订，不证明曾经扣款已退款，也不保证用户以后不会重新开启；App 回前台和管理页关闭后均要重新读取。单靠 `currentEntitlements` 看不到“用户是否取消了下一期续订”，也不能把没有新的交易回调视为状态没有变化。

此流程已由用户确认，用于替代最初的“自动取消”目标；购买后提供管理入口，设置保留仍续订的状态，不每次启动反复强弹管理页。

## 4. App 端授权与购买职责

建议集中实现购买管理与免费额度管理，各页面读取同一份权限状态，不各自联网查询。

- 商品：在 App Store Connect 创建年度订阅与永久非消耗商品。价格、币种、本地化展示价格及订阅周期从苹果读取，不照搬安卓服务器定价，不把“一年”硬编码为购买时间加 365 天。
- 购买：处理成功、用户取消、待批准、失败及重复点击；只为经过验证的有效交易发放权益，完成交付后结束交易。启动补处理未完成交易。
- 恢复：启动读取 `Transaction.currentEntitlements`，持续监听 `Transaction.updates`，回前台刷新；用户主动点击“恢复购买”时使用 `AppStore.sync()`。不在日常每次使用功能时强制认证。
- 年度状态：读取苹果提供的有效权益、到期／续费日期及续订信息。区分已取消续费但仍有效、已到期、扣款重试、宽限期和撤销，不能只用一个日期比较替代所有状态。App 持续运行跨过有效期时也要重新评估。
- 永久状态：由有效非消耗型交易决定；不以一个可随意修改的本地 `isPro = true` 作为永久授权依据。
- 多设备／重装：同一购买用的 Apple 账户恢复苹果权益。iOS 不采用安卓激活码换机顶替规则；跨平台权益互通不在本轮范围。
- UI：保留现有高级版介绍风格，支付确认交给苹果；设置提供权益状态、恢复购买、管理订阅。适配苹果购买方式的文案，不保留微信扫码、激活码、激活服务器等不适用说明。
- 已有永久权益时，不再引导重复购买年费；仍需保留第 3 节所述遗留年费续订状态。

依据：[StoreKit 2](https://developer.apple.com/storekit/)、[当前权益](https://developer.apple.com/documentation/storekit/transaction/currententitlements)、[恢复购买](https://developer.apple.com/documentation/storekit/appstore/sync())。

### 4.1 权益、续订与加载状态分开表示

界面所需状态至少包含：当前权益来源、已验证的交易／到期信息、年度续订状态、读取状态、购买操作状态。`isPro` 只作为最终派生结果，不能承担全部状态。

| 场景 | 高级功能与界面行为 |
|---|---|
| 首次读取尚未完成 | 权益相关入口显示正在确认；普通连接、浏览、筛选等不等待购买系统。不能先显示“已到期”或催重复购买，也不能无凭证直接开放高级功能；异常时结束转圈并提供重试 |
| 已成功确认无有效权益 | 使用免费规则；与网络失败、验证失败区分 |
| 年度有效且自动续订开启 | 开放高级功能，显示下一续费日期；开启续订不等于下一次扣款必然成功 |
| 年度有效但自动续订关闭 | 开放到本期结束，显示有效期；不立即降级 |
| 苹果确认处于扣款宽限期 | 宽限期内继续完整开放；用苹果的 `gracePeriodExpirationDate`，不能因原交易的到期日已过而误锁 |
| 仅处于扣款重试期、无有效宽限期 | 这笔订阅不提供权益；仍需检查是否存在永久或其他有效权益 |
| 年度已到期／已撤销 | 重新评估所有权益；没有其他有效权益才执行免费规则 |
| 永久有效，年费仍续订 | 提供永久功能，同时保留年费取消引导；两个事实并存 |
| 新购买待批准／用户取消／失败／无法验签 | 不因本次购买新增权益；已有有效权益不能被该失败结果清空 |
| 商品价格加载失败 | 显示商品暂不可用与重试，不以商品列表为空判定用户是免费版 |

启动、回前台、交易变更、管理订阅页返回及已知到期／宽限期边界触发统一重新评估，不依赖“苹果一定在到期那一刻回调”。后台挂起时不承诺计时器执行，恢复前台必须重新检查。支持的新系统可监听订阅状态更新，但仍保留最低系统版本的刷新路径。

依据：[订阅状态的权益规则](https://developer.apple.com/documentation/storekit/product/subscriptioninfo/renewalstate)、[宽限期截止时间](https://developer.apple.com/documentation/storekit/product/subscriptioninfo/renewalinfo/graceperiodexpirationdate)、[续订信息须验证](https://developer.apple.com/documentation/storekit/product/subscriptioninfo/status-swift.struct/renewalinfo)、[是否继续续订](https://developer.apple.com/documentation/storekit/product/subscriptioninfo/renewalinfo/willautorenew)。

### 4.2 交易处理与恢复的实施约束

- 应用级购买管理器持有唯一长期交易监听任务，不随购买弹窗关闭而销毁；购买入口互斥，防止多个页面同时发起付款。
- `purchase()` 成功结果、`Transaction.updates` 和未完成交易恢复统一进入处理流程。不能只监听 `updates` 而漏掉本机购买返回值，也不能只处理购买返回而漏掉外部续费／跨设备变更。
- 同一交易重复到达时幂等处理；不能重复播放购买成功反馈、叠加一年有效期或重置免费额度。交易 ID 可以用于幂等，但同一交易后续发生撤销时仍必须处理，不能因为“这个 ID 处理过”就忽略更新。
- 仅为已配置且匹配应用的商品、经过验证且提供当前权益的交易解锁。历史交易、已过期交易和被升级替代的交易不能因签名有效就重新发放权益；已处理的历史／撤销事件也需按 StoreKit 生命周期完成处理，不遗留无限重放。
- 验证与权益交付完成后再 `finish()`；付款后进程退出、关闭购买窗口、网络切换，重开 App 仍能恢复处理。禁止为清空队列而盲目结束未验证交易。
- 权益扫描完成后形成一致快照，不能扫描到一条就先清空其他商品。但**不得等待商品价格或无关续订详情后才交付已确认权益**；已验证的有效购买及时更新对应权益并完成交付，再协调后续聚合。商品加载、功能权益、年度管理信息各自表示加载／失败；年度信息暂不可用不妨碍已确认永久权益。多个异步刷新合并并带版本保护，不能让购买前旧结果覆盖刚解锁的状态，也不能在每次扫描开头先清空 `isPro`。
- 首选 StoreKit 已维护的设备端交易数据与验证结果；不另建自签授权 token、全量交易数据库或第二套 JWS 验签系统。内存保存已验证的有效依据，必要的展示缓存不能单独发放权限。若真机证明需增加跨启动缓存，再单独说明有效性、撤销和账户切换边界，不能先存一个永久布尔值兜底。
- 切换“媒体与购买项目”账户后依据 StoreKit 重新评估；不读取用户 Apple 账户邮箱／密码，不新建设备到苹果账户的映射。明确撤销或完成的有效权益重算必须生效，不能以“旧缓存曾经有效”为由永远拒绝降级。
- 恢复购买分别说明“已恢复有效权益”“已完成检查但无有效购买”“暂时无法确认”；恢复失败不引导已经付款的人再次付费。

首次启动立即注册 `Transaction.updates`，并读取当前权益。苹果说明启动监听会收到当时的未完成交易；显式 `Transaction.unfinished` 启动扫描可以保留作为恢复入口，但只执行一次并复用同一处理器，不在每次弹窗／前台变化时重复扫描或开第二个长期监听。`AppStore.sync()` 仅响应用户的恢复操作，不用作启动、回前台或网络恢复时的自动刷新。

年费和永久是状态型权益，无需为了幂等构建永久增长的“已处理订单表”。重复处理收敛到相同权益即可；新购庆祝与业务交付分开，有限的展示事件去重不能挡住同一交易的退款／撤销更新。`finish()` 不等待烟花播完、管理订阅操作完成或旧年费取消。

依据：[交易更新的交付路径](https://developer.apple.com/documentation/storekit/transaction/updates)、[启动恢复与监听示例](https://developer.apple.com/documentation/storekit/getting-started-with-in-app-purchases-using-storekit-views)。

## 5. 相机网络、离线与性能

- 已验证且仍有效的权益支持离线使用，连接相机 AP 后不能因为互联网暂时不可用就立即降级。
- 购买、恢复和同步最新续费记录需要网络。离线无法获知刚发生的续费或退款，不承诺实时获知；有效期已过且无法确认续费时应明确提示需要联网确认，不能自行生成新的有效期。
- 已确认启用苹果 16 天已付费续订宽限期；客户端仍需验证离线、跨到期和状态恢复，不擅自添加任何苹果未授予的额外赠送天数。
- 功能入口只读取本地已评估的权限状态；传输热路径、照片列表布局、动画逐帧回调不执行 StoreKit 请求或扫描交易历史。
- 统一来源不等于全部 UI 订阅整个购买管理器。权益变化、商品价格、支付进度、监看秒数分别发布，只通知相关视图；值未变化不重复发布。免费额度沿用现有单传输 worker 的顺序检查／记账，不为当前未存在的多文件并行下载预建额度预占、回滚或订单数据库。
- 免费额度检查放在安卓对应的业务节点，避免每张缩略图、每次重绘重复查询。
- 订阅信息刷新失败不等于苹果明确撤销权益。保留仍在有效期限内的已验证依据；已知期限已经结束时不能把旧缓存当成无限期授权。首次安装且无本地凭证、换账户、调整系统时钟、跨时区均需单独验证，不承诺纯客户端可防止所有篡改。
- 相机 AP 无外网时，应给出当前购买／恢复无法联网的说明与重试入口，不自动断开相机、不自动切换网络；有蜂窝互联网等可用路径时也不能仅根据“连了相机 Wi-Fi”就禁止付款。

## 6. 沙盒与上线准备

- Xcode 本地 `.storekit` 配置可离线模拟商品及交易，适合快速验证状态机，不等于真实苹果沙盒验证。
- 开发签名 App 与 TestFlight 使用苹果沙盒，不真实扣费。环境由签名／分发与 StoreKit 配置决定，不是仅靠 `#if DEBUG` 切换。
- 苹果沙盒使用 App Store Connect 商品配置与测试账户，可加速测试续费／到期；测试周期不能带入正式逻辑。
- 上线需要完成开发者账户、付费协议、收款／税务资料、商品价格／本地化、隐私政策／使用条款及 App／内购审核配置。人民币目标价与不开家庭共享已确认；商品 ID、可选价格档位、销售地区和实际后台配置尚未完成。
- 首版不引入第三方订阅后台；将来若需要跨安卓／iOS授权、服务端业务访问控制或 App 未运行时的主动订单处理，再单独评估服务端。
- 安卓后台的赠送／改永久／任意追加天数／单设备解绑／吊销／解除吊销不能全部用普通 StoreKit 客户端替代。用户已确认用苹果优惠码提供兑换解锁能力；订阅补偿延期有专门服务端接口及适用范围，不能当成任意改期限能力。详情见配套审查第 3、4 节。

### 6.1 商品配置与界面必须明确的内容

- 本轮年费是**每年付款一次的一年订阅**，不是“承诺一年、按月付款”方案。年度商品放入一个高级版订阅组，永久商品独立配置；不把永久商品当成该组的另一等级。
- 家庭共享已确定不开，年度订阅与非消耗永久商品都不启用。若将来用户另行要求变更，需重新评估共享权益与撤销及不可撤回的配置开关，不能开发时顺手开启。
- 自定义购买页明确展示套餐权益、真实币种价格、年度扣费周期、自动续订说明、取消方式、恢复购买、隐私政策及使用条款。已确认支持优惠码，但具体活动尚未配置，不展示虚构试用或折扣；公开面向所有人的免费试用并未因支持优惠码而自动获批。
- Android 年费是主动续买，iOS 已改为自动续期：安卓临近到期的橙色警告和“立即续费”不能原样套给正常自动续订用户。建议自动续订显示“下一续费日期”，关闭续订显示“有效至”，扣款问题显示实际需要处理的状态；具体中文及其他语言文案在实施时一并对照记录。
- 商品 ID、Bundle ID、订阅组和购买环境建立明确对应；苹果商品不存在、尚未可用或部分返回时，禁用对应购买操作，不造一个安卓兜底价让用户付款。变更地区后的价格展示重新加载，不改变已确认的权益。
- 工程当前最低 iOS 16。优先使用该版本可用的 StoreKit 2 接口；较新 StoreKit 视图／状态 API 必须做可用性判断，不能为了购买页默默提高部署版本。

### 6.2 沙盒隔离与审核准备

- TestFlight 可能使用 Release 构建但依然是沙盒；不能把“Release”等同于正式购买环境。正式发布的 Scheme 不携带本地 StoreKit 模拟配置，不把沙盒订单缓存当成正式购买。
- 本地模拟、苹果沙盒和正式环境分别验证状态恢复，不靠清空一个 `isPro` 模拟真实退款。安卓隐藏的“恢复免费版”调试入口不直接搬进正式 iOS；测试覆盖开关不能撤销苹果购买，也不能泄漏为正式解锁入口。
- 自动续期订阅应有持续价值，审核说明需如实描述持续维护、功能更新或相机兼容支持等实际提供内容；不能只凭“技术上能创建年度商品”就声称订阅审核必定通过。
- 购买与恢复入口在未连接相机时也应可访问。App Review 备注提供真实使用路径、内购商品说明及相机依赖；必要时准备演示视频或硬件说明。不得把仅 Debug 的模拟照片入口当成审核人员一定能使用的功能。
- 无自建后台不等于无售后：保留恢复购买、管理订阅和反馈路径；客服不能承诺凭本地截图关闭用户续订或发放苹果权益。日志只记录诊断必要的环境、商品、状态和错误，不记录账户凭据或完整交易签名原文。

依据：[家庭共享及不可撤销开关](https://developer.apple.com/documentation/storekit/supporting-family-sharing-in-your-app)、[订阅持续价值与管理](https://developer.apple.com/app-store/subscriptions/)、[审核所需硬件／演示信息](https://developer.apple.com/app-store/review/)。

依据：[内购商品类型](https://developer.apple.com/help/app-store-connect/reference/in-app-purchases-and-subscriptions/in-app-purchase-types)、[苹果沙盒测试](https://developer.apple.com/documentation/storekit/testing-in-app-purchases-with-sandbox)、[Xcode 本地测试](https://developer.apple.com/documentation/storekit/getting-started-with-in-app-purchases-using-storekit-views)。
